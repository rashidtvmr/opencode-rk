# WEB-013 - Search and deep-research chat mode

Status: IN PROGRESS / NOT ACCEPTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: real search/research tools and source/reference projection.
Test obligations: WEB-013-T01, WEB-013-T02, WEB-013-T03, WEB-013-T04, WEB-013-T05.

## User-observable outcome

When native research tools are installed, users can choose Search or Deep Research,
select sources, review a plan, see bounded progress, steer/cancel the run and receive
a cited final result.

## Observable contract and tests

- **WEB-013-T01 — research lifecycle:** selected real sources/tools create a reviewable
  plan, stream progress, accept steering and finish with references bound to claims.
- **WEB-013-T02 — no-adapter/provider failure:** Search/Research is explicitly
  unavailable or fails structurally; ordinary OpenAI text turns are never mislabeled
  as research.
- **WEB-013-T03 — accessibility:** mode/source/plan controls, progress and references
  have semantic state and keyboard operation without live-region progress spam.
- **WEB-013-T04 — bounds/cancel:** source count, retained progress, execution time and
  concurrent research work are bounded; cancel tears down child/tool work.
- **WEB-013-T05 — replay:** the plan, source set, activity summary and cited final
  result can be reloaded from durable records.

## Current implementation boundary

- The daemon capability manifest explicitly reports Search and Deep Research as
  unavailable. Local `grep` remains a local workspace tool and is never relabeled as
  web search.
- The composer surfaces disabled Search/Deep Research entries with the daemon reason;
  ordinary text turns carry no research mode or source fields.
- No native research executor, plan/progress persistence or answer-citation adapter
  exists yet, so the research happy-path/replay tests remain blocked and this story
  is NOT ACCEPTED.
