Status: NOT STARTED. Kind: product. Runtime optional: False.

Requirements: none (DISC-002 discovered `opencode.integrations` residual; deferred per `opencode.integration-auth` refresh finding).
Dependencies: none.
Test obligations: INT-005-T01, INT-005-T02, INT-005-T03, INT-005-T04, INT-005-T05.

## User-observable outcome

Native code can decide whether one stored credential needs refresh, run at
most one refresh per credential at a time (concurrent callers coalesce onto
the in-flight refresh), and record success (new expiry) or typed failure
without inventing provider network behavior. Refresh execution itself stays
behind a caller-supplied callback; this slice owns only the decision,
single-flight, and outcome recording.

## Observable contract

- `RefreshState { credential_id: CredId, expires_at_ms: u64, refreshed_at_ms: u64 }`;
  `CredId`: validated non-empty string, max 128 bytes.
- `needs_refresh(state, now_ms, window_ms) -> bool`: true iff
  `now_ms + window_ms >= expires_at_ms`. Default `REFRESH_WINDOW_MS = 300_000`
  (5 minutes, matching pinned `refreshWindowMinutes: 5`); caller may pass an
  explicit window. Pure function, no clock read.
- `RefreshGate::new(max_inflight: usize)` (default `MAX_INFLIGHT = 128`):
  `try_begin(cred) -> Result<RefreshGuard, RefreshError>`; second concurrent
  `try_begin` on the same `cred` while a guard is live => `Err(RefreshError::AlreadyRefreshing)`
  (caller coalesces); unknown/duplicate completion => typed error, never a panic.
- `RefreshGuard::complete(self, gate, new_expiry_ms) -> RefreshState` records
  success; `RefreshGuard::fail(self, gate, reason: RefreshFail) -> RefreshError`
  records typed failure (`ProviderRejected` | `NetworkUnavailable` | `ExpiredGrant`)
  with zero secret bytes. Guard completion is the only path that mutates state.
- Suggested module boundary: new `crates/providers/src/int_refresh.rs`
  (additive fragment only). Worker never edits shared `lib.rs`, `Cargo.toml`,
  schemas, or migrations; integrator wires exports.
- Caller owns `now_ms`, the actual provider refresh callback, secret storage,
  persistence, events, and background scheduling (none here).

## Failure states

- Not-due credential: `needs_refresh` false; `try_begin` still allowed (caller
  decides) but `complete` with `new_expiry_ms <= now_ms` => `Err(RefreshError::InvalidExpiry)`;
  state unchanged.
- Double-begin: `Err(RefreshError::AlreadyRefreshing)`; first guard unaffected,
  no second execution started.
- Complete/fail without live guard: `Err(RefreshError::NoInflightRefresh)`; state unchanged.
- Gate full (`inflight == max_inflight`): `Err(RefreshError::GateFull)`; nothing admitted.
- Secret safety: expiry values and typed reasons only; access/refresh token bodies
  never accepted, retained, or logged. No SQLite/OpenCode DB writes. No changes to
  the user's existing OpenCode database; tests use disposable fixture state only.

## Resource bounds

- Count cap: `max_inflight` (default 128) bounds concurrent guards; no unbounded
  attempt map, no 30-second scrubber thread, no background fiber.
- Byte cap: `CredId` max 128 B; gate stores ids + two u64s only; no retained
  payloads, no unbounded queue.
- Owner/cancel path: synchronous guard RAII-style completion; dropped guard
  without complete/fail releases the slot as `ExpiredGrant`-free abort
  (`try_begin` succeeds again); no detached task, no thread, no clock.
- Zero hidden cost when idle: empty gate allocates nothing beyond the map shell.

## Test obligations (frozen)

- INT-005-T01 (decision + success path): state expiring in 60s with 5-min window:
  `assert!(needs_refresh(s, now, 300_000))`; far-future expiry:
  `assert!(!needs_refresh(s, now, 300_000))`; `try_begin` => Ok, `complete(new_expiry)`
  => `assert_eq!(state.expires_at_ms, new_expiry)` and slot released (`try_begin` Ok again).
- INT-005-T02 (single-flight coalescing): live guard on cred A; second `try_begin(A)`
  => `assert_eq!(err, AlreadyRefreshing)`; `try_begin(B)` => Ok (independent);
  after `complete(A)`, `try_begin(A)` => Ok again.
- INT-005-T03 (caps hold): `max_inflight = 4`, begin 4 distinct creds; 5th =>
  `assert_eq!(err, GateFull)`; fill/release cycle of 10k creds completes with
  `inflight() == 0` and no growth (no OOM, no leaked slots).
- INT-005-T04 (failure states): `complete` with past expiry =>
  `assert_eq!(err, InvalidExpiry)` and state unchanged; `fail` without guard =>
  `assert_eq!(err, NoInflightRefresh)`; `fail` with guard records typed reason
  (`assert!(matches!(err_recorded, ProviderRejected | NetworkUnavailable | ExpiredGrant))`)
  and releases the slot; dropped guard without completion releases the slot
  (`try_begin` Ok again, assert reclaimed).
- INT-005-T05 (no side effects + safety): refresh decision/recording performs no I/O
  (assert no FS/DB writes outside disposable fixture dir); captured logs contain
  zero token bytes and zero credential ids beyond a fixed `cred-***` redaction;
  a denied double-begin asserts zero provider-callback executions (counter stays 0),
  not just an error string.
