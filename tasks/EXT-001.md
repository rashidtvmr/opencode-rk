## User-observable outcome

Scoped native plugin add/remove/wait lifecycle for one registry owner: callers
register native plugin declarations, remove them by id, block until a plugin is
ready (with caller-owned cancellation), and list current registrations in
deterministic order. No JavaScript host is started, no filesystem watcher is
started, no network is touched, no external plugin is activated. Reload/watch
semantics are explicitly out of scope (owned by EXT-004 as a deferred
boundary); built-in wiring through this same registry is owned by EXT-002.

## Observable contract

- `PluginId(u64)`: monotonically increasing per registry, starts at 1.
  `ContractVersion(u32)`; `SUPPORTED_CONTRACT_VERSION: u32 = 1`.
- `PluginDecl { name: String, contract_version: u32, capabilities: Vec<String> }`.
  Name: 1..=128 chars, `[A-Za-z0-9][A-Za-z0-9._-]*`. Capabilities: 0..=16
  entries, each 1..=64 chars, same charset; duplicates within one declaration
  rejected.
- `PluginState { Registered, Ready }`.
  `PluginInfo { id: PluginId, decl: PluginDecl, state: PluginState }`.
- `PluginRegistry::new() -> PluginRegistry` (empty, no I/O, no threads).
  - `add(&mut self, decl: PluginDecl) -> Result<PluginId, PluginError>`.
    Validates name/capabilities/version, rejects duplicates (by name) and
    overflow, inserts as `Registered`, returns id.
  - `mark_ready(&mut self, id: PluginId) -> Result<(), PluginError>`.
    Test/owner hook modelling scoped activation completing; unknown id =>
    `Unknown`. (Real external activation stays deferred per EXT-004; this is
    an in-memory state flip, not a host launch.)
  - `remove(&mut self, id: PluginId) -> bool`. Removes only that id; unknown
    id => `false`, registry otherwise unchanged.
  - `wait_ready(&self, id: PluginId, cancel: &AtomicBool) -> Result<(), PluginError>`.
    `Ok(())` iff state is `Ready`; `Registered` with no cancel spins on
    parking with bounded checks and returns `Cancelled` promptly once
    `cancel` is set (checks at least every 1 ms, returns within 50 ms);
    unknown id => `Unknown`; removed id observed by a waiter => `Unknown`.
    No callback execution, no host launch.
  - `list(&self) -> Vec<PluginInfo>` sorted by `PluginId` ascending
    (insertion order, deterministic).
- Native bounds are explicit public constants (upstream supplies none; the
  frozen RED suite owns the exact values):
  `MAX_PLUGINS: usize = 64`, `MAX_CAPABILITIES: usize = 16`,
  `MAX_NAME_LEN: usize = 128`, `MAX_CAP_LEN: usize = 64`.
- Deterministic: same add/mark_ready/remove sequence => identical
  `list()` output. No wall-clock in ordering or ids.
- Suggested module boundary: new pure in-memory module
  `crates/ext/src/lifecycle.rs` (new crate `opencode-rk-ext`); worker ships
  additive fragment only, never edits shared `lib.rs`, `Cargo.toml`,
  schemas, migrations. Independent test owner:
  `crates/ext/tests/plugin_lifecycle.rs`.
- Explicitly excluded: external JS/TS host, executable plugin callbacks,
  hook execution (REQ-020: SEC-010/SEC-011/EXT-008), skill discovery/listing
  and command registry internals (unresolved partitions in the gap file),
  UI presentation (REQ-005: UI-010/EXT-005/EXT-009/EXT-012/UI-012), file
  extraction (EXT-013), policy gating (TOOL-007), filesystem, network,
  persistence, environment lookup, credentials/secrets, HTTP routes,
  background work, new dependencies.

## Failure states

- Invalid name (empty, too long, bad charset): `Err(PluginError::InvalidName)`;
  registry unchanged.
- Duplicate name: `Err(PluginError::Duplicate)`; registry unchanged, no id consumed.
- Bad capabilities (too many, bad entry, intra-decl duplicate):
  `Err(PluginError::InvalidCapabilities)`; registry unchanged.
- Unsupported contract version (`!= SUPPORTED_CONTRACT_VERSION`):
  `Err(PluginError::UnsupportedContract)`; registry unchanged.
- Registry full (`len == MAX_PLUGINS`): `Err(PluginError::Overflow)`;
  registry unchanged; never exceeds cap.
- `mark_ready`/`wait_ready` unknown id: `Err(PluginError::Unknown)`; no state change.
- `wait_ready` with cancel set (before or during): `Err(PluginError::Cancelled)`
  promptly (within 50 ms); no state change, no thread leaked.
- `remove` unknown id: returns `false`; registry unchanged (harmless, mirrors
  EXT-003 close-unknown semantics).
- Secret safety: declarations hold names/capability labels only; no file
  bodies, no credentials; nothing secret is logged. No SQLite/OpenCode DB
  writes. No changes to the user's existing OpenCode database; tests use
  disposable in-memory registries only.

## Resource bounds

- Count caps: `MAX_PLUGINS` bounds the vec; `add` cap-checks before push; no
  unbounded queue of pending registrations.
- Byte caps: name/capability length caps bound retained bytes
  (max ~64 * (128 + 16*64) bytes, small and constant); no unbounded retained output.
- Owner/cancel path: caller owns the `PluginRegistry` lifetime and the
  `AtomicBool` cancel flag; `wait_ready` takes `&self` + `&AtomicBool` and
  parks (bounded 1 ms slices), never spawns a thread; no detached task, no
  background finalizer.
- Zero hidden cost: `new()` + `list()` on an empty registry allocates only
  the empty vec; no threads, no watchers, no host process.

- EXT-001-T01 (happy path): add 3 valid decls => ids 1,2,3;
  `mark_ready(2)` => `Ok`; `wait_ready(2, unset_flag)` => `Ok(())`;
  `list().len() == 3`, `list()` ids sorted `[1,2,3]`,
  `list()[1].state == Ready`, others `Registered`.
- EXT-001-T02 (remove scope): add 2, remove first => returns `true`;
  `list().len() == 1` with remaining id 2; `remove(unknown)` => `false` and
  `list()` unchanged; `wait_ready(removed_id)` => `Err(Unknown)`.
- EXT-001-T03 (validation, registry unchanged): duplicate name =>
  `Err(Duplicate)`; empty/bad name => `Err(InvalidName)`; 17 capabilities =>
  `Err(InvalidCapabilities)`; `contract_version: 999` =>
  `Err(UnsupportedContract)`; fill to `MAX_PLUGINS` then one more =>
  `Err(Overflow)` and `list().len() == MAX_PLUGINS`; each error leaves
  `list()` byte-identical to before the call.
- EXT-001-T04 (wait cancel): `mark_ready` unknown id => `Err(Unknown)`;
  `wait_ready` unknown id => `Err(Unknown)`; pre-set cancel flag on a
  `Registered` plugin => `Err(Cancelled)` within 50 ms; set cancel 5 ms
  into a blocked `wait_ready` => `Err(Cancelled)` and joining the waiter
  thread shows no leaked thread (test thread count delta 0).
- EXT-001-T05 (no host/side-effect safety): run full lifecycle while
  asserting no child process spawned (no new host process), no files
  created outside the disposable test dir, no test writes to any DB path;
  captured logs contain zero capability strings beyond the plugin name and
  zero credential-like bytes.
