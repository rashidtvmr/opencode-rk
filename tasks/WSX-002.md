## User-observable outcome

Callers driving one caller-owned remote sync loop observe a reconnecting event stream: connect succeeds and queued events sync with typed acks, transient failures back off with overflow-safe delays capped at 30s, an over-full queue sheds new items with a typed QueueFull error instead of growing memory without limit, and dispose closes the queue and socket so queued bytes return to zero with no leaked handle. No network beyond the fixture harness, no persistence, no background task owned by this module.

## Observable contract

- `SyncState { Disconnected, Connecting, Connected, Error { retry_in_secs: u64 } }`: initial Disconnected; `connect()` moves Disconnected/Error -> Connecting -> Connected on transport ok, or -> Error on transport failure.
- `RemoteSync::new(transport: &dyn SyncTransport) -> RemoteSync`: caller-supplied transport trait only (fixture harness in tests); this module performs no direct socket I/O.
- `connect(&mut self) -> Result<(), SyncError>`: success drains queued events in FIFO order, each acked by transport; failure records Error with computed backoff and retains the queue intact.
- `push(&mut self, event: SyncEvent) -> Result<(), SyncError>`: event bytes max 256 KiB; rejects past either cap with `Err(QueueFull)`; `ack(seq)` removes only the acked seq.
- `backoff_secs(failures: u32) -> u64`: `min(REMOTE_RECONNECT_BASE_SECS << min(failures, 31), REMOTE_RECONNECT_CAP_SECS)` computed in u64 with saturation, never overflow, sequence 2,4,8.. capped at 30.
- `dispose(&mut self)`: closes queue and socket handle; queued bytes return 0; post-dispose `push`/`connect` => `Err(Disposed)`.
- Bounds as explicit public constants: `REMOTE_RECONNECT_BASE_SECS: u64 = 2`, `REMOTE_RECONNECT_CAP_SECS: u64 = 30`, `MAX_SYNC_QUEUE_ITEMS: usize = 256`, `MAX_SYNC_QUEUE_BYTES: usize = 4_194_304` (4 MiB).
- Deterministic: same transport script plus same pushes => identical states, delays, and ack order; no wall-clock, no globals.
- Suggested module boundary: `crates/server/src/remote_sync.rs` owning SyncState, RemoteSync, SyncEvent, SyncError, SyncTransport, REMOTE_RECONNECT_BASE_SECS, REMOTE_RECONNECT_CAP_SECS, MAX_SYNC_QUEUE_ITEMS, MAX_SYNC_QUEUE_BYTES, connect, push, ack, backoff_secs, dispose; shared lib.rs wiring left to integrator.
- Explicitly excluded: workspace routing/header strip/bridge queue (WSX-001), event-log semantics (SYNC-001), SSE framing (WEB-005), auth/TLS, ShareNext sync.

## State and persistence transitions

- Connection lifecycle: Disconnected -> Connecting -> Connected on ok; Connecting -> Error on fail; Error -> Connecting on next `connect()`; any state -> Disposed via `dispose()` (terminal, one-way).
- Queue lifecycle: empty -> buffered (push Ok) -> empty (drain on connect plus ack); `QueueFull` and failed-connect rejections leave queued bytes identical to before (no partial push, no partial drain).
- Ack removes exactly the acked seq; unacked events survive reconnect and resync in original order.
- Persistence: none; queue and state are caller-owned memory. Cross-restart resume is explicitly out of scope.

## Failure states

- Transport failure on connect: `Err(SyncError::Transport)`; state becomes Error with `retry_in_secs == backoff_secs(failures)`; queue unchanged.
- Queue full by items (len == 256) or bytes (would exceed 4 MiB): `Err(SyncError::QueueFull)`; queue unchanged; never exceeds either cap.
- Oversize single event (> 256 KiB): `Err(SyncError::TooLarge)`; queue unchanged.
- Post-dispose use: `Err(SyncError::Disposed)`; no state change, no transport call.
- Overflow safety: `backoff_secs(u32::MAX)` == 30 with no panic, no wrap (asserted by test).
- Secret safety: errors carry variant names only, never event bytes. Tests use fixture events; no live credentials, no DB writes.

## Resource bounds

- Queue caps: at most 256 items and 4 MiB total; `push` checks both before insert; no unbounded queue, no unbounded retained output.
- Backoff: pure u64 arithmetic, no timers or sleeps owned by this module; caller schedules the retry.
- Owner/cancel path: caller owns the loop, transport, and socket handle; all methods synchronous, spawn no thread; `dispose`/drop releases buffered bytes and closes the handle immediately; no detached task, no background reconnect loop, no socket held after dispose.
- Zero hidden cost: `new()` allocates only the empty queue; idle cost is the caller-owned struct only.
