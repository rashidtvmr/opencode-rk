## User-observable outcome

A pure, offline repository-reference normalizer: given one repository reference
string (plus optional branch and cache root) it returns a normalized reference,
a typed validation failure, a branch-isolated cache path, and a stable cache
identity. UI/CLI can validate a repo URL and preview where its cache would live
without cloning, fetching, or touching the network or filesystem. This is the
smallest strict-TDD-friendly fragment carved from the repository-operations
family per `sources/operations-ownership-gap.json` candidate
`repository-reference-normalization`.

## Observable contract

- `RepoRef { host: String, path: String, branch: Option<String> }`;
  `NormalizedRef { canonical: String, host: String, path: String, branch: String }`.
- `RepoError::Malformed` (unsupported/empty form), `RepoError::UnsafeBranch`
  (empty, `.`, `..`, leading `-`/`/`, contains `..`, whitespace, `~`, `^`,
  `:`, `?`, `*`, `[`, control chars, or longer than 255 bytes),
  `RepoError::InputTooLong` (reference string over 2048 bytes).
- `normalize_ref(input: &str, branch: Option<&str>) -> Result<NormalizedRef, RepoError>`:
  accepts `owner/repo`, `host/owner/repo`, full `https://` URL forms;
  default host `github.com`; default branch `main`; trims ASCII whitespace;
  rejects malformed/unsafe deterministically; pure, no env read in this
  function (GitHub base-override env consult lives in an explicit
  `normalize_ref_with_base` wrapper and is covered by T05, never silent).
- `cache_path(root: &str, norm: &NormalizedRef) -> String`: `root/host/path@branch`
  with `/` separators; branch sanitized to `[A-Za-z0-9._-]` else `_`.
- `cache_identity(norm: &NormalizedRef) -> String`: stable
  `host/path@branch` string; same inputs => identical output.
- Deterministic: same inputs => same outputs; no wall-clock, no I/O.
- Suggested module boundary: NEW file `crates/foundation/src/ops_repo_ref.rs`
  (pure functions only). Worker ships additive fragment only, never edits
  shared `lib.rs`, `Cargo.toml`, schemas, migrations. Integrator wires `pub mod`.

## Failure states

- Empty/whitespace-only input or unsupported form: `Err(RepoError::Malformed)`; no partial value returned.
- Unsafe branch (rules above): `Err(RepoError::UnsafeBranch)`; no path/identity derived.
- Reference over 2048 bytes: `Err(RepoError::InputTooLong)` before any parse.
- Non-UTF8-safe display: lossy label for display only; matching/identity use
  raw bytes; normalization continues or rejects per rules, never panics.
- Secret safety: reference strings hashed/comparison only in tests via fixture
  literals; nothing logged beyond the rejected input's shape (length/reason),
  never credentials. No SQLite/OpenCode DB writes. No changes to the user's
  existing OpenCode database; tests use in-memory strings only.

## Resource bounds

- Byte caps: 2048-byte input, 255-byte branch; chunked nothing (single short
  string); no unbounded retained output.
- O(n) time in input length, O(1) extra memory beyond returned structs; no
  queue, no thread, no detached work; caller owns all lifetimes.

## Test obligations (frozen)

- OPS-008-T01 (happy path): `normalize_ref("owner/repo", None)` =>
  `host == "github.com"`, `branch == "main"`,
  `canonical == "github.com/owner/repo@main"`;
  `normalize_ref("https://example.com/a/b", Some("dev"))` branch `dev`;
  `cache_path("/c", &n) == "/c/github.com/owner/repo@main"`;
  `cache_identity(&n) == "github.com/owner/repo@main"`.
- OPS-008-T02 (determinism + branch isolation): two runs same inputs =>
  identical `NormalizedRef`/path/identity; `main` vs `dev` give different path
  and identity; results sorted/stable across repeated calls.
- OPS-008-T03 (bounds): 2049-byte input => `InputTooLong`; 256-byte branch =>
  `UnsafeBranch`; 10k-input batch completes without allocation blowup
  (each call O(1) extra).
- OPS-008-T04 (failure states): `""`, `"  "`, `"://bad"`, `"a/"` =>
  `Malformed`; branches `"../x"`, `"-evil"`, `"a b"`, `"~h"`, `"a*b"` =>
  `UnsafeBranch`; on error no path/identity is produced.
- OPS-008-T05 (env isolation + safety): plain `normalize_ref` never reads
  process env (test sets a decoy `GITHUB_*` var, verdict unchanged); wrapper
  `normalize_ref_with_base` applies explicit base only when passed; no test
  touches network, filesystem, or any DB; logs contain zero credential bytes.
