# EXT-007 - Native plugin integration metadata bridge

Status: IMPLEMENTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: none (DISC-002 discovered intersection of extensibility and integration-auth surfaces).
Dependencies: INT-004 candidate implementation on main (`d8fa485`).
Test obligations: EXT-007-T01, EXT-007-T02, EXT-007-T03, EXT-007-T04, EXT-007-T05.

## User-observable outcome

Native plugins can contribute bounded integration name plus key/OAuth method metadata through the existing scoped integration registry. Plugin scope closure removes that plugin's contribution and reveals any prior scoped metadata. This slice is inert metadata only: it neither executes JavaScript nor handles credentials, environment variables, OAuth callbacks, refresh, network requests, or persistence.

## Observable contract

- A caller-owned plugin scope can atomically contribute one bounded set of integration records and key/OAuth method metadata to `IntegrationRegistry`.
- Registration order is deterministic. Key methods occupy the single key slot; OAuth metadata is keyed by method id and same-id updates replace in place, matching the existing INT-004 method semantics and pinned Integration editor behavior.
- A later plugin scope overrides visible integration/method metadata; closing it reveals the previous scope, and closing a scope removes only that scope's contribution.
- The bridge prevalidates/bounds a whole declaration before committing it. Invalid identifiers/metadata or integration/method overflow returns typed `IntegrationError` and leaves the registry unchanged.
- Existing INT-004 public caps remain authoritative; the bridge adds no unbounded retained state.

## Ownership, lifetime, persistence, and safety

- Product boundary: additive API in `crates/providers/src/integration.rs`; no new module or dependency is required.
- Caller owns the plugin scope token and calls `close_scope`; no background lifecycle task is introduced.
- Persistence transitions: none. The bridge mutates only in-memory `IntegrationRegistry` metadata.
- Explicitly excluded: external JS/TS plugin activation, hidden JS runtime, executable plugin callbacks, OAuth authorize/callback/refresh execution, raw key/token material, credential resolution/storage, env-variable projection, network, HTTP routes, filesystem access, persistence, background work, and new dependencies.
- The generic EXT plugin lifecycle, skills, commands, hooks, reload/watch and UI/TUI compatibility remain separate unresolved ownership slices and are not claimed by EXT-007.
