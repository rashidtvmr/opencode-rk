## User-observable outcome

Callers spawning SDK backends through one caller-owned spawner observe bounded ownership: Server/Process/Tui backends start under an 8-slot cap with a 30s startup deadline, every owned child carries a kill-on-drop handle that reaps without leaving zombies, a ninth concurrent spawn is rejected with a typed SpawnFull error that changes nothing, and startup timeouts kill and reap the child with no leaked process. No real spawn beyond the fixture harness, no secrets in errors or logs.

## Observable contract

- `BackendKind { Server, Process, Tui }`: closed enum; every spawn request names exactly one variant.
- `SpawnRequest { kind: BackendKind, argv: Vec<String>, dir: String }`: argv 1..=32 entries, each 1..=1024 chars, no NUL bytes; dir 1..=1024 chars.
- `Spawner::new(port: &dyn SpawnPort) -> Spawner`: caller-supplied port only (fixture harness in tests); this module performs no direct `Command::spawn`.
- `spawn(&mut self, req: SpawnRequest) -> Result<ChildHandle, SpawnError>`: more than MAX_SPAWNS live children => `Err(SpawnFull)`; startup exceeding STARTUP_TIMEOUT_SECS => `Err(StartupTimeout)` with the child killed and reaped.
- `ChildHandle { id: u64, kind: BackendKind }`: owned handle; `kill()` terminates and reaps; drop kills and reaps (kill-on-drop); `wait()` reaps and reports `ExitStatus`; double-wait => `Err(AlreadyReaped)`.
- Bounds as explicit public constants: `MAX_SPAWNS: usize = 8`, `STARTUP_TIMEOUT_SECS: u64 = 30`.
- Deterministic: same fixture script plus same requests => identical ids, statuses, and error variants; no wall-clock, no globals.
- Suggested module boundary: `crates/server/src/sdk_spawns.rs` owning BackendKind, SpawnRequest, ChildHandle, ExitStatus, SpawnError, SpawnPort, Spawner, MAX_SPAWNS, STARTUP_TIMEOUT_SECS, spawn, kill, wait; shared lib.rs wiring left to integrator.
- Explicitly excluded: typed HTTP calls (SDK-001), ACP framing (ACP-001), plugin code execution, shell-string concatenation (argv only, never a shell line), ambient process spawn.

## State and persistence transitions

- Spawner lifecycle: live-count 0..=MAX_SPAWNS; spawn-ok increments, reap/kill decrements; `SpawnFull` leaves the count and table byte-identical to before.
- Child lifecycle: starting -> live (startup ack within deadline) or killed-on-timeout; live -> reaped via `wait`/`kill`/drop; reaped ids never reused within one spawner.
- Startup timeout: partial child killed and reaped by the module via the port; no half-owned entry remains in the table.
- Persistence: none; the table is caller-owned memory. Cross-restart child adoption is explicitly out of scope.

## Failure states

- Ninth concurrent spawn (live == 8): `Err(SpawnError::SpawnFull)`; table unchanged; no port spawn call.
- Startup past deadline: `Err(SpawnError::StartupTimeout)`; child killed and reaped; live count unchanged from before the attempt.
- Bad request (empty argv, > 32 args, NUL byte, empty/oversize dir): `Err(SpawnError::InvalidInput)`; no port call, table unchanged.
- Backend start refusal by port: `Err(SpawnError::StartFailed)`; nothing recorded.
- Wait on reaped/unknown id: `Err(SpawnError::AlreadyReaped)` / `Err(SpawnError::UnknownChild)`; table unchanged.
- Unchanged-state guarantees: every error above leaves the live table byte-identical to before except StartupTimeout, which provably returns to the pre-attempt count (asserted by count test).
- Secret safety: errors carry variant names, kinds, and ids only, never argv secrets or environment bytes. Tests use fixture argv only; no inherited env.

## Resource bounds

- Spawn cap: at most MAX_SPAWNS live children; `spawn` checks before any port call; no unbounded process table.
- Startup deadline: STARTUP_TIMEOUT_SECS enforced via the caller port deadline; no sleep owned here.
- Owner/cancel path: caller owns the spawner, port, and all child lifetimes; handles are kill-on-drop; `wait` reaps exactly once; drop of the spawner kills and reaps all live children; no detached task, no orphaned child, no zombie (fixture asserts `reaped == spawned`).
- Zero hidden cost: `new()` allocates only the empty table; idle cost is the caller-owned struct only.
