# WEB-015 - Projects, workspace context and memory disclosure

Status: IN PROGRESS / NOT ACCEPTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: workspace/session context and reference/memory contracts.
Test obligations: WEB-015-T01, WEB-015-T02, WEB-015-T03, WEB-015-T04, WEB-015-T05.

Implemented boundary (2026-09-15): the singleton daemon can read the canonical
`data/catalog.db` format-2 workspace registry and expose bounded workspace metadata to
the browser. The browser has a keyboard-native read-only workspace selector and makes
the registry-only boundary explicit. If the catalog is absent, the API returns an
explicit unavailable state instead of inventing projects.

This does **not** yet satisfy project-scoped sessions/files/instructions, memory or
per-turn context-source disclosure. The current schema/service has no authoritative
workspace-to-session/file membership or persisted memory/context configuration, so the
browser must not filter or attribute chats to a selected workspace yet.

## User-observable outcome

Chats, files and reusable instructions can be grouped by project/workspace. Users can
inspect which memory/context sources contributed to a turn and manage loaded context
without leaking hidden provider reasoning.

## Observable contract and tests

- **WEB-015-T01 — project context:** opening a project loads only its real scoped
  sessions/files/instructions and exposes an inspectable context-source breakdown.
- **WEB-015-T02 — missing/forbidden context:** unavailable files, invalid paths and
  cross-workspace access fail explicitly and do not leak data into another project.
- **WEB-015-T03 — accessibility:** project switcher, context inspector and memory
  source controls expose names/state and support full keyboard operation.
- **WEB-015-T04 — bounds/lifetime:** open projects/files/watchers/context sources obey
  native caps/eviction and unload cleanly; context previews are bounded.
- **WEB-015-T05 — persistence:** project membership, loaded context configuration and
  disclosed sources remain consistent across client reconnect/reload.
