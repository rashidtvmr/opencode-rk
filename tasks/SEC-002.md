# SEC-002 - Deterministic destructive-command and SQL controls

Status: CANDIDATE. Kind: product slice. Requirement: REQ-025
(requirements/user-requirements.json:27). Owed obligations:
SEC-002-T01..T05 (mapped to tests below).

## Claim

`classify_destructive_argv` (crates/security/src/lib.rs) now deterministically
classifies the extended destructive-command surface (git push --force,
git reset --hard, git clean -fd family, chmod world-writable, chown root,
kill -9/-KILL/-s KILL, docker rm/rmi/volume rm, kubectl delete/drain/cordon,
pip install --break-system-packages) and `authorize_sql` extends coverage to
GRANT/REVOKE, CREATE/CREATE UNIQUE/DROP/ALTER INDEX and REINDEX, and UPDATE
without WHERE. All Deny decisions are mandatory: a `PermissionSet::star()`
wildcard cannot lift them (docs/SECURITY.md section 1, AGENTS.md).

## What changed (crates/security/src/lib.rs only)

Process classification (`classify_destructive_argv` plus new helpers
`classify_git`, `is_world_writable_mode`):

| Pattern | Decision | Notes |
|---|---|---|
| git push --force / -f / --force-with-lease | Deny | `-f` matched inside short-flag bundles; flags scanned only after the subcommand |
| git reset --hard | Deny | --soft/--mixed allowed |
| git clean -fd / -fx / -dx / --force bundles | Deny | needs the force flag; `git clean -d` alone allowed |
| chmod 777 / 776 / o+w / a+w / go+w / a+rwx | Deny | any 3-digit octal whose world digit grants write (2,3,6,7); 644, u+x allowed |
| chown root / root:root | Deny | -R variants included; `chown dev:dev` allowed |
| kill -9 / -KILL / -SIGKILL / -s KILL | Deny | SIGTERM (`kill -TERM`, plain `kill pid`) allowed |
| docker rm / docker rmi / docker volume rm | Deny | `docker ps`, `docker volume ls` allowed |
| kubectl delete / drain / cordon | Deny | `kubectl get` allowed |
| pip / pip3 install --break-system-packages | Deny | ordinary `pip install pkg` allowed |

SQL classification (`authorize_sql`): word tokens are now split on any
non-alphabetic character, so quoted identifiers and backticks no longer defeat
matching.

| Statement | Decision |
|---|---|
| GRANT ... / REVOKE ... | Deny (privilege changes never executed by an agent) |
| DROP INDEX ... | Deny (DROP extended to INDEX/VIEW/SCHEMA/USER/DATABASE/TABLE/ROLE/TRIGGER/SEQUENCE objects) |
| CREATE INDEX / CREATE UNIQUE INDEX / ALTER INDEX / REINDEX / DROP CLUSTER | RequireHuman |
| UPDATE without WHERE | RequireHuman (mirrors existing DELETE rule) |
| UPDATE ... WHERE / DELETE ... WHERE / SELECT | Allow |

## Decisions

- Forced-push classification is argv-only; opaque `bash -c "git push --force"`
  strings stay on the existing RequireHuman shell path (defense in depth,
  direct argv preferred).
- `git` global options before the subcommand (`git -C path push --force`) are
  not parsed; conservative miss is a future hardening item, `ponytail:`
  boundary noted in code review. Flag scan is restricted to args after
  position 0 so `git push origin -f feature` and `git clean -fd` match while
  `git reset --hard`-style long flags use exact equality (no substring bugs).
- SQL UPDATE-without-WHERE is RequireHuman (data change, potentially safe with
  human review), while GRANT/REVOKE and DROP are Deny (privilege/object loss).
- Chmod detection keys on world-write bit, not the literal "777" string.

## Remaining unknowns / gaps

- The classifier is a deterministic pattern gate, not a sandbox (SECURITY.md
  section 3): real isolation remains owned by the Landlock line (SEC OS
  backend tasks). Do not advertise these rules as containment.
- Subcommand aliases and config-driven wrappers (e.g. `git co`, shell
  functions, `docker-compose rm`) are out of scope for this slice.
- SEC-012 and SEC-016 (also REQ-025) may extend the same table; this card
  claims only T01..T05 behaviors listed above.
