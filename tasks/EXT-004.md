## User-observable outcome

An explicit deferred-activation boundary for reload/watch: while external
JS/TS plugin activation remains design work upstream, the native registry
exposes a bounded, auditable record of reload requests and watcher interest
that performs zero filesystem watching, launches zero hosts, and activates
zero external code. A reload request is validated, recorded as
`Deferred(DeferredReason)`, and reported back; a `list_deferred()` projection
shows exactly what is still pending and why. Watch registration records
interest only - it never starts an OS watcher. This turns the upstream "still
design work" caveat into an observable contract instead of a silent no-op.

## Observable contract

- `DeferredReason { ExternalActivationDeferred, WatchDeferred, ReloadDeferred }`.
  `DeferredEvent { seq: u64, plugin: Option<PluginId>, reason: DeferredReason }`
  (`plugin: None` = registry-wide reload request).
- `EXT4_MAX_DEFERRED: usize = 128`, `EXT4_MAX_WATCHERS: usize = 32`
  (explicit public constants; upstream supplies none; frozen RED owns values).
- `DeferredLog::new() -> DeferredLog` (empty, no I/O, no threads).
  - `request_reload(&mut self, plugin: Option<PluginId>) -> Result<u64, BoundaryError>`.
    Records `ReloadDeferred` (per-plugin) or registry-wide (`None`) event,
    returns its `seq`. Never touches the EXT-001 registry state: no add,
    remove, or readiness change.
  - `note_external(&mut self, plugin: Option<PluginId>) -> Result<u64, BoundaryError>`.
    Records `ExternalActivationDeferred` for an external-JS/TS activation
    attempt that is refused-by-design here; returns `seq`. Performs zero
    host launch, zero `dlopen`, zero subprocess.
  - `add_watcher(&mut self, label: WatchLabel) -> Result<u32, BoundaryError>`.
    Records watcher interest only; returns watcher id. Starts zero OS
    watchers, zero threads, zero file handles. Duplicate label =>
    `Err(Duplicate)`; over cap => `Err(Overflow)`.
  - `remove_watcher(&mut self, id: u32) -> bool`. Unknown id => `false`,
    log otherwise unchanged.
  - `list_deferred(&self) -> Vec<DeferredEvent>` sorted by `seq` ascending.
  - `drain(&mut self, n: usize) -> Vec<DeferredEvent>`: removes and returns
    the oldest `n` events (or fewer); lets the owner bound memory explicitly.
- `WatchLabel`: 1..=64 chars, `[A-Za-z0-9][A-Za-z0-9._-]*`.
- Deterministic: same call sequence => identical `seq` series from 1 and
  identical `list_deferred()` output. No wall-clock anywhere.
- Suggested module boundary: `crates/ext/src/deferred.rs` (same new crate
  `opencode-rk-ext` as EXT-001/EXT-002); worker ships additive fragment
  only, never edits shared `lib.rs`, `Cargo.toml`, schemas, migrations.
  Independent test owner: `crates/ext/tests/plugin_deferred.rs`.
- Runtime optional True: when the boundary feature is off, none of these
  functions is called; the log is never constructed; zero cost (mirrors
  TOOL-016 opt-out proof).
- Explicitly excluded: any filesystem watcher (notify/inotify/kqueue),
  any JS/TS host or subprocess, executable plugin callbacks, hook execution
  (REQ-020), skill/command discovery, UI presentation (REQ-005), file
  extraction (EXT-013), policy gating (TOOL-007), network, persistence,
  environment lookup, credentials/secrets, HTTP routes, background work,
  new dependencies. A reload request must never mutate plugin readiness or
  re-execute anything.

## Failure states

- Over deferred cap (`len == EXT4_MAX_DEFERRED`): `request_reload` /
  `note_external` return `Err(Overflow)`; log unchanged; never exceeds cap.
- Over watcher cap (`watchers == EXT4_MAX_WATCHERS`): `add_watcher` returns
  `Err(Overflow)`; no watcher recorded, no OS handle opened.
- Bad watch label (empty, too long, bad charset): `Err(InvalidLabel)`; unchanged.
- Duplicate watch label: `Err(Duplicate)`; unchanged, no id consumed.
- `remove_watcher` unknown id: returns `false`; unchanged (harmless).
- `drain(0)`: returns empty vec, log unchanged. `drain(n > len)`: returns
  all events, log empty; never panics.
- Secret safety: events hold seq/id/reason only; labels hold short names
  only; no paths, no file bodies, no credentials; nothing secret logged.
  No SQLite/OpenCode DB writes. No changes to the user's existing OpenCode
  database; tests use disposable in-memory logs only.

## Resource bounds

- Count caps: `EXT4_MAX_DEFERRED` bounds the event vec (push cap-checked;
  overflow errors instead of growing); `EXT4_MAX_WATCHERS` bounds watcher
  records; `drain` gives the owner an explicit shrink path; no unbounded queue.
- Byte caps: labels max 64 bytes each (max ~2 KiB total watcher labels);
  events are fixed-size structs (max 128 * ~24 bytes); no unbounded
  retained output.
- Owner/cancel path: caller owns the `DeferredLog` lifetime; all methods
  are synchronous, non-blocking, constant-time; no cancel flag needed
  (nothing blocks); no detached task, no background thread, no OS handle.
- Disabled path (feature off): log never constructed; zero allocation,
  zero threads, zero file handles, zero I/O.
