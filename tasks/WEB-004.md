## User-observable outcome

Control-plane routes are unreachable from non-local interfaces unless an
explicit, bounded remote-exposure grant exists. Local loopback callers keep
working with no extra setup; any remote attempt without a grant is refused
before authentication parsing and before any domain service runs. The pure
wire-compat contract (INT-008) stays usable locally regardless of the remote
flag. `web/` browser code is owned elsewhere; this card specifies the
server-side exposure contract only.

## Observable contract

- New additive Rust boundary: `crates/server/src/control_plane_exposure.rs`
  (suggested; worker ships additive fragment only, never edits shared `lib.rs`,
  `Cargo.toml`, schemas, migrations; integrator wires).
- `Exposure { allow_remote: bool, bind: BindAddr }` with `Default` =
  `{ allow_remote: false, bind: Loopback }`; remote is opt-in, never default.
- `check_exposure(peer: IpAddr, cfg: &Exposure) -> Result<(), ExposureDeny>`:
  loopback peer + any cfg => `Ok`; non-loopback peer + `allow_remote: false` =>
  `Err(ExposureDeny::RemoteDenied)`; non-loopback + `allow_remote: true` => `Ok`
  (auth itself stays with the auth owner; this gate only decides reachability).
- Gate position: `check_exposure` runs before auth parsing and before the domain
  service call (asserted by ordered spy: `assert_eq!(order, [exposure, auth, service])`
  on allow; `assert_eq!(order, [exposure])` on deny).
- `GET /health` stays reachable for local supervision regardless of flag;
  control-plane mutation routes (`POST /control/*`) are the gated set
  (`GATED_PREFIXES = ["/control/"]`).
- Deterministic: same (peer, cfg) => same verdict; no DNS, no I/O, no clock.

## Failure states

- Remote without grant: `Err(RemoteDenied)` mapped to `403/remote_denied` with
  redacted template; auth parser never runs (`assert!(!auth_entered())`),
  service call count stays 0.
- Spoofed `X-Forwarded-For` / `Forwarded` headers: ignored for the verdict
  (decision uses only the transport peer address);
  test with spoofed loopback header over non-loopback peer => still denied.
- Unix-socket peer (no IP): treated as local (`Ok`); test asserts socket peer passes
  with default cfg.
- Misconfigured `allow_remote: true` + loopback bind: local still works; test asserts
  bind mismatch is surfaced by daemon config validation owned elsewhere (this slice
  only asserts the gate verdict, not bind enforcement).
- Secret safety: deny path logs peer family only (v4/v6/socket), never full
  credentials/tokens; no user DB writes; no network dial.

## Resource bounds

- Gate is O(1) pure function over (peer, cfg); no allocation beyond the deny value.
- No queue, thread, task, clock, watcher, retry, or background work.
- Owner/cancel path: none (synchronous verdict); caller owns connection lifetime.
- Deny responses bounded: fixed template body <= 512 bytes.
