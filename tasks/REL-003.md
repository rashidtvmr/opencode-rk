## User-observable outcome

A deterministic safety-and-resource-correctness release validator proves the
candidate preserved capability-based safety and bounded-resource behavior at
release time instead of blindly translating upstream files. Given a read-only
candidate revision (security/resource gate outputs, capability and quota
fixtures, release revision), it emits pass/fail with an attributable failing
fixture on any unsafe resource behavior or unverified release state. It
duplicates neither SEC-017 control ownership nor the REL-002 TDD-proof
guarantee.

## Observable contract

- Proposed validator entrypoint: `python3 tools/check_release_safety.py --revision <rev> --gates <dir> --caps <caps.json> --quotas <quotas.json> --out <report.json>` (new additive file; this card defines the contract, implementer ships the file).
- Inputs (read-only): security gate outputs (mandatory-control denials incl. `*`-cannot-bypass cases), resource gate outputs (byte + count quotas, retention/eviction behavior), capability fixture (explicit capabilities, scoped cancellation tokens), quota fixture (explicit bounds, no silent history deletion), candidate revision id.
- Output `report.json`: `{"passed": bool, "checks": {"mandatory_intact": pass|fail, "denied_no_side_effects": pass|fail, "bytes_bounded": pass|fail, "quotas_enforced": pass|fail}, "failing_fixture": "<path or null>", "evidence_rev": "<rev>", "partition": "safety-resource-correctness-release-validator"}`; stdout mirrors JSON; exit `0` pass, `2` assurance failure, `1` tool error.
- Pass condition (all four): mandatory_intact (every mandatory control denial held under `*`/broad-grant fixture), denied_no_side_effects (blocked write created no file, blocked process never started, per-receipt fs/proc diff empty), bytes_bounded (retained bytes <= quota on oversize/overflow fixture), quotas_enforced (queue counts + bytes + retention policy all enforced, no silent precious-history deletion).
- Deterministic: same inputs => byte-identical report; no network, no wall-clock in verdict; ordering by sorted check ids only.
- Suggested module boundary: `tools/check_release_safety.py` + fixture dir `fixtures/release-safety/`; worker ships additive files only, never edits shared `lib.rs`, `Cargo.toml`, schemas, migrations, controller `state/`, verifier config.

## Failure states

- Mandatory bypass (broad `*` grant or prompt/hook lifts a mandatory control): exit `2`, `checks.mandatory_intact: fail`, fixture is the bypass receipt naming the control.
- Denied with side effects (blocked write left a file, blocked process started, secret logged): exit `2`, `checks.denied_no_side_effects: fail` with fs/proc/log diff attached as `failing_fixture`.
- Unbounded retention (oversize input grows retained bytes past quota, unbounded queue, silent history deletion to meet byte target): exit `2`, `checks.bytes_bounded` or `checks.quotas_enforced: fail` with the overflowing measurement.
- Blind translation without safety evidence (upstream-behavior fixture with no gate receipts): exit `2` with reason `unverified-release-state`, never pass on file-parity alone.
- Tool error (unreadable gates, malformed caps/quotas, unknown flag): exit `1`, no report written; never exit `0` on error.

## Resource bounds

- Read-only: opens gates/caps/quotas read-only; writes only `<out>` report; never mutates the user OpenCode database, never runs host-destructive commands; tests use disposable fixture dirs only.
- Bounded: inputs capped (default 256 files, 8 MiB total); report capped (default 64 KiB); single process, no threads, no network, no retained output beyond the report.
- Owner/cancel path: caller owns process lifetime; `--timeout` (default 60s) aborts with exit `1`; no detached task, no background thread.
