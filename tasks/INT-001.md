## User-observable outcome

Pure secret-free integration registry projection for one caller-owned
registry at a time: callers register bounded integration descriptors
(name plus key/OAuth method metadata) into nested scopes, override them in
a later scope, close the scope to reveal the prior value, and list current
registrations in deterministic order. This slice stores no credential
material, reads no environment, performs no network or OAuth
callback/refresh work, and publishes no events. Secret persistence,
provider refresh, plugin bridging, server routes, and external OAuth
behavior stay with their own owners.

## Observable contract

- `MethodKind { Key, OAuth }`; `MethodMeta { kind: MethodKind, method_id:
  String, label: String }`: `method_id` 1..=64 chars, `label` 0..=128
  chars, charset `[A-Za-z0-9][A-Za-z0-9._-]*` for id, printable ASCII for
  label. No secrets in any field.
- `IntegrationDesc { name: String, methods: Vec<MethodMeta> }`: `name`
  1..=64 chars, same id charset; 0..=8 methods per integration.
- `ScopeToken(u64)`: monotonically increasing per registry, starts at 1.
- `IntegrationRegistry::new() -> IntegrationRegistry` (empty, no I/O, no
  threads).
  - `open_scope(&mut self) -> ScopeToken`. Caller-owned nesting; scopes
    close in LIFO order only.
  - `register(&mut self, scope: ScopeToken, desc: IntegrationDesc) ->
    Result<(), RegistryError>`: validates name/methods, rejects duplicates
    (same name within the same scope) and overflow; last-scope-wins for
    reads.
  - `close_scope(&mut self, scope: ScopeToken) -> u64`: removes only that
    scope's entries (must be the innermost open scope), returns count
    removed; unknown/non-innermost scope => `Err(RegistryError::Scope)`,
    registry unchanged.
  - `get(&self, name: &str) -> Option<&IntegrationDesc>`: innermost visible
    registration, or `None`.
  - `list(&self) -> Vec<(&str, &IntegrationDesc)>` sorted by name ascending
    (deterministic; innermost value shown per name).
- Bounds as explicit public constants (upstream supplies none; frozen RED
  owns values): `MAX_INTEGRATIONS: usize = 64`,
  `MAX_METHODS_PER_INTEGRATION: usize = 8`, `MAX_SCOPES: usize = 16`,
  `MAX_NAME_LEN = 64`, `MAX_METHOD_ID_LEN = 64`, `MAX_LABEL_LEN = 128`.
- Deterministic: same open/register/close sequence => identical `list()`.
  No wall-clock anywhere. Attempt ids/time are INT-004's domain, not here.
- Suggested module boundary: new pure in-memory module
  `crates/providers/src/registry.rs` (crate `opencode-rk-providers`);
  worker ships additive fragment only, never edits shared `lib.rs`,
  `Cargo.toml`, schemas, migrations. Independent test owner:
  `crates/providers/tests/integration_registry.rs`.
- Explicitly excluded: OAuth attempt lifecycle (INT-004), key/OAuth
  connection APIs and auth flows (INT-002), credential/secret storage,
  environment lookup, provider authorize/refresh callbacks, OAuth attempt
  auto-callbacks, network, HTTP routes, persistence, events, background
  scrubber, PTY/project/location/client-server behavior, new dependencies.

## Failure states

- Invalid name (empty, too long, bad charset):
  `Err(RegistryError::InvalidName)`; registry unchanged.
- Invalid method (bad id/label, too many methods):
  `Err(RegistryError::InvalidMethod)`; registry unchanged.
- Duplicate name within the same scope: `Err(RegistryError::Duplicate)`;
  registry unchanged, prior scopes untouched.
- Registry full (`visible names == MAX_INTEGRATIONS` or scope entries cap):
  `Err(RegistryError::Overflow)`; registry unchanged; never exceeds cap.
- Scope overflow (`open scopes == MAX_SCOPES`): `Err(RegistryError::Scope)`;
  no scope opened.
- `close_scope` unknown id or non-innermost scope:
  `Err(RegistryError::Scope)`; registry unchanged (strict LIFO; INT-004's
  harmless-close semantics are not borrowed here).
- Secret safety: descriptors hold names/method ids/labels only; no key
  material, tokens, or codes accepted by any constructor. No
  SQLite/OpenCode DB writes. Tests use disposable in-memory registries
  only.

## Resource bounds

- Count caps: `MAX_INTEGRATIONS` bounds visible names; `MAX_SCOPES` bounds
  open scopes; `register` cap-checks before insert; no unbounded queue of
  pending registrations.
- Byte caps: name/method/label length caps bound retained bytes (max
  ~64 * (64 + 8*(64+128)) bytes, small and constant); `list()` returns
  bounded borrows; no unbounded retained output.
- Owner/cancel path: caller owns the registry and scope tokens; all
  methods synchronous on `&mut self`/`&self`, spawn no thread; no
  cancellation token needed (sub-microsecond ops); no detached task, no
  background scrubber, no clock thread.
- Zero hidden cost: `new()` + `list()` allocates only the empty vecs; no
  threads, no watchers, no network handles.

## Test obligations (frozen)

- INT-001-T01 (happy path): open scope, register 3 integrations (key-only,
  oauth-only, both) => `Ok`; `get("b")` returns the oauth entry;
  `list().len() == 3` sorted by name; `list()` names
  `["a","b","c"]`.
- INT-001-T02 (override + reveal): open scope s1, register `"x"` label
  `"v1"`; open scope s2, register `"x"` label `"v2"` => `get("x").label ==
  "v2"`; `close_scope(s2)` => 1 and `get("x").label == "v1"`;
  `close_scope(s1)` => 1 and `get("x")` is `None`.
- INT-001-T03 (validation, registry unchanged): duplicate name in same
  scope => `Err(Duplicate)`; empty/bad name => `Err(InvalidName)`; 9
  methods => `Err(InvalidMethod)`; fill to `MAX_INTEGRATIONS` then one more
  => `Err(Overflow)` and visible count stays `MAX_INTEGRATIONS`; each error
  leaves `list()` byte-identical to before the call.
- INT-001-T04 (scope discipline): `close_scope(unknown)` =>
  `Err(Scope)`; open s1, open s2, `close_scope(s1)` (non-innermost) =>
  `Err(Scope)` and both scopes intact; fill to `MAX_SCOPES` open scopes =>
  next `open_scope` is `Err(Scope)`; close all in LIFO order => empty.
- INT-001-T05 (no secret/network side-effect safety): run full matrix
  while asserting no child process spawned, no files created outside the
  disposable test dir, no DB writes, no network handle opened; captured
  logs contain zero method-label strings beyond the integration name and
  zero credential-like bytes; type-level assertion: no public constructor
  accepts a `secret`/`token`/`code` parameter.
