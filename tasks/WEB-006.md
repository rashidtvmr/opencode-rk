# WEB-006 - Shared singleton daemon and embedded web host

Status: IMPLEMENTED / NOT ACCEPTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: BASE-004 singleton primitive; existing native server/session/catalog runtime.
Test obligations: WEB-006-T01, WEB-006-T02, WEB-006-T03, WEB-006-T04, WEB-006-T05.

## User-observable outcome

The browser client uses the same per-user/data-directory OpenCode RK backend authority
as every other application client. The user does not start a separate web-only
`serve` process. Production web assets and `/api/*` come from the singleton daemon;
Vite is development-only.

## Research and source evidence

- `PLAN.md` ADR-001/ADR-002: one Tokio runtime per daemon; CLI/TUI/web/desktop attach
  to one daemon per OS user + data directory.
- `crates/server/src/daemon.rs`: PID/Unix-socket singleton primitive exists but has no
  production caller and its accepted client bytes are currently discarded.
- `crates/cli/src/main.rs::serve`: currently bypasses the singleton and creates an
  independent HTTP runtime.
- `docs/features/chatgpt-web-parity.md`: explicit 2026-09-15 user-directed parity
  synthesis and one-daemon invariant.

## Observable contract and tests

- **WEB-006-T01 — same-instance reuse:** starting/ensuring the backend twice for the
  same data directory returns one healthy instance/HTTP origin, and session state
  created by one client is immediately visible to the other.
- **WEB-006-T02 — stale/unavailable recovery:** stale PID/socket/endpoint metadata is
  recovered deterministically; a healthy existing daemon is never replaced or
  shadowed by a second listener.
- **WEB-006-T03 — client accessibility/launch contract:** the production web entry
  point is discoverable from the daemon without requiring Vite or a second manual
  server command; failure is explicit and keyboard-independent.
- **WEB-006-T04 — singleton race and lifecycle bounds:** concurrent first starters
  yield exactly one owner; readiness wait is bounded; shutdown drops HTTP/control
  listeners and no detached producer/runtime survives.
- **WEB-006-T05 — isolation and compatibility:** different data directories can run
  independently; the existing HTTP API remains compatible and the legacy `serve`
  command cannot create a second authority for the same data directory.

## Non-goals

- No new raw IPC feature protocol is invented merely for the TUI. Future native TUI
  may initially consume the same local HTTP API while the Unix socket remains the
  singleton/control/readiness channel.
- This task does not claim remote multi-user security mode.

## Implementation evidence

- `crates/server/src/daemon.rs` now uses an OS-backed advisory file lock for
  cross-process singleton ownership and publishes bounded per-data-directory backend
  endpoint metadata.
- `crates/cli/src/main.rs` makes `serve` participate in the singleton and adds
  `opencode-rk web`, which reuses a healthy daemon or becomes its owner without a
  separate Vite process.
- `crates/server/src/web_assets.rs` serves the production web bundle from the same
  native origin as `/api/*`; `web/vite.config.ts` emits that release bundle into the
  server's embedded asset directory.
- Focused WEB-006 tests cover same-instance reuse, isolation, stale recovery,
  exact-one concurrent ownership, embedded SPA/API serving and the `web --no-open`
  entry point.
- The original compiling behavioral RED in
  `crates/cli/tests/web_singleton_runtime.rs` is frozen at SHA-256
  `5bdadc6831700ada0b8e826593c414c9ab92fc360a88c7f3c28e0cb055239e02`.
