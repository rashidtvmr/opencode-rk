## User-observable outcome

Native code can project a caller-supplied typed integration handler outcome
into its normalized HTTP-facing shape (secret-free projection, `NoContent`
mutation ack, or typed `InvalidRequest` / auth / code-required error) without
touching credentials, environment, storage, network, provider callbacks, or
events. Provider-specific authorization/refresh execution, credential
persistence, env resolution, and transport stay with their existing owners.
This slice proves the normalization rule: auth failures are intentionally
normalized and code-mode completion without a code stays pending as
code-required rather than failing as auth.

## Observable contract

- `Method { Key, OAuth }`; `NonSecretMeta { id: String, label: String,
  method: Method }`: `id`/`label` 1..=64 chars charset
  `[A-Za-z0-9][A-Za-z0-9._-]*`; no secret material in any field.
- `HandlerOp { List, Get, KeyAck, OAuthStart, OAuthComplete { code: Option<String> },
  AttemptPoll }`; caller supplies only `NonSecretMeta` values and an optional
  code presence flag (never raw key/token bytes).
- `HandlerResponse { Projection(NonSecretMeta), List(Vec<NonSecretMeta>),
  NoContent, Err(HandlerError) }`;
  `HandlerError { InvalidRequest, AuthFailed, CodeRequired, NotFound }`.
- `project(op, meta: Option<&NonSecretMeta>, items: &[NonSecretMeta])
  -> HandlerResponse` (pure, synchronous, no I/O):
  - `List` => `List(items)` sorted by `id` ascending (deterministic).
  - `Get` with `meta` present => `Projection(meta)`; absent => `Err(NotFound)`.
  - `KeyAck`/`OAuthStart` with valid meta => `NoContent`; invalid
    id/label => `Err(InvalidRequest)`.
  - `OAuthComplete { code: None }` => `Err(CodeRequired)`; attempt stays
    pending (no mutation signal); never `AuthFailed`.
  - `OAuthComplete { code: Some(_) }` with caller-asserted auth failure flag
    => `Err(AuthFailed)` normalized (same shape regardless of provider
    reason; carries zero provider detail).
  - `AttemptPoll` missing => `Err(NotFound)`.
- Bounds as explicit public constants (upstream supplies none; frozen RED
  owns values): `MAX_ITEMS: usize = 128`, `MAX_ID_LEN = 64`,
  `MAX_LABEL_LEN = 64`.
- Deterministic: same `(op, meta, items)` => byte-identical response; no
  wall-clock, no randomness in ordering.
- Suggested module boundary: new pure in-memory module
  `crates/integration/src/handler_projection.rs` (or new crate
  `opencode-rk-integration` if workspace resists); worker ships additive
  fragment only, never edits shared `lib.rs`, `Cargo.toml`, schemas,
  migrations. Independent test owner:
  `crates/integration/tests/handler_projection.rs` (or equivalent).
- Explicitly excluded: raw key/OAuth secret material, env variable reads,
  provider authorize/refresh/callback execution, credential persistence,
  attempt-map lifecycle/timers (INT-004), event publication (INT-008
  separation), HTTP transport/SSE, filesystem, background work, new
  dependencies.

## Failure states

- Invalid id/label (empty, too long, bad charset):
  `Err(HandlerError::InvalidRequest)`; no projection returned.
- Missing meta for `Get`/`AttemptPoll`: `Err(NotFound)`; no default
  projection invented.
- Code-mode completion without code: `Err(CodeRequired)`; caller must keep
  attempt pending and unmutated (asserted by test sentinel).
- Auth failure (caller-asserted): `Err(AuthFailed)` normalized; carries no
  provider reason, no secret bytes, no env value.
- Over `MAX_ITEMS`: projection truncates `List` to `MAX_ITEMS` sorted
  prefix and reports `truncated: true` on the list wrapper; never exceeds
  cap, never OOM.
- Secret safety: inputs/outputs hold id/label/method only; captured logs
  contain zero credential-like bytes. No SQLite/OpenCode DB writes. Tests
  use disposable in-memory vectors only.

## Resource bounds

- Count cap: `MAX_ITEMS` bounds admitted items; `project` cap-checks before
  collect; no unbounded queue of pending outcomes.
- Byte caps: id/label length caps bound retained bytes (max ~128 * 128
  bytes, small and constant); `List` returns a bounded vec copy; no
  unbounded retained output.
- Owner/cancel path: caller owns `items` lifetime and `meta` refs; `project`
  synchronous on `&[...]`, spawns no thread; no cancellation token needed
  (sub-microsecond ops); no detached task, no background finalizer, no
  host process.
- Zero hidden cost: construction allocates nothing beyond the caller vec;
  error path allocates nothing beyond the fixed error value.

  flags project to byte-identical `AuthFailed` (no leaked detail);
  200-item input => `len == MAX_ITEMS` and `truncated == true`, sorted
  prefix preserved.

  process, no files outside disposable test dir, no DB writes, no env read
