## User-observable outcome

Callers routing workspace traffic through one caller-owned proxy observe correct forwarding: local session/status calls are served without leaving the loopback path, remote workspace calls are forwarded with hop-by-hop and routing headers stripped, HTTP bodies and WebSocket frames cross the `__workspace_ws` bridge intact in order, and an over-full proxy queue sheds new items with a typed QueueFull error instead of growing memory without limit.

## Observable contract

- `ProxyTarget { Local, Remote { endpoint: String } }`: endpoint max 2048 chars, http/https/ws/wss scheme only.
- `route(target_hint: &RouteHint) -> ProxyTarget`: `RouteHint { path, has_directory }`: paths under `/api/sessions` or `/api/status` with a local directory => Local; `/__workspace_ws` or explicit remote hint => Remote; decision is a pure function of caller-supplied input.
- `strip_headers(headers: &[(String, String)]) -> Vec<(String, String)>`: removes hop-by-hop (`connection`, `keep-alive`, `transfer-encoding`, `upgrade`, `proxy-authenticate`, `proxy-authorization`, `te`, `trailer`) plus routing headers (`x-workspace-directory`, `x-workspace-remote`); case-insensitive; order of survivors preserved.
- `ProxyQueue::new() -> ProxyQueue`: `push(item: ProxyItem) -> Result<(), ProxyError>`: item bytes max 256 KiB; queue rejects past either cap with `Err(QueueFull)`; `drain() -> Vec<ProxyItem>` returns FIFO in order and empties the queue.
- `ProxyItem { kind: ProxyItemKind, bytes: Vec<u8> }`; `ProxyItemKind { HttpBody, WsFrame }`: bridge preserves kind and byte order end to end.
- Bounds as explicit public constants: `MAX_PROXY_QUEUE_BYTES: usize = 4_194_304` (4 MiB), `MAX_PROXY_QUEUE_ITEMS: usize = 256`.
- Deterministic: same hints/headers/items => identical targets/stripped lists/drain order; no wall-clock, no I/O, no globals.
- Suggested module boundary: `crates/server/src/workspace_proxy.rs` owning ProxyTarget, RouteHint, ProxyQueue, ProxyItem, ProxyItemKind, ProxyError, MAX_PROXY_QUEUE_BYTES, MAX_PROXY_QUEUE_ITEMS, route, strip_headers; shared lib.rs wiring left to integrator.
- Explicitly excluded: actual socket I/O, TLS, reconnect/backoff (WSX-002), SSE transport (WEB-005), auth/CORS policy, ShareNext sync.

## State and persistence transitions

- Routing: stateless pure function; no state change by construction.
- Header strip: stateless pure function; input slice unchanged; returns a new vec.
- Queue lifecycle: empty -> buffered (push Ok) -> empty (drain); `QueueFull` rejections leave the queue byte-identical to before (no partial push).
- Persistence: none; the queue is caller-owned memory. Cross-restart resume is explicitly out of scope.

## Failure states

- Queue full by items (len == 256) or bytes (would exceed 4 MiB): `Err(ProxyError::QueueFull)`; queue unchanged; never exceeds either cap.
- Oversize single item (> 256 KiB): `Err(ProxyError::TooLarge)`; queue unchanged.
- Bad endpoint (empty/oversize/unsupported scheme): `Err(ProxyError::BadEndpoint)`; no routing recorded.
- Forbidden headers only: strip returns survivors (possibly empty); never errors on header input (header names capped at 256 chars, values at 8 KiB; over-cap => `Err(ProxyError::BadHeader)` with input unchanged).
- Secret safety: stripped values (e.g. proxy-authorization) are dropped, never logged; errors carry variant names only. Tests use fixture headers; no live credentials, no DB writes.

## Resource bounds

- Queue caps: at most 256 items and 4 MiB total; `push` checks both before insert; no unbounded queue, no unbounded retained output.
- Per-item cap: 256 KiB bounds any single push; per-header caps bound strip inputs.
- Owner/cancel path: caller owns the queue and all connection handles; all functions synchronous, spawn no thread; `drain`/drop releases buffered bytes immediately; no detached task, no background forwarder, no socket held by this module.
- Zero hidden cost: `new()` allocates only the empty vec; idle cost is the caller-owned struct only.
