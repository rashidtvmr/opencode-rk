## User-observable outcome

Native plugins can contribute a bounded, caller-scoped set of named reference source metadata to the session runtime without starting a JavaScript host or materializing any source. Local and Git source descriptors remain inert metadata. Closing a plugin scope removes only that scope's contributions and reveals any prior scoped value for the same alias.

## Observable contract

- A caller-owned plugin scope can atomically register a bounded declaration of named `ReferenceSource` metadata.
- Supported source metadata is limited to:
  - local: path, optional description, optional hidden flag;
  - Git: repository, optional branch, optional description, optional hidden flag.
- Registration/list ordering is deterministic by alias. A later plugin scope overrides the visible value for the same alias; closing that scope reveals the previous scoped value.
- The owning scope can add, remove, and list metadata without mutating other scopes. Closing an unknown/already-closed scope is harmless and reports no removal.
- Invalid aliases, duplicate aliases within one declaration, oversized metadata, scope overflow, and per-scope reference overflow return typed errors and leave the registry unchanged.
- Native safety/resource bounds are explicit public constants because upstream does not supply numeric caps. The frozen RED suite owns the exact values used by this implementation.

## Ownership, lifetime, persistence, and safety

- Product boundary: new pure in-memory module `crates/sessions/src/reference.rs`, exported from `crates/sessions/src/lib.rs`.
- Independent test owner: `crates/sessions/tests/plugin_reference_bridge.rs`.
- Caller owns the numeric plugin scope id and explicit `close_scope` lifecycle. No background finalizer/task is introduced.
- Persistence transitions: none. The bridge keeps only bounded in-memory source metadata.
- Explicitly excluded: external JS/TS plugin activation, hidden JavaScript runtime, executable plugin callbacks, reference guidance rendering, model/session prompt injection, template/`@` expansion, local path resolution, filesystem reads, Git clone/fetch/checkout/cache-path derivation, repository refresh, network, persistence, environment lookup, credentials/secrets, HTTP routes, background work, and new dependencies.
- DISC-003 remains separately IN PROGRESS / NOT ACCEPTED; local EXT-003 implementation cannot claim verifier/controller acceptance.
