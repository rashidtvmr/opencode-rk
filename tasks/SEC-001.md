## User-observable outcome

Agent-originated file, process, SQL and tool operations are authorized by a
deterministic broker. Ordinary permissions (glob rules, including `*`) grant
ordinary access only. Mandatory controls (secret deny, system deny, destructive
deny, human gates) hold even under a wildcard `*` allow. Every decision is
recorded in a bounded audit trail.

## Observable contract

- `PermissionRule { pattern, effect }`: glob match over a per-intent scope
  (file: normalized path; process: program basename; sql: statement; tool:
  name). `*` matches every intent; `*` crosses no `/`; `**` crosses `/`;
  `?` matches one non-`/` char. First matching rule wins.
- `PermissionSet { rules }`: `PermissionSet::star()` is one Allow `*` rule.
  `evaluate` returns the first matching rule or None (default allow for
  ordinary intents, subject to mandatory controls).
- Enforcement order in `PermissionBroker::authorize`: baseline mandatory
  decision first (`Deny` or `RequireHuman` from policy), returned unchanged
  regardless of rules; rules apply only when the baseline is `Allow`
  (Allow stays allowed, Deny rule narrows, Ask rule escalates to human).
  Targeted Allow rules cannot lift a mandatory Deny or human gate.
- `Decision::is_mandatory()`: true for Deny and RequireHuman.
- Audit: every `authorize` call appends `AuditEntry { seq, at, intent,
  decision }`; `seq` is monotonic; capacity `MAX_AUDIT_ENTRIES` (1024) with
  oldest-first eviction; shared across `with_policy` / `with_permissions`
  forks (same `Arc<Mutex<..>>`); `generation` bumps on each fork.
- No new dependencies. No `unsafe`. No wall-clock dependence in decisions
  (timestamps are audit metadata only).

## Failure states

- Secret read (`.env`, `.env.*`, `.ssh`, `.aws`, gcloud config,
  `credentials`): Deny, even under star.
- System write/delete (`/etc`, `/usr`, `/bin`, `/sbin`, `/boot`, `/system`,
  `C:/Windows`, `C:/Program Files`): Deny, even under star.
- Destructive argv (`rm -rf *`, system deletes, mkfs, raw-device dd,
  `find -delete`) and destructive SQL (`DROP`, `TRUNCATE`, `GRANT/REVOKE`):
  Deny, even under star.
- Human gates (project-root-external writes, file delete, shell `-c`,
  `DELETE`/`UPDATE` without `WHERE`, `ALTER TABLE`, index/cluster changes):
  RequireHuman with fresh ApprovalId, even under star.

## Acceptance criteria

- SEC-001-T01: star allow does not bypass secret/system denies.
- SEC-001-T02: star allow does not bypass destructive denies.
- SEC-001-T03: star allow does not bypass human gates; targeted Allow rules
  cannot lift mandatory outcomes.
- SEC-001-T04: glob semantics (`*` vs `**` vs `?`), first-match-wins order,
  Deny/Ask narrowing of ordinary allows.
- SEC-001-T05: audit trail records every decision with monotonic seq and
  bounded retention; generation bumps on policy/permission forks.
- `cargo test -p opencode-rk-security` green; `cargo check --workspace` clean
  (modulo unrelated lanes).
