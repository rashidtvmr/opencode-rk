# WEB-005 - Server SSE/event stream transport limits for web clients

Status: NOT STARTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: none (DISC-002 discovered surfaces `opencode.server-control-plane` + `opencode.app-client`; DISC-003 review partial, not release evidence).
Dependencies: none newly introduced by this slice.
Test obligations: WEB-005-T01, WEB-005-T02, WEB-005-T03, WEB-005-T04, WEB-005-T05.

## User-observable outcome

Web clients subscribed to `GET /events` receive a bounded, well-formed SSE
stream: each event arrives as a complete `data:` frame, slow consumers apply
backpressure instead of growing memory without limit, and disconnects reclaim
all stream state promptly. Event payload semantics stay with INT-008; this card
owns only the transport envelope and its bounds. `web/` browser code is owned
elsewhere; this card specifies the server-side stream contract only.

## Observable contract

- New additive Rust boundary: `crates/server/src/event_stream.rs` (suggested;
  worker ships additive fragment only, never edits shared `lib.rs`, `Cargo.toml`,
  schemas, migrations; integrator wires).
- `StreamConfig { max_frame_bytes: usize, max_buffered_frames: usize, keepalive_ms: u64 }`:
  `Default` = `{ max_frame_bytes: 1_048_576, max_buffered_frames: 64, keepalive_ms: 15_000 }`.
- `encode_frame(payload: &[u8]) -> Result<String, FrameError>`:
  single SSE `data:` frame (`"data: <payload>\n\n"`); payload over
  `max_frame_bytes` => `Err(FrameError::TooLarge)` and the frame is dropped
  (subscriber kept alive; drop counted).
- `Content-Type: text/event-stream`, `Cache-Control: no-cache` headers on
  `GET /events`; body is a sequence of complete frames only (never a partial
  `data:` line; asserted by frame-join test).
- Backpressure: per-subscriber buffer holds at most `max_buffered_frames`;
  exceeding it disconnects that subscriber with `SlowConsumer` (no global queue
  growth, no cross-subscriber blocking).
- Deterministic encode: same payload bytes => same frame string; no timestamps
  inside frames (keepalive `:ping` comments carry no clock data in tests).

## Failure states

- Oversize event: `Err(TooLarge)`; frame dropped, `dropped_frames` counter +1,
  subscriber stays connected; next well-formed event still delivered.
- Slow consumer: buffer full => subscriber disconnected with `SlowConsumer`;
  other subscribers unaffected (`assert_eq!(other.received(), all)`).
- Client disconnect: all per-subscriber state (buffer, counter, task handle)
  reclaimed promptly; `assert_eq!(live_subscribers(), n - 1)` and no FD/task leak
  (harness asserts task count and buffer bytes return to baseline).
- Malformed payload bytes (invalid UTF-8): frame rejected with
  `FrameError::InvalidUtf8`, counted, connection kept; never emits a partial frame.
- Secret safety: frames carry only INT-008 payload bytes; no secrets added by
  transport; no user DB writes; tests use fixture payloads only.

## Resource bounds

- Per-subscriber byte cap: `max_buffered_frames * max_frame_bytes` is the hard
  ceiling (default 64 MiB worst case, normally KiB-scale); buffer bytes exposed
  via `buffered_bytes()` for tests.
- No unbounded queue, no retained history replay beyond the live buffer, no
  background thread per subscriber beyond the connection task owned by the HTTP
  runtime (cancelled on disconnect via scoped cancellation).
- Owner/cancel path: disconnect/cancel drops the subscriber struct; pending
  frames dropped, never flushed after close (`assert!(!flushed_after_close())`).
- Keepalive `:ping` at `keepalive_ms` keeps intermediaries alive; keepalive
  carries no payload and allocates one fixed small string.

## Test obligations (frozen)

- WEB-005-T01 (framing happy path): `encode_frame(b"{\"a\":1}")` =>
  `assert_eq!(frame, "data: {\"a\":1}\n\n")`; 3-frame join over harness =>
  each `data:` line complete, `assert_eq!(frames.len(), 3)`, headers include
  `text/event-stream` and `no-cache`.
- WEB-005-T02 (oversize drop): payload `max_frame_bytes + 1` =>
  `assert_eq!(err, TooLarge)`, `assert_eq!(dropped_frames(), 1)`,
  subscriber still connected and next small frame delivered intact.
- WEB-005-T03 (slow consumer): `max_buffered_frames = 2` harness, publish 5
  without reading => publisher disconnects that subscriber with `SlowConsumer`
  (`assert!(disconnected_as_slow())`), second live subscriber receives all 5.
- WEB-005-T04 (disconnect reclaim): subscribe 3, drop 1 mid-stream =>
  `assert_eq!(live_subscribers(), 2)`, `assert_eq!(buffered_bytes(), baseline)`,
  harness task count returns to pre-subscribe value (no leak).
- WEB-005-T05 (no side effect + safety): invalid-UTF8 payload =>
  `assert_eq!(err, InvalidUtf8)` with no partial frame emitted
  (`assert!(emitted_bytes().is_empty())`); run touches nothing outside the
  disposable fixture dir; logs contain zero payload-secret bytes.
