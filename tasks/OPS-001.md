## User-observable outcome

A bounded resource ledger plus a disabled-feature zero-cost proof for the
native daemon. Operators get typed admission caps taken from
`config/resource-targets.json` (queue counts AND byte counts, reservations
recorded before work is admitted) and an attestation that every optional
subsystem left off starts zero tasks, zero threads, zero watchers, zero
stores and performs zero I/O. Whole-tree measurement covers the daemon
process tree, never the daemon alone. No user history is silently deleted to
meet a byte target.

## Observable contract

- `AdmissionCaps { max_queued_agents: u32, max_input_bytes_per_session: u64,
  max_preview_bytes_per_tool: u64, max_subscriber_bytes: u64 }`:
  `Default` loads the four values above from `config/resource-targets.json`;
  any zero field is rejected at construction (`InvalidCap(name)`).
- `BudgetLedger::new(caps)`: pure admission ledger (no I/O, no clock).
  `admit(kind: WorkKind, bytes: u64) -> Result<Reservation, OverBudget>` where
  `WorkKind = AgentSlot | SessionInput | ToolPreview | SubscriberBuffer`.
  Each kind enforces BOTH a count cap and a byte cap (PLAN.md section 9: a
  bounded queue count is insufficient when messages are huge).
- `Reservation` is RAII: charges bytes+slot on admit, releases both on drop;
  `cancel()` releases early and is idempotent. Caller owns ledger lifetime;
  no background thread, no detached task.
- `DisabledCostAttestation { tasks: u32, threads: u32, stores: u32,
  watchers: u32, bytes: u64 }`:
  `attest_disabled(subsystems: &[SubsystemProbe]) -> DisabledCostAttestation`
  where each `SubsystemProbe` reports what an optional subsystem (plugin host,
  JS compatibility host, file watcher, LSP service, optional web) would start
  when its `Features` flag is off. All-off input yields all-zero output.
- `attest_single_enabled(probes, name)`: enabling exactly one subsystem starts
  only that subsystem; every other probe still reports zero (isolation).
- Deterministic: same caps + same admit/release sequence => identical
  ledger state; no wall-clock in decisions.
- Suggested module boundary: `crates/ops/src/resource_ledger.rs` (new crate
  `opencode-rk-ops`); fallback `crates/foundation/src/resource_ledger.rs` if
  the workspace resists a new crate. Worker ships additive fragment only,
  never edits shared `lib.rs`, `Cargo.toml`, schemas, migrations.
- Explicit non-ownership: BASE-004/005/006/007/008 stay closed (this card
  consumes flags, never stores them); `State.create` transform registration,
  `LocationServiceMap` 60-minute TTL eviction, and global import-time
  mkdir/environment behavior are NOT owned here (gap-file blockers above).

## Failure states

- Zero cap field: `Err(InvalidCap(name))` at construction; ledger unusable
  until fixed, never silently unbounded.
- Admit past count cap: `Err(OverBudget::SlotsExhausted { kind })`; admit past
  byte cap: `Err(OverBudget::BytesExhausted { kind, requested, available })`;
  failed admit charges nothing (assert zero side effect, not just error string).
- Over-budget history/tool output: spill per explicit retention policy with
  `Spilled { bytes, policy }` record; silent deletion is forbidden and
  asserted in T05.
- Probe reporting nonzero cost while its flag is off: attestation returns
  `Err(CostLeak { subsystem })`, never a zeroed lie.
- No SQLite/OpenCode DB writes. No changes to the user's existing OpenCode
  database; tests use disposable in-memory fixtures only.

## Resource bounds

- Byte caps: per-kind byte totals from `AdmissionCaps`; per-item preview bound
  64 KiB; no unbounded retained output, no unbounded queue.
- Count caps: agent slots 256 (count+bytes double-bound); no unbounded pending
  vector (admit checked before any push).
- Owner/cancel path: `Reservation::cancel` + drop-release; ledger is
  synchronous with no spawned task; caller owns lifetime; no detached task,
  no background thread.
- Disabled path: zero tasks/threads/I/O/allocation beyond the attestation
  struct; no watcher/store/service construction. Zero hidden cost when off
  (REQ-032 proof, not just flag storage).

## Test obligations (frozen)

- OPS-001-T01 (all-off zero cost): all probes disabled =>
  `assert_eq!(attest_disabled(probes), Ok(zero))` with
  `tasks == 0 && threads == 0 && stores == 0 && watchers == 0 && bytes == 0`;
  assert no fixture-FS handle opened (probe I/O counters stay zero).
- OPS-001-T02 (single-enable isolation): enable exactly one probe =>
  `attest_single_enabled` ok for that name AND every other probe still
  reports zero; enabling a second probe does not change the first probe's
  report (no shared hidden pool).
- OPS-001-T03 (admit/release accounting): admit N sessions under both caps =>
  ok; release half (drop) => `available` rises by exactly the released bytes
  and slots; re-admit succeeds; `cancel()` twice releases once (idempotent,
  saturates at zero, never underflows).
- OPS-001-T04 (count+byte double bound): 300 tiny agent admits =>
  `Err(SlotsExhausted)` while byte total stays under cap; one 2 MiB session
  input => `Err(BytesExhausted { requested, available })` while slot count
  stays under cap; failed admits leave ledger state bit-identical
  (`assert_eq!(before, after)`).
- OPS-001-T05 (no silent deletion + safety): force spill on an over-budget
  tool preview => `Ok(Spilled)` with explicit policy record and original
  bytes recoverable from the spill path; no test writes outside the
  disposable fixture dir (assert DB/fixture-outside untouched); captured logs
  contain zero spilled-body bytes; `InvalidCap` for each zeroed cap field.
