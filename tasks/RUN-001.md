## User-observable outcome

Callers driving one session observe single-flight execution: at most one normal run plus one concurrent shell run per session; a second normal prompt while one is running is rejected with a typed BusyError; cancelling a run reclaims its slot and releases all owned handles; an idle session holds no runner slot and no task handle. No threads escape the caller; no unbounded step loop exists.

## Observable contract

- `RunKind { Normal, Shell }`: shell lane runs concurrently with at most one normal run; two normals never coexist.
- `RunnerState { Idle, Running { kind }, Busy }` per session id (`String` 1..=128 chars).
- `RunnerSet::new() -> RunnerSet` (empty, no I/O, no threads).
  - `start(&mut self, session: &str, kind: RunKind) -> Result<RunGuard, BusyError>`: free slot => `Ok` guard owning the slot; occupied normal slot + Normal request => `Err(BusyError { session })`; occupied shell slot + Shell request => `Err(BusyError)`; set unchanged on rejection.
  - `RunGuard`: owned RAII handle; `cancel(self)` releases the slot immediately and records Cancelled; `complete(self)` releases the slot and records Completed; `Drop` releases the slot as Cancelled if neither was called (kill-on-drop).
  - `status(&self, session: &str) -> RunnerState`: Idle when no live guard; Running when a guard is alive.
  - `cancel_all(&mut self, session: &str) -> usize`: releases every live slot for that session; returns count released; unknown session => 0, set unchanged.
- `BusyError { session: String }`: typed rejection only; carries the session id, never internal handles.
- Bounds as explicit public constants: `MAX_STEPS: u32 = 64` (per-run step budget, enforced by the caller via `steps_remaining()` on the guard); session id max 128 chars.
- Deterministic: same start/cancel/complete sequence => identical states and identical release counts; no wall-clock, no I/O, no globals.
- Suggested module boundary: `crates/sessions/src/runner.rs` owning RunKind, RunnerState, RunnerSet, RunGuard, BusyError, MAX_STEPS, start/status/cancel_all; shared lib.rs wiring left to integrator.
- Explicitly excluded: prompt-loop semantics, subtask/tool execution, model resolution, retry/backoff, persistence, network, HTTP routes, background threads.

## State and persistence transitions

- Slot lifecycle per (session, kind): free -> held (start Ok) -> free (complete/cancel/drop); held slots are visible via `status() == Running`.
- Run outcome recorded on release: Completed (complete), Cancelled (cancel or drop); the set retains only a bounded outcome counter, never task handles.
- Idle invariant: when no guard is alive for a session, `status()` is Idle and the set holds zero handles for that session (asserted by handle-count test).
- Persistence: none; the set is caller-owned memory. Cross-restart run recovery is explicitly out of scope.

## Failure states

- Duplicate normal start while normal running: `Err(BusyError)`; set unchanged; first guard unaffected (still live, still counted once).
- Duplicate shell start while shell running: `Err(BusyError)`; set unchanged.
- Invalid session id (empty/oversize): `Err(BusyError)` is NOT used; `Err(RunnerError::InvalidInput)`; set unchanged. (BusyError is reserved for genuine contention.)
- `cancel_all` unknown session: returns 0; set unchanged (harmless).
- Guard dropped without complete/cancel: slot released as Cancelled; no leak (asserted by live-count test).
- Step budget exhausted (`steps_remaining() == 0`): caller must stop; guard offers `complete()` only; no automatic continuation, never unbounded.
- Secret safety: errors carry session ids only; no prompt content, no tokens. No DB writes; tests use fixture session ids.

## Resource bounds

- Slot cap: at most 2 live guards per session (one Normal, one Shell); `start` cap-checks before insert; no unbounded runner map growth beyond caller-driven sessions (caller may cap sessions; module documents the per-session bound).
- Step cap: MAX_STEPS bounds caller loops; upstream Infinity explicitly not reproduced.
- Owner/cancel path: caller owns the RunnerSet and every RunGuard; guards are synchronous RAII values, spawn no thread; `cancel_all`/drop releases slots immediately; no detached task, no background callback, no child process, no network handle.
- Zero hidden cost: `new()` + `status()` allocate only the empty map; idle cost is the caller-owned set only.

## Test obligations (frozen)
