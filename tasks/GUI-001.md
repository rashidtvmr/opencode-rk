## User-observable outcome

A user installs a native app — macOS first, Linux second, Windows in Phase 3 — that attaches to the already-running global `ocm` daemon on their PC: session list, streaming transcript that survives reconnects with zero lost or duplicated events, permission prompts that fail closed, and a composer that never drops keystrokes. No Electron, no Tauri, no webview wrapper. The daemon remains the single source of truth; each GUI keeps only window/layout, selection, scroll anchor, unsent draft, and paint caches keyed by (sessionID, blockID, revision).

## Source evidence

- Daemon substrate already built (measured 2026-09-26): crates/server/src/event_stream.rs (12.5K: SSE encode_frame, keepalive_frame, sse_headers, byte_cap, per-subscriber buffers, dropped_frames, buffered_bytes, disconnected_as_slow); crates/server/src/event_cursor.rs (10.2K: Cursor, ReplayBuffer with head_seq/retained_from/replay, Durability, CursorError); crates/server/src/acp_bridge.rs (8.8K: ACP v1 codec); crates/server/src/desktop_bridge.rs (1.3K: channel topics, thin/early).
- The precise gap (measured): zero hits for `Last-Event-ID` / `last_event_id` across crates/ — Cursor/ReplayBuffer exist and are tested but the SSE endpoint never accepts a resume cursor; reconnecting clients must full-rebootstrap today.
- OpenCode V2 HttpApi precedent: GET /api/event SSE with the honest contract "volatile by contract: a slow consumer overflows and fails the stream" — our addition is the replay endpoint that makes that failure recoverable.
- ACP v1 precedent for handshake + permission shape: initialize capabilities (omitted = unsupported, `_meta` extension), session/request_permission with allow_once/allow_always/reject_once/reject_always.
- macOS research: hybrid SwiftUI shell + AppKit core (NSTableView diffable transcript, TextKit 1 NSTextView composer); sandbox forbids UDS (EPERM-prone) so TCP 127.0.0.1 + bearer token; SwiftPM cannot ship a signed .app (checked-in .xcodeproj + xcodebuild).
- Linux research: GTK4 floor 4.14 (Ubuntu 24.04 sets the ceiling); verified 26.04 Resolute ships GTK 4.22.2 + libadwaita 1.9.0 + glibc 2.43; libadwaita is optional progressive enhancement, never a hard dep; Flatpak (org.gnome.Platform//50) is primary distribution; GtkListView (never ListBox); glibc forward-only rule forces oldest-host builds.

## Observable contract (program-level; each leaf carries its own)

- Every client leaf demonstrates, end-to-end through the real transport: connect -> stream -> survive a forced reconnect with zero dup/loss -> render a permission prompt that fails closed.
- Slow consumer: backpressure, then fail with `ocm.overflow` + resync instruction. Never silently skip; never an unbounded buffer.
- Permission: TTL expiry = DENY always, no config override; no client attached = DENY; first-responder-wins for multi-client; `desktop_attached` => phone/remote approvals locked (`409 approval_locked_to_desktop`).
- Capability handshake degrades payloads: `images:false` receives zero base64 bytes; `ansi:false` receives stripped text + flag.
- Three languages means no shared client crate; cross-client consistency comes from the frozen conformance corpus (W1-e), not shared code.
- Explicitly excluded from this program: Windows GUI and mobile apps (Phase 3, separate cards); embedding the Rust daemon inside any .app; any change to tools/, tests/bootstrap/, sources/*.json, or protectedPaths files.

## Program gate GUI-001-T00 (frozen, owned by W1-a, re-run by every client leaf)

Drive a 500-event session, kill the TCP connection at event 137, reconnect with Last-Event-ID, assert byte-identical concatenated transcript versus the uninterrupted run. If this does not exist and pass, no client work is legitimate — regardless of UI quality. Bounded replay buffer backing it: 2,000 events or 4 MiB (whichever first), persisted to the session DB so it survives daemon restart.

## Leaf order (leaves are authored lazily at lease time, not pre-authored)

Wave W1 — daemon client contract, 5 parallel Rust lanes, one owned file each, each a client-observable capability provable standalone:

- GUI-001-A (gui_resume.rs): Last-Event-ID + ?after= resume, exclusive seq>after, resync.required on overflow, 204 on revoked token. Owns T00.
- GUI-001-B (gui_handshake.rs): POST /api/handshake capability negotiation + payload degradation.
- GUI-001-C (gui_permission.rs): exactly-once first-responder-wins arbitration; TTL=>DENY; no-client=>DENY; desktop-attached lock.
- GUI-001-D (gui_batching.rs): server-side token batching, 50ms/32-token windows (~40 events per 2,000-token response, not 2,000).
- GUI-001-E (crates/conformance): frozen fixture corpus + replay assertion every client is graded against. Frozen BEFORE any client exists.

Wave W2 — one working macOS app, 1 lane: real window, connect -> stream -> forced-reconnect survival -> permission prompt. Vertical slice, owns its app entry, no dead code.

Wave W3 — macOS deepening, 4 parallel lanes, disjoint files: NSTableView transcript (cell reuse; never LazyVStack) + incremental block-split highlight (Neon/HighlighterSwift; TextKit 1, never TextKit 2 for append-at-bottom) + coalesced 8-16ms flush off-main; NSTextView composer + CJK IME (never TextEditor); MenuBarExtra/sandbox/notarize/Sparkle 2/signing; theming + a11y + settings. All consume BRAND and the W1-e corpus.

Wave W4 — one working Linux GTK4 app, 1 lane: real window over the same corpus. Starts only after a real human has used the macOS app. Floor: GTK 4.14 API, v4_14 feature flags max on host builds, Flatpak primary, libadwaita optional, GtkListView, Wayland-native, headless via Xvfb.

Wave W5 — Linux deepening, 3 parallel lanes: packaging (deb/rpm/Flatpak built on oldest host), IME/CJK matrix, a11y/portal hardening.

Phase 3 (separate cards, not this program): Windows GUI (WPF/.NET 10 unpackaged self-contained recommended; named pipes; revisited against the frozen corpus), mobile (PWA 3.0 -> Android 3.1 -> iOS 3.2; no Rust in the app; reconnect+resume not keepalive; APNs/FCM nudges with fail-closed expiry).

## Failure states (program-level)

- A lane needing a file it does not own STOPS and files an integration proposal. No exceptions, no drive-by edits. (This is the friction-killer.)
- No leaf depends on another leaf in the same wave. A leaf that feels blocked by a peer is a decomposition error, not a scheduling problem — re-decompose.
- A parent stays open while any leaf is unaccepted or any path is unwired (convergence rule). This umbrella closes only when every leaf is accepted AND the corpus test passes on the merged tree.
- Windows/mobile scope creep into this program: rejected; they are separate cards.

## Resource bounds (program-level)

- Bounded replay (2,000 events / 4 MiB cap, persisted); `buffered_bytes` under cap under slow-consumer test; no unbounded queue/retained output anywhere. Each leaf states its own bounds; the gate (E3) checks them.
