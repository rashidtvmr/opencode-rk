## User-observable outcome

Native code can resolve a caller-supplied request/session location hint into
a deterministic project identity/location context (canonical directory,
optional branded workspace identity, optional git VCS metadata) without
performing filesystem discovery, git I/O, database reads/writes, or owning
the core Location runtime. Callers keep filesystem/git/database authority;
this slice proves the precedence and session-pinning rules: request-scoped
routes honor explicit directory/workspace hints with deterministic fallback,
while session-scoped routes ignore request context and reuse the pinned
session directory/workspace.

## Observable contract

- `DirHint { path: String }` 1..=256 chars, must start with `/`, charset
  `[A-Za-z0-9/._-]`; `WsHint { id: String }` 1..=64 chars, must start with
  `wrk`, charset `[A-Za-z0-9_-]`; `VcsInfo { remote: Option<String>,
  branch: Option<String> }` caller-supplied only (never discovered here).
- `RequestCtx { dir: Option<DirHint>, ws: Option<WsHint> }`;
  `SessionPin { directory: String, workspace_id: Option<String> }`
  (caller-pinned; same charsets as hints).
- `LocationCtx { directory: String, workspace_id: Option<String>,
  vcs: Option<VcsInfo>, identity: Identity }`;
  `Identity { Global, RootCommit(String), CommonDir(String), Remote(String) }`
  precedence: explicit non-file `remote` > `CommonDir` > `RootCommit` >
  `Global`; file-scheme remotes (`file:...`) contribute no identity (fall
  through); absent everything => `Global`.
- `resolve_request(ctx: &RequestCtx, default_dir: &str, vcs: Option<VcsInfo>)
  -> Result<LocationCtx, CtxError>`: explicit `dir` wins when valid;
  malformed dir falls back to `default_dir` deterministically (never dies);
  explicit `ws` kept only when valid else `None`; identity derived from
  caller-supplied `vcs.remote`/`common_dir`/`root_commit` per precedence.
- `resolve_session(pin: &SessionPin, req: &RequestCtx, vcs: Option<VcsInfo>)
  -> Result<LocationCtx, CtxError>`: ignores `req` entirely (session never
  accepts request context); returns pinned directory/workspace; invalid
  pinned directory => `Err(CtxError::InvalidPin)`; unknown session binding
  is the caller's `Err`, never invented here.
- `CtxError { InvalidPin, InvalidDefault }`; request-path malformed hints
  fall back rather than error (matches upstream best-effort reads).
- Bounds as explicit public constants (upstream supplies none; frozen RED
  owns values): `MAX_DIR_LEN = 256`, `MAX_WS_LEN = 64`.
- Deterministic: same `(ctx/pin, defaults, vcs)` => byte-identical
  `LocationCtx`; no wall-clock, no filesystem read in ordering.
- Suggested module boundary: new pure in-memory module
  `crates/integration/src/location_ctx.rs` (same crate as INT-007);
  worker ships additive fragment only, never edits shared `lib.rs`,
  `Cargo.toml`, schemas, migrations. Independent test owner:
  `crates/integration/tests/location_ctx.rs` (or equivalent).
- Explicitly excluded: filesystem/git discovery, remote/history reads,
  project-cache read/commit, legacy migration/persistence, session DB
  reads, LocationServiceMap/config runtime, EventV2 emission (INT-008
  separation), network, background work, new dependencies.

## Failure states

- Malformed request `dir` (empty, too long, bad charset, not absolute):
  deterministic fallback to `default_dir`; `workspace_id` unaffected.
- Malformed request `ws` (empty, too long, not `wrk`-prefixed):
  dropped to `None`; directory still resolves.
- Invalid `default_dir` (malformed same rules): `Err(InvalidDefault)`; no
  context invented.
- Session pin with malformed directory: `Err(InvalidPin)`; request hints
  never consulted as rescue.
- `file:`-scheme remote: contributes no identity (falls to next precedence);
  non-file remote: becomes `Identity::Remote` top precedence.
- Secret safety: hints carry directory/workspace strings only; no
  credentials; nothing secret logged. No SQLite/OpenCode DB reads/writes.
  Tests use disposable in-memory hints only.

## Resource bounds

- Length caps: `MAX_DIR_LEN`/`MAX_WS_LEN` bound retained strings; `resolve_*`
  validate before clone; no unbounded queue of pending contexts.
- Byte caps: returned `LocationCtx` is a small fixed-shape struct (bounded
  strings + optional small `VcsInfo`); no vector growth, no retained output
  beyond one struct per call.
- Owner/cancel path: caller owns all inputs/outputs; both functions
  synchronous on `&`, spawn no thread; no cancellation token needed
  (sub-microsecond ops); no detached task, no background finalizer, no
  host process.
- Zero hidden cost: resolution allocates only the bounded output struct;
  fallback path allocates nothing beyond the default-dir copy.
