## User-observable outcome

The native HTTP boundary decodes the canonical typed control-plane input
(MoveSession shape) exactly once, at the route layer, before any domain
service runs. A well-formed request reaches the domain service with identical
field values; a malformed request is rejected at the boundary with no domain
side effect. `web/` browser code is owned elsewhere; this card specifies the
server-side decode contract only.

## Observable contract

- New additive Rust boundary: `crates/server/src/control_plane_inputs.rs`
  (suggested; worker ships additive fragment only, never edits shared `lib.rs`,
  `Cargo.toml`, schemas, migrations; integrator wires).
- `MoveSessionInput { session_id: SessionId, target_directory: RelPath, target_workspace: Option<WorkspaceId> }`:
  decoded once at the route layer from the canonical JSON wire shape; field
  values forwarded to the domain service byte-identical (no normalization,
  no defaulting beyond explicit `Option` absence).
- Absent optional keys stay absent (`None`); a present `null` for a required
  field is rejected, not coerced.
- Decode is total: `decode_move_session_input(bytes) -> Result<MoveSessionInput, InputDecodeError>`.
  `InputDecodeError` is `{ MissingField(&'static str), MalformedField(&'static str), BodyTooLarge }`.
- Body cap: requests larger than `MAX_CONTROL_INPUT_BYTES = 64 * 1024` are
  rejected with `BodyTooLarge` before JSON parsing.
- Deterministic: same bytes + same cap => same `Ok` value or same `Err` variant;
  no wall-clock, no I/O, no randomness in decode.
- Domain service is not invoked on decode failure (asserted by test spy, not by
  error string alone).

## Failure states

- Missing required field (`session_id`, `target_directory`):
  `Err(InputDecodeError::MissingField(name))`; service call count stays 0.
- Wrong JSON type (e.g. numeric `session_id`, null required field, non-object top):
  `Err(InputDecodeError::MalformedField(name))`; service call count stays 0.
- Body over `MAX_CONTROL_INPUT_BYTES`: `Err(InputDecodeError::BodyTooLarge)`;
  no partial parse, no service call.
- Unknown extra keys: ignored (forward compatibility); decode still succeeds and
  forwarded struct contains only canonical fields.
- Secret safety: input values never logged; test fixtures use disposable dirs;
  no user OpenCode DB writes; no network.

## Resource bounds

- Byte cap: `MAX_CONTROL_INPUT_BYTES` (64 KiB) bounds retained input; parse works
  on the bounded buffer; no unbounded retained output.
- No queue, thread, task, clock, watcher, or background finalizer. Decode is pure
  and synchronous over caller-owned bytes; output borrows nothing beyond owned return.
- Owner/cancel path: none needed (synchronous, bounded); caller owns input
  lifetime; no detached work.
- Disabled path: not applicable (pure function; zero cost when uncalled).

## Test obligations (frozen)

- WEB-001-T01 (happy-path decode + forward): canonical JSON bytes =>
  `assert_eq!(input.session_id.as_str(), "ses_abc")`,
  `assert_eq!(input.target_directory.as_str(), "proj/x")`,
  `assert!(service.calls() == 1)` with forwarded values equal to decoded struct.
- WEB-001-T02 (absent vs null): missing `target_workspace` => `assert!(input.target_workspace.is_none())`;
  explicit `null` required field => `assert_eq!(err, MalformedField("session_id"))`
  and `assert_eq!(service.calls(), 0)`.
- WEB-001-T03 (malformed rejection): non-object top-level / wrong types =>
  `assert!(matches!(err, MalformedField(_)))`, `assert_eq!(service.calls(), 0)`;
  unknown extra keys still decode `Ok` with canonical fields intact.
- WEB-001-T04 (byte cap): body of `MAX_CONTROL_INPUT_BYTES + 1` =>
  `assert_eq!(err, BodyTooLarge)` and parse never attempted
  (`assert!(!parser_entered())`); 10k small bodies decode without growth
  (no OOM, bounded RSS delta asserted by harness).
- WEB-001-T05 (no side effect + safety): failing decode on missing root fixture =>
  `Ok/Err` without filesystem I/O (`assert_eq!(service.calls(), 0)`,
  `assert!(fixture_outside_untouched())`); captured logs contain zero input-body
  bytes beyond field names.
