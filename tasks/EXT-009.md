## User-observable outcome

Bounded, in-memory skill/command namespacing boundary for one caller-owned
registry at a time: callers register skill/command name declarations from
ordered sources, later sources win on name collision, and list/lookup
projections are deterministic. No filesystem traversal, no remote discovery,
no file extraction, no policy gating, no handler execution, no UI
presentation. Later-source precedence and permission-shape filtering inputs
are recorded as inert metadata only; actual permission evaluation stays with
its owners.

## Observable contract

- `EntryKind { Skill, Command }`; `NameDecl { kind: EntryKind, name: String,
  source: u32 }`: `name` 1..=64 chars, `[A-Za-z0-9][A-Za-z0-9._-]*`;
  `source` is caller-supplied order key (larger wins on collision).
- `MAX_NAMES: usize = 512`, `MAX_NAME_LEN: usize = 64`
  (explicit public constants; upstream supplies none; frozen RED owns values).
- `Namespace::new() -> Namespace` (empty, no I/O, no threads).
  - `register(&mut self, decl: NameDecl) -> Result<bool, NamespaceError>`:
    validates name; inserts new `(kind,name)` => `Ok(true)`; same
    `(kind,name)` with `source >= existing.source` replaces and returns
    `Ok(false)` (later-source precedence); same `(kind,name)` with
    `source < existing.source` keeps existing and returns `Ok(false)`.
    Skill and Command namespaces are independent (same string in both kinds
    coexists). Overflow => `Err(Overflow)`, registry unchanged.
  - `unregister(&mut self, kind: EntryKind, name: &str) -> bool`: removes
    exactly that entry; unknown => `false`, registry otherwise unchanged.
  - `lookup(&self, kind: EntryKind, name: &str) -> Option<&NameDecl>`.
  - `list(&self, kind: EntryKind) -> Vec<&NameDecl>` sorted by name
    ascending (deterministic; no wall-clock).
- Deterministic: same register/unregister sequence => identical
  `list()`/`lookup()` output. No wall-clock anywhere.
- Suggested module boundary: new pure in-memory module
  `crates/ext/src/namespacing.rs` (crate `opencode-rk-ext`); worker ships
  additive fragment only, never edits shared `lib.rs`, `Cargo.toml`,
  schemas, migrations. Independent test owner:
  `crates/ext/tests/plugin_namespacing.rs`.
- Explicitly excluded: skill file discovery/listing, filesystem traversal,
  remote URL discovery, cache lifetime/invalidation, permission evaluation
  (TOOL-007/SEC-001), handler/invocation execution, hook execution
  (REQ-020), file extraction/materialization (EXT-013), slash-invocation and
  UI/TUI presentation (UI-010/UI-012/EXT-012), reload/watch, external host,
  network, persistence, environment lookup, credentials/secrets, HTTP routes,
  background work, new dependencies.

## Failure states

- Invalid name (empty, too long, bad charset): `Err(NamespaceError::InvalidName)`;
  registry unchanged.
- Registry full (`len == MAX_NAMES` across both kinds): `Err(Overflow)`;
  registry unchanged; never exceeds cap.
- `unregister` unknown entry: returns `false`; registry unchanged (harmless).
- `lookup` unknown entry: returns `None`; no state change.
- Same-name cross-kind entries never collide: registering `"run"` as Command
  while `"run"` exists as Skill => `Ok(true)` with both present.
- Secret safety: entries hold kind/name/source only; no file bodies, no
  credentials; nothing secret logged. No SQLite/OpenCode DB writes. Tests use
  disposable in-memory registries only.

## Resource bounds

- Count cap: `MAX_NAMES` bounds all entries; `register` cap-checks before
  push; no unbounded queue of pending declarations.
- Byte cap: name length cap bounds retained bytes (max ~512 * 64 bytes,
  small and constant); `list()` returns bounded borrowed refs; no unbounded
  retained output.
- Owner/cancel path: caller owns the `Namespace` lifetime and source ids;
  all methods synchronous on `&mut self`/`&self`, spawn no thread; no
  cancellation token needed (constant-time ops); no detached task, no
  background finalizer, no host process.
- Zero hidden cost: `new()` + `list()` allocates only the empty vec; no
  threads, no watchers, no discovery.

  `("test", src 1)` and command `("lint", src 1)` => `list(Skill).len() == 2`

  `lookup(Skill,"lint").source == 1`; cross-kind `"lint"` coexists in both.

  `"lint"` src 2 => `Ok(false)`, `lookup` source now 2; re-register src 1
  => `Ok(false)`, source stays 2; `unregister(Skill,"lint")` => `true`,
  `lookup` => `None`, command `"lint"` still present;
  `unregister(Skill,"ghost")` => `false`, registry unchanged.
- EXT-009-T03 (validation, registry unchanged): empty/bad name (`""`,
  `"a/b"`, `" a"`, 65 chars) => `assert_eq!(err, InvalidName)`; fill to
  `MAX_NAMES` then one more => `Err(Overflow)` and total len ==
  `MAX_NAMES`; each error leaves `list()` byte-identical to before the call.
- EXT-009-T04 (determinism): same register sequence built twice =>
  `list(Skill)` name/source pairs equal and `list(Command)` equal; two
  sources racing on one name resolve deterministically to the larger source.
- EXT-009-T05 (no discovery/side-effect safety): run full matrix while
  asserting no child process spawned, no files created outside the
