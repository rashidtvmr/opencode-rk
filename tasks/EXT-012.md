## User-observable outcome

Declarative UI-contribution boundary for one caller-owned plugin scope at a
time: native code can record which plugin scope contributed which bounded UI
declaration (command entry, panel slot, status item), list those declarations
in deterministic registration order, revoke one scope without touching
others, and prove that no presentation executes, no JavaScript host starts,
and no renderer is touched by this slice. Real rendering, TUI/Solid
presentation, and client architecture stay deferred to UI-012
(dependency-constrained). Manifest shape validation (EXT-005), lifecycle
add/remove/wait (EXT-001), scoped execution (EXT-006), and hook mutation
(EXT-008) are explicitly out of scope.

## Observable contract

- `UiSurface { Command, Panel, StatusItem }`; `UiDecl { surface:
  UiSurface, label: String, detail: String }`: `label` 1..=64 chars,
  `detail` 0..=256 chars, charset `[A-Za-z0-9][A-Za-z0-9._-]*` for label,
  printable ASCII (no control chars) for detail.
- `ActivationGate { closed }`: `closed()` default; `open()` requires an
  explicit caller call (tests open it only to assert the boundary still
  holds; opening never renders or imports anything in this slice).
- `UiBoundary::new() -> UiBoundary` (empty, no I/O, no threads).
  - `declare(scope: u64, decl: UiDecl) -> Result<u64, UiError>`: validates
    label/detail, rejects duplicates (same scope+surface+label) and
    overflow, assigns monotonic `UiId(u64)` from 1, records insertion
    order. Works identically whether the gate is open or closed (recording
    is not presentation).
  - `revoke_scope(scope: u64) -> u64`: removes only that scope's decls,
    returns count removed; unknown scope => 0, registry otherwise unchanged
    (mirrors EXT-003/EXT-008 close-unknown semantics).
  - `list() -> Vec<(UiId, u64 /*scope*/, UiDecl)>` sorted by `UiId`
    ascending (registration order, deterministic).
  - `describe(id: u64) -> Option<(u64 /*scope*/, UiDecl)>`: pure metadata
    projection for the future renderer; performs zero rendering.
  - `request_render(id: u64) -> Err(UiError::Deferred)`: always deferred
    while the gate is closed AND while open in this slice (no renderer
    ships here); proves the boundary: recording/describe never presents.
- Bounds as explicit public constants (upstream supplies none; frozen RED
  owns values): `MAX_UI_DECLS: usize = 64`, `MAX_LABEL_LEN = 64`,
  `MAX_DETAIL_LEN = 256`.
- Deterministic: same declare/revoke sequence => identical `list()`.
  No wall-clock in ordering or ids.
- Suggested module boundary: new pure in-memory module
  `crates/ext/src/ui_boundary.rs` (crate `opencode-rk-ext`); worker ships
  additive fragment only, never edits shared `lib.rs`, `Cargo.toml`,
  schemas, migrations. Independent test owner:
  `crates/ext/tests/plugin_ui_boundary.rs`.
- Runtime optional True: when the UI-contribution feature is off, none of
  these functions is called; the boundary is never constructed; zero cost
  (mirrors TOOL-016 opt-out proof).
- Explicitly excluded: manifest validation (EXT-005), lifecycle
  add/remove/wait (EXT-001), scoped execution and broker gating (EXT-006),
  hook declaration/execution (EXT-008), EXT-009 lifecycle-adjacent
  behavior, any renderer/TUI/Solid/client work (UI-012), external JS/TS
  import, filesystem, network, persistence, environment lookup,
  credentials/secrets, HTTP routes, background work, new dependencies.

## Failure states

- Invalid label (empty, too long, bad charset):
  `Err(UiError::InvalidLabel)`; registry unchanged.
- Invalid detail (too long, control chars):
  `Err(UiError::InvalidDetail)`; registry unchanged.
- Duplicate (same scope+surface+label): `Err(UiError::Duplicate)`;
  registry unchanged, no id consumed.
- Registry full (`len == MAX_UI_DECLS`): `Err(UiError::Overflow)`;
  registry unchanged; never exceeds cap.
- `request_render` any id (known or unknown): `Err(UiError::Deferred)`; no
  presentation runs, gate state unchanged. Unknown id is deferred, never
  success.
- `describe` unknown id: returns `None`; registry unchanged.
- `revoke_scope` unknown scope: returns `0`; registry unchanged (harmless).
- Secret safety: decls hold surface/label/detail strings only; no tool I/O,
  no credentials; nothing secret logged. No SQLite/OpenCode DB writes.
  Tests use disposable in-memory boundary only.

## Resource bounds

- Count cap: `MAX_UI_DECLS` bounds the vec; `declare` cap-checks before
  push; no unbounded queue of pending declarations.
- Byte caps: label/detail length caps bound retained bytes (max ~64 * 320
  bytes, small and constant); `list()`/`describe()` return bounded copies;
  no unbounded retained output.
- Owner/cancel path: caller owns the `UiBoundary` lifetime and scope ids;
  all methods synchronous on `&mut self`/`&self`, spawn no thread; no
  cancellation token needed (sub-microsecond ops); no detached task, no
  background finalizer, no host process, no renderer handle.
- Disabled path (feature off): boundary never constructed; zero allocation,
  zero threads, zero I/O.

## Test obligations (frozen)

- EXT-012-T01 (happy path): gate closed; declare 3 decls across 2 scopes
  (command + panel + status mix) => ids 1,2,3; `list().len() == 3` in id
  order; `describe(2)` returns the panel decl with its scope;
  surfaces/labels match inputs.
- EXT-012-T02 (scope revoke): declare 2 in scope 7, 1 in scope 8;
  `revoke_scope(7)` => 2 and `list().len() == 1` with scope-8 decl only;
  `revoke_scope(unknown)` => 0 and `list()` unchanged; `describe` of a
  revoked id => `None`; re-declare same surface/label under a fresh scope
  after revoke => `Ok` (no ghost duplicate).
- EXT-012-T03 (validation, registry unchanged): duplicate decl =>
  `Err(Duplicate)`; empty/bad label => `Err(InvalidLabel)`; 257-char
  detail => `Err(InvalidDetail)`; fill to `MAX_UI_DECLS` then one more =>
  `Err(Overflow)` and `len == MAX_UI_DECLS`; each error leaves `list()`
  byte-identical to before the call.
- EXT-012-T04 (deferred presentation): gate closed: `request_render(known)`
  => `assert_eq!(err, Deferred)`; `request_render(unknown)` =>
  `Err(Deferred)`; open the gate: `request_render(known)` still =>
  `Err(Deferred)`; recording still works while open (declare => `Ok`);
  `describe` output byte-identical before/after every `request_render` (no
  presentation side channel).
- EXT-012-T05 (no host/renderer side-effect safety): run full matrix while
  asserting no child process spawned, no renderer/thread started, no files
  outside the disposable test dir, no DB writes; captured logs contain zero
  label strings beyond the test's own short names and zero
  credential-like bytes; gate-ever-opened test asserts still zero render
  invocations via a counter the (absent) renderer would have hit.
