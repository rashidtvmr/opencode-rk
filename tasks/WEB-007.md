# WEB-007 - Transcript geometry and per-message action bars

Status: NOT STARTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: existing web transcript and message API.
Test obligations: WEB-007-T01, WEB-007-T02, WEB-007-T03, WEB-007-T04, WEB-007-T05.

## User-observable outcome

Every request/response occupies a full-width transcript row. User content is aligned
right, assistant content left, and all role-appropriate actions appear below the
message rather than floating over it. Every persisted user/assistant row includes a
visible **Fork** trigger; activating it opens the message-owned branch popover.

## Observable contract and tests

- **WEB-007-T01 — row/action happy path:** user and assistant rows span the transcript
  width, align their content by role, and expose the correct below-message action bar,
  including a Fork trigger whose popover contains **Branch in new chat**.
- **WEB-007-T02 — unavailable action honesty:** actions that lack a real backend
  capability are disabled/omitted with an explanation and never simulate success.
- **WEB-007-T03 — accessibility:** DOM reading order remains chronological; every
  action has an accessible name, visible focus and keyboard operation; Fork opens its
  popover from keyboard, Escape closes it and focus returns to Fork; 200%/400% reflow
  does not obscure message content or controls.
- **WEB-007-T04 — bounds:** large messages/action sets do not create unbounded retained
  UI state or layout work; reduced-motion preference is respected.
- **WEB-007-T05 — persistence/render compatibility:** persisted legacy messages and
  newly streamed messages render the same action-row geometry after reload.
