# WEB-016 - Voice and dictation

Status: IN PROGRESS / NOT ACCEPTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: real native audio/realtime provider adapter.
Test obligations: WEB-016-T01, WEB-016-T02, WEB-016-T03, WEB-016-T04, WEB-016-T05.

## User-observable outcome

Users can dictate into the composer and, where a real realtime/audio adapter exists,
hold a voice conversation with synchronized text transcript and explicit microphone
state.

## Observable contract and tests

- **WEB-016-T01 — audio happy path:** permissioned microphone capture reaches a real
  native transcription/realtime adapter and produces visible editable transcript.
- **WEB-016-T02 — permission/adapter failure:** denied microphone, missing device or
  unsupported provider stays explicit; text chat remains usable and no fake transcript
  is generated.
- **WEB-016-T03 — accessibility:** voice controls have non-audio labels/state, live
  text transcript, keyboard stop/mute, and never make voice the only interaction path.
- **WEB-016-T04 — resource lifecycle:** capture duration/buffers/reconnects are bounded;
  mute/stop/unmount releases media tracks and provider stream promptly.
- **WEB-016-T05 — transcript fidelity:** persisted text/audio metadata follows the
  configured retention contract and reconnect does not duplicate utterances.

## Current implementation boundary

- The daemon capability manifest reports voice unavailable because no native
  transcription/realtime audio adapter is installed.
- The composer keeps text chat usable and exposes a disabled, screen-reader-labelled
  voice control containing that daemon-provided reason. It never requests microphone
  access while the capability is unavailable.
- Capture, transcription, realtime conversation and audio retention remain absent;
  no fake transcript is generated. This story remains NOT ACCEPTED.
