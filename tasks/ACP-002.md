## Observable contract

- `Capability { FileRead, FileWrite, Terminal, Auth, ModeSwitch, HistoryRestore, UpdateStream }`: closed enum; every ACP-adjacent request maps to exactly one variant.
- `is_supported(cap: Capability) -> bool`: true only for FileRead/FileWrite; all others false by construction.
- `require(cap: Capability) -> Result<(), AcpFileError>`: FileRead/FileWrite => Ok; anything else => `Err(Unsupported { capability })` naming the variant.
- `read_text(root: &Path, rel: &str, fs: &dyn FileReader) -> Result<String, AcpFileError>`: rel must be a root-relative `a/b.txt` path (no `..`, no absolute, max 512 chars); content max MAX_ACP_FILE_BYTES; non-UTF8 => `Err(NotText)`.
- `write_text(root: &Path, rel: &str, text: &str, fs: &mut dyn FileWriter) -> Result<u64, AcpFileError>`: same path rules; text bytes max MAX_ACP_FILE_BYTES; returns bytes written; writes via caller-supplied trait only (this module performs no direct fs I/O).
- `FileReader`/`FileWriter` are caller-supplied traits over a disposable fixture dir in tests; production wiring is the integrator's, not this slice's.
- Bounds as explicit public constant: `MAX_ACP_FILE_BYTES: usize = 1_048_576` (1 MiB) per file.
- Deterministic: same root plus same fixture files plus same calls => byte-identical results; no wall-clock, no ambient fs, no globals.
- Suggested module boundary: `crates/server/src/acp_files.rs` owning Capability, FileReader, FileWriter, AcpFileError, MAX_ACP_FILE_BYTES, is_supported, require, read_text, write_text; shared lib.rs wiring left to integrator.
- Explicitly excluded: ACP framing/session/modes (ACP-001), terminal/auth/mode/history/update implementations (rejected, never built here), ambient filesystem access, network.

## State and persistence transitions

- Capability state: fixed at compile time; no runtime registration, no feature flags, no state change.
- Read path: pure projection of caller-supplied files; performs no state change by construction.
- Write path: single atomic write_text call per invocation; success reports bytes written; failure writes nothing (trait contract: implementations must be all-or-nothing; tests assert fixture bytes unchanged on error).
- Persistence: files themselves are caller-owned via the injected traits; this module retains nothing between calls.

## Failure states

- Unsupported capability: `Err(Unsupported { capability })` naming Terminal/Auth/ModeSwitch/HistoryRestore/UpdateStream; no fallback attempted, no partial behavior.
- Path escape (`..`, absolute, empty, > 512 chars): `Err(AcpFileError::PathNotAllowed)`; nothing read or written.
- Missing file on read: `Err(AcpFileError::NotFound)`; nothing returned.
- Oversize content (> 1 MiB) either direction: `Err(AcpFileError::TooLarge)`; writes leave fixture bytes unchanged.
- Non-UTF8 file on read: `Err(AcpFileError::NotText)`; nothing returned.
- Secret safety: errors carry paths and variant names only, never file content. Tests use disposable fixture dirs and generated datasets only.

## Resource bounds

- Byte caps: read content and written text each capped at 1 MiB; rejected before retention (no unbounded queue/output).
- Path caps: rel max 512 chars; no glob, no recursion, one file per call.
- Owner/cancel path: caller owns root, traits, and all file lifetimes; functions synchronous, spawn no thread; no cancellation token needed; no detached task, no background watcher, no network handle.
- Zero hidden cost: no statics, no cache; idle cost is zero.
