# INT-006 - Remote MCP transport/auth boundary

Status: NOT STARTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: none (DISC-002 discovered `opencode.integrations` residual; remote MCP auth/transport reconciliation deferred per finding).
Dependencies: none.
Test obligations: INT-006-T01, INT-006-T02, INT-006-T03, INT-006-T04, INT-006-T05.

## User-observable outcome

Native code can describe one remote MCP server attachment (endpoint, transport,
auth mode), validate it before any connection, run a bounded connect/handshake
with explicit timeout and cancellation, and close it with all resources
reclaimed. No MCP session semantics, tool listing, or prompt behavior is
claimed; this slice owns only the transport/auth boundary up to handshake.

## Observable contract

- `McpTransport`: `Sse { url: HttpsUrl }` | `WebSocket { url: WssUrl }` |
  `Stdio { bin: AbsPath, argv: Vec<OsArg> }`. Only `https://` / `wss://`
  accepted for remote; anything else (incl. plain `http:`/`ws:`) is rejected
  before connect. `url` max 2 KiB, `argv` max 32 entries x 1 KiB each.
- `McpAuth`: `None` | `BearerHandle { handle: OpaqueId }` | `OAuthHandle { handle: OpaqueId }`.
  Handles are opaque 128-B-max ids; raw tokens never cross this boundary.
- `McpAttachment::validate(&self) -> Result<(), McpError>`: scheme/allowlist,
  length, and arg-count checks; `connect(cfg, cancel: &AtomicBool) -> Result<McpSession, McpError>`
  runs a bounded handshake (`HANDSHAKE_TIMEOUT_MS = 10_000`, max 64 KiB handshake
  bytes); `McpSession::close(self)` reclaims everything.
- Handshake result is `McpSession { endpoint_label, transport, auth_mode }`
  (label only, no retained body); session owns exactly one transport handle.
- Suggested module boundary: new `crates/providers/src/int_mcp.rs`
  (additive fragment only). Worker never edits shared `lib.rs`, `Cargo.toml`,
  schemas, or migrations; integrator wires exports.
- Caller owns handle-to-secret resolution, actual socket/process creation policy,
  MCP session semantics, tool calls, persistence, and events.

## Failure states

- Invalid endpoint (bad scheme, over length, bad argv): `Err(McpError::InvalidEndpoint)`;
  no connection attempted, no process spawned.
- Missing/unknown auth handle: `Err(McpError::AuthRejected)`; no retry, no secret logged.
- Handshake timeout (>10s), over 64 KiB, or pre-set cancel flag:
  `Err(McpError::HandshakeTimeout | McpError::HandshakeTooLarge | McpError::Cancelled)`;
  partial bytes dropped, handle closed.
- Remote close/reset mid-handshake: `Err(McpError::TransportClosed)`; resources reclaimed.
- Secret safety: handles only; tokens/keys never accepted, retained, or logged.
  No SQLite/OpenCode DB writes. No changes to the user's existing OpenCode database;
  tests use disposable fixture loopback/fake transports only, never live network.

## Resource bounds

- One attachment = one handle; no reconnect loop, no retry queue, no registry.
  Concurrent attachments bounded by caller; this module caps handshake bytes
  (64 KiB) and time (10 s) per connect.
- Count caps: `argv` <= 32, each <= 1 KiB; url <= 2 KiB; handshake buffer <= 64 KiB;
  no unbounded outbox (contrast pinned PTY outbox gap, deliberately not repeated).
- Owner/cancel path: `cancel: &AtomicBool` checked before connect and per
  handshake chunk; `close(self)` consumes the session and closes the handle;
  `Drop` closes if not explicitly closed; no detached task, no thread, no clock thread.
- Zero hidden cost when idle: no listener, watcher, or background task; validation
  alone performs zero I/O.

- INT-006-T01 (validate + handshake happy path): valid SSE attachment validates Ok;

- INT-006-T02 (transport/mode matrix): each of SSE/WebSocket/Stdio x None/Bearer/OAuth

- INT-006-T03 (bounds hold): 65 KiB fake handshake => `assert_eq!(err, HandshakeTooLarge)`;
  33 argv entries (or 2 KiB+1 url) => `assert_eq!(err, InvalidEndpoint)`;
  slow fake exceeding 10 s (virtual clock, no wall sleep) => `assert_eq!(err, HandshakeTimeout)`;
  all with handles closed (`open_handles() == 0`).
- INT-006-T04 (failure + cancel): pre-set cancel => `assert_eq!(err, Cancelled)` and
  prompt return (<1s on large fixture); mid-handshake remote close =>
  `assert_eq!(err, TransportClosed)`; unknown auth handle => `assert_eq!(err, AuthRejected)`;
  every failure asserts `open_handles() == 0` (reclaimed), not just an error string.
- INT-006-T05 (no side effects + safety): validation performs zero I/O (assert no
  FS/DB writes outside disposable fixture dir); captured logs contain zero handle
  bytes beyond a fixed `hdl-***` redaction and zero url query secrets; no test
  opens a live socket or spawns a real process (assert fake-transport marker present).
