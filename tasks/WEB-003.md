## User-observable outcome

The native server exposes its concrete HTTP routes as a projection of one
authoritative Protocol API definition: every served route exists in Protocol,
route handlers are thin callers over domain services, and domain/storage
services import zero HTTP/wire types. Adding a route without a Protocol entry
fails the suite. `web/` browser code is owned elsewhere; this card specifies
the server-side API-projection contract only.

## Observable contract

- New additive Rust boundary: `crates/server/src/protocol_api.rs` (suggested;
  worker ships additive fragment only, never edits shared `lib.rs`, `Cargo.toml`,
  schemas, migrations; integrator wires).
- `ProtocolRoute { method: Method, path: &'static str, handler: &'static str }`;
  `PROTOCOL_ROUTES: &[ProtocolRoute]` is the single authoritative table
  (minimum seed: `GET /health`, `POST /control/move_session`, `GET /events` SSE).
- `served_routes() -> Vec<(Method, &str)>` enumerates routes actually registered
  on the native router; invariant `served_routes() ⊆ PROTOCOL_ROUTES`
  (method + path equality; path templates compared literally).
- `assert_protocol_coverage()` test helper fails if any served route lacks a
  Protocol entry, or if two entries share the same (method, path) key.
- Handlers are thin: each handler decodes input (WEB-001), calls exactly one
  domain service method, translates errors (WEB-002); handler body performs no
  Git/filesystem/network I/O directly (asserted by import scan + call spy).
- Deterministic: same table + same router build => same route list order (sorted
  by (method, path)); no wall-clock, no I/O in projection.

## Failure states

- Route without Protocol entry: `assert_protocol_coverage()` fails with the
  offending (method, path); server build harness refuses to start in test mode
  (`assert!(build_router().is_err())` when a rogue route is injected).
- Duplicate (method, path) in `PROTOCOL_ROUTES`: coverage helper fails naming
  the duplicate key; no silent shadowing.
- Handler importing domain-mutating I/O crates directly (git/fs/net): import-scan
  test fails naming the file and crate; fix is to move I/O into the domain service.
- SSE/raw misplacement: `GET /events` must be registered as an SSE stream route,
  not a JSON route (`assert!(route_kind("/events") == RouteKind::Sse)`); wrong kind fails.
- Secret safety: route table contains zero secrets/paths; tests use disposable
  fixtures; no user OpenCode DB writes; no network.

## Resource bounds

- Route table is a fixed static slice (no growth at runtime); router build is
  O(routes); `MAX_ROUTES = 256` (`assert!(PROTOCOL_ROUTES.len() <= 256)`).
- No queue, thread, task, clock, watcher, or background work introduced by the
  projection itself; per-route byte/stream limits stay with transport (WEB-005).
- Owner/cancel path: none (static table + synchronous build); caller owns router lifetime.
- No unbounded retained output: coverage failure prints at most the offending keys.
