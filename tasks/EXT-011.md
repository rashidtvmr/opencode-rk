## User-observable outcome

A bounded, in-memory plugin config-transform replay boundary for one
caller-owned registry at a time: plugin scopes contribute ordered,
validated key/value config transforms; the registry replays them in
registration order into a deterministic projection; a scope can be disabled
(its transforms stop projecting while staying recorded) and closed (its
transforms are removed and prior scope values for the same key are
revealed). No service is mutated, no host is started, no filesystem or
network is touched. Built-in cross-service composition stays out of scope.

## Observable contract

- `Transform { scope: u64, key: String, value: String, seq: u64,
  disabled_scope: bool }`: `key` 1..=128 chars
  `[A-Za-z0-9][A-Za-z0-9._-]*`; `value` 0..=1024 chars UTF-8 (no interior
  NUL); per-scope keys unique (same scope+key twice => `Duplicate`).
- `EXT11_MAX_TRANSFORMS: usize = 512`, `EXT11_MAX_KEY_LEN = 128`,
  `EXT11_MAX_VALUE_LEN = 1024` (explicit public constants; upstream supplies
  none; frozen RED owns values).
- `TransformLog::new() -> TransformLog` (empty, no I/O, no threads).
  - `add(scope: u64, key: &str, value: &str) -> Result<u64, TransformError>`:
    validates key/value, rejects per-scope duplicate and overflow, assigns
    monotonic `seq` from 1, records in insertion order.
  - `set_scope_disabled(scope: u64, disabled: bool)`: future `project()`
    skips (disabled) or includes (enabled) that scope's transforms; record
    itself is retained; unknown scope is harmless (no error, no-op).
  - `close_scope(scope: u64) -> u64`: removes only that scope's transforms,
    returns count removed; unknown/already-closed => 0, log otherwise
    unchanged (mirrors EXT-003 close-unknown semantics).
  - `project() -> Vec<(String, String)>`: replays non-disabled transforms in
    `seq` order; later `seq` wins per key; output sorted by key ascending
    (deterministic projection, pure).
- Deterministic: same add/disable/close sequence => identical `project()`.
  No wall-clock anywhere.
- Suggested module boundary: new pure in-memory module
  `crates/ext/src/transform_replay.rs` (crate `opencode-rk-ext`); worker
  ships additive fragment only, never edits shared `lib.rs`, `Cargo.toml`,
  schemas, migrations. Independent test owner:
  `crates/ext/tests/plugin_transform_replay.rs`.
- Explicitly excluded: composed-service mutation (catalog/config/commands/
  skills/integrations/agents/references/models/filesystem/HTTP), executable
  plugin callbacks, host launch, hook execution (REQ-020), skill/command
  internals (EXT-009), file extraction (EXT-013), policy gating (TOOL-007),
  UI presentation, reload/watch, filesystem, network, persistence,
  environment lookup, credentials/secrets, HTTP routes, background work, new
  dependencies.

## Failure states

- Invalid key (empty, too long, bad charset): `Err(TransformError::InvalidKey)`;
  log unchanged.
- Invalid value (too long, interior NUL): `Err(TransformError::InvalidValue)`;
  log unchanged.
- Per-scope duplicate key: `Err(TransformError::Duplicate)`; log unchanged,
  no `seq` consumed.
- Log full (`len == EXT11_MAX_TRANSFORMS`): `Err(TransformError::Overflow)`;
  log unchanged; never exceeds cap.
- `close_scope` unknown scope: returns `0`; unchanged (harmless).
- `set_scope_disabled` unknown scope: no-op, no error; projection unchanged.
- Secret safety: transforms hold short key/value labels only; no
  credentials; nothing secret logged. No SQLite/OpenCode DB writes. Tests use
  disposable in-memory logs only.

## Resource bounds

- Count cap: `EXT11_MAX_TRANSFORMS` bounds the vec; `add` cap-checks before
  push; no unbounded queue of pending transforms.
- Byte caps: key/value length caps bound retained bytes (max ~512 * 1152
  bytes); `project()` returns a bounded vec copy; no unbounded retained output.
- Owner/cancel path: caller owns the `TransformLog` lifetime and scope ids;
  all methods synchronous on `&mut self`/`&self`, spawn no thread; no
  cancellation token needed (linear replay over a capped vec); no detached
  task, no background finalizer, no host process.
- Zero hidden cost: `new()` allocates only the empty vec; disabled scopes
  cost no extra allocation beyond the retained records.

## Test obligations (frozen)

- EXT-011-T01 (happy path + replay): `add(7,"theme","dark")` => 1,
  `add(7,"font","mono")` => 2, `add(8,"theme","light")` => 3;
  `project()` => `[("font","mono"),("theme","light")]` (later seq wins,
  sorted by key).
- EXT-011-T02 (disable + close reveal): `set_scope_disabled(8, true)` =>
  `project()` theme reverts to `"dark"`; re-enable => `"light"` again;
  `close_scope(8)` => 1 and `project()` => `[("font","mono"),
  ("theme","dark")]`; `close_scope(8)` again => 0, projection unchanged;
  `close_scope(unknown)` => 0.
- EXT-011-T03 (validation, log unchanged): duplicate key in same scope =>
  `assert_eq!(err, Duplicate)`; empty/bad key => `Err(InvalidKey)`; 1025-char
  value and interior-NUL value => `Err(InvalidValue)`; fill to
  `EXT11_MAX_TRANSFORMS` then one more => `Err(Overflow)`; each error leaves
  `project()` byte-identical to before the call. Same key in different
  scopes => `Ok` (not a duplicate).
- EXT-011-T04 (no service mutation): build any EXT-001/003/007 registry (or
  test double), snapshot its `list()`; issue adds/disables/closes against
  the boundary; registry snapshot byte-identical afterwards; projection of
  512 entries completes promptly (<1 s).
- EXT-011-T05 (side-effect safety): run full matrix while asserting no child
  process spawned, no files outside the disposable test dir, no DB writes;
  captured logs contain zero value strings beyond the test's own short keys
  and zero credential-like bytes.
