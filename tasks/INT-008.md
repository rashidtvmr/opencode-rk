## User-observable outcome

Native code can decode and encode the canonical current OpenCode event wire shape and project one event into the legacy event payload shape, including the additional durable `sync` projection used by compatibility consumers, without starting transport/runtime services or duplicating accepted domain-event ownership.

## Observable contract

- New additive Rust boundary: `crates/contracts/src/opencode_event.rs`, exported from `crates/contracts/src/lib.rs`. Accepted `crates/contracts/src/events.rs` is not modified or re-owned.
- Current wire events carry validated `evt_` IDs, `type`, generic typed `data`, and optional `metadata`, `durable`, and `location`; absent optional fields are omitted when encoded. A present `metadata` or `durable` key must decode its underlying object schema rather than using JSON `null` as absence. Metadata values themselves remain unconstrained `unknown` values, so null values inside the metadata object are valid.
- A present `location` decodes only as the canonical `{directory, workspaceID?}` object. `directory` remains an unconstrained string at this pure wire boundary because the pinned `AbsolutePath` schema adds only a brand; a present `workspaceID` must be a string starting with `wrk`, with no stronger `wrk_` or existence rule. A present null/malformed location or workspace ID is rejected, while an absent key remains absent.
- Durable metadata preserves `aggregateID`, `seq`, and `version` exactly. `versioned_type(type, version)` returns the exact `${type}.${version}` compatibility key.
- Decoding rejects a missing ID or an ID that does not start with `evt_`. No stronger ID rule is invented because the pinned Schema only requires that prefix.
- The ordinary legacy projection is exactly `{id,type,properties:data}`.
- A durable current event additionally yields exactly one `sync` projection with `syncEvent {id,type:<type>.<version>,seq,aggregateID,data}`. A non-durable event yields no sync projection.

## Ownership, lifetime, resources, and exclusions

- Projection is pure and synchronous over one caller-owned event. The ordinary projection and optional sync projection borrow the source data and cannot outlive it.
- Projection cardinality is fixed: exactly one ordinary legacy projection plus at most one sync projection. No registry, history, queue, retry loop, thread, task, clock, watcher, or background finalizer is introduced.
- Transport remains responsible for byte/stream limits; this pure contract does not retain or buffer event histories.
- No network, filesystem, environment lookup, credentials/secrets, hidden JavaScript runtime, storage, database access, user OpenCode DB mutation, process execution, or new dependency is permitted.
- Explicitly excluded and kept with existing owners: BASE-002 `EventEnvelope`/`DomainEvent` semantics; DB-003 persistence; SESS-002 CRUD; the full EventManifest/domain union; EventV2 persistence/replay/pubsub; SSE subscription/heartbeat/headers; GlobalBus emission; instance/workspace location lookup; bridge subscriber/finalizer lifecycle; V2 config lowering; MoveSession Git/project/session mutation and event publication; daemon/bootstrap/auth/WEB-004 remote behavior.
- DISC-003 remains separately **IN PROGRESS / NOT ACCEPTED**. A locally GREEN INT-008 candidate does not imply verifier/controller acceptance.
