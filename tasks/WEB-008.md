# WEB-008 - Edit, retry, regenerate and branch semantics

Status: IMPLEMENTED / NOT ACCEPTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: SESS-018 typed fork boundary, existing turn execution.
Test obligations: WEB-008-T01, WEB-008-T02, WEB-008-T03, WEB-008-T04, WEB-008-T05.

## User-observable outcome

Users can edit an earlier request, retry/regenerate an answer and branch a
conversation without destroying the original history. Each persisted user/assistant
message action row has a Fork trigger. Its popover exposes **Branch in new chat**,
which creates and immediately opens a new session from that exact message boundary.
Branch ancestry is explicit and navigable.

## Fork / Branch in new chat contract

- The selected parent message is the branch boundary and is inherited **inclusive**.
- The parent session is never truncated, edited or reparented by a fork.
- The client identifies the selected boundary by message ID. The server resolves that
  message to its immutable sequence before invoking the format-2 fork primitive; durable
  provenance stores the parent session plus `fork_message_seq`. The API may echo/derive
  the selected boundary message ID, but the durable schema does not fabricate or persist
  a `fork_message_id`. A later project-aware implementation must also preserve
  project/workspace scope rather than moving the branch to global history.
- Both persisted user and assistant messages are valid visible branch boundaries.
  Internal system/tool rows are not exposed as user branch actions yet.
- The child title is deterministic and bounded from the source title (for example
  `Branch: <source title>` with the existing title byte limit), and the client selects
  the new session as soon as creation succeeds.
- Fork creation is atomic: any invalid/missing boundary, depth/history-cap failure or
  persistence error creates no partial child and leaves the source untouched.

## Observable contract and tests

- **WEB-008-T01 — real branch:** choosing Fork → Branch in new chat on a persisted
  message creates exactly one child session containing parent history through that
  selected message inclusive, stores parent-session + immutable boundary-sequence provenance,
  leaves source/later messages unchanged and navigates to the child. Cover both user
  and assistant boundaries.
- **WEB-008-T02 — retry failure semantics:** provider failure retains the user-visible
  branch/history state, produces no fake assistant record, and can be retried from a
  deliberate action.
- **WEB-008-T03 — accessible actions/navigation:** edit/retry/branch controls and
  branch chooser are keyboard/screen-reader operable; Fork has an accessible name,
  its popover announces Branch in new chat, Escape restores focus, and successful
  branching moves navigation to the newly created session without focus loss.
- **WEB-008-T04 — bounds/cancel:** fork depth/history copy limits and turn concurrency
  limits are enforced; cancelling a retry releases its provider/runtime resources.
- **WEB-008-T05 — reload fidelity:** original and branched histories, active branch and
  fork provenance survive reload without duplicate messages.
