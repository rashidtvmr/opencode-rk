## User-observable outcome

A deterministic release-feature-accounting validator proves every required
V2 feature is accounted for in the release ledger without converting local
evidence into controller acceptance. Given a read-only repository snapshot
(canonical plan, requirements, source reconciliation, backlog exhaustion
ledger, controller statuses), it emits machine-verifiable pass/fail plus a
concrete missing/misclassified-feature fixture on failure. It adds one
distinct release guarantee and duplicates no existing check.

## Observable contract

- Proposed validator entrypoint: `python3 tools/check_release_accounting.py --snapshot <dir> --out <report.json>` (new additive file; this card defines the contract, implementer ships the file).
- Inputs (read-only): requirements/user-requirements.json, ralph.json, sources/disc-003-reconciliation.json + sources/disc-003-reconciliation.manifest.json, backlog exhaustion ledger output (`python3 tools/validate_backlog_exhaustion.py`), controller status set (exact revision + per-story accepted/not-accepted).
- Output `report.json`: `{"passed": bool, "missing": [ids], "misclassified": [ids], "evidence_rev": "<git rev>", "partition": "release-feature-accounting-validator"}`; stdout mirrors the JSON; exit `0` on pass, exit `2` on accounting failure, exit `1` on tool/usage error.
- Pass condition: every mandatory requirement maps to at least one explicitly evidenced task edge (requirement subtraction or task-number inference alone never passes); every mapped edge cites task evidence (card path + frozen test IDs); controller-not-accepted stories are reported as not-accepted, never upgraded by local validator success.
- Deterministic: same snapshot bytes => byte-identical report; no network, no wall-clock in verdict (`evidence_rev` is the snapshot rev, informational ordering only by sorted ids).
- Suggested module boundary: `tools/check_release_accounting.py` + fixture dir `fixtures/release-accounting/`; worker ships additive files only, never edits shared `lib.rs`, `Cargo.toml`, schemas, migrations, controller `state/`.

## Failure states

- Missing feature (requirement with zero evidenced edges in snapshot): exit `2`, `passed: false`, id listed in `missing` with expected-edge hint; no partial pass.
- Misclassified feature (edge by task-number inference, requirement subtraction, or empty behavior-surface membership): exit `2`, id listed in `misclassified` with reason `inference-without-evidence`.
- Local-pass presented as acceptance (fixture where validator inputs pass but controller status is not accepted): validator still reports `passed` for accounting only and never emits an acceptance grant; output contains no `"accepted": true` grant for any story.
- DISC-001/DISC-010 duplication (inputs contain only pin/coverage evidence with no release ledger): exit `2` with reason `duplicate-of-existing-owner`, naming DISC-001 or DISC-010.
- Tool error (unreadable snapshot, malformed JSON, unknown flag): exit `1`, no report written; never exit `0` on error.

## Resource bounds

- Read-only: opens snapshot files read-only; writes only `<out>` report path; never mutates the user OpenCode database, never runs host-destructive commands; tests use disposable fixture dirs only.
- Bounded: input file count capped (default 256 files, 8 MiB total); report capped (default 64 KiB, truncation lists overflow count, never silent drop of fail entries); single process, no threads, no network, no retained output beyond the report.
- Owner/cancel path: caller owns process lifetime; `--timeout` flag (default 60s) aborts with exit `1`; no detached task, no background thread.
