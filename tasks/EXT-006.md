## User-observable outcome

Permission-scoped native plugin execution for one caller-owned scope at a
time: a registered native plugin (EXT-001 id) may invoke only the
capabilities named in its validated manifest (EXT-005), and every invocation
passes through the trusted permission broker before any effect. Deny leaves
zero side effects. No JavaScript host is started, no external module is
imported, no executable plugin callback runs outside the broker, no
filesystem/network access escapes the grant. Hook mutation semantics
(EXT-008), skill/command internals, UI presentation, reload/watch, and
external activation are explicitly out of scope.

## Observable contract

- `Capability = String` (validated charset per EXT-005; 1..=64 chars).
- `PluginGrant { plugin: PluginId, capabilities: Vec<Capability> }`: the
  validated manifest capabilities bound to one EXT-001 registry id. Binding
  is explicit: `bind(plugin_id, manifest) -> PluginGrant` revalidates the
  manifest and snapshots its capability list (later manifest edits do not
  retro-apply).
- `EffectRequest { capability: String, op: String, args: Vec<u8> }`: `op`
  1..=64 chars same charset; `args` bounded (`MAX_ARGS_BYTES: usize = 4096`).
- `EffectOutcome { applied: bool, bytes_out: Vec<u8> }`: native in-memory
  effects only (counter/flag/map writes inside the caller-provided
  `EffectSink`); `bytes_out.len() <= MAX_RESULT_BYTES (4096)`.
- `execute(grant, req, broker, sink, cancel) -> Result<EffectOutcome, ExecError>`:
  1. capability membership: `req.capability` in `grant.capabilities`, else
     `Err(ExecError::UnknownCapability)`;
  2. op validation, else `Err(ExecError::InvalidOp)`;
  3. args length check, else `Err(ExecError::TooLarge)`;
  4. cancel pre-check, else `Err(ExecError::Cancelled)`;
  5. broker assertion `broker.assert(req)`: deny => `Err(ExecError::Denied)`
     with zero sink mutation;
  6. on allow, apply the single bounded in-memory effect to `sink`.
- `broker` is a caller-supplied `&dyn PermissionBroker` with
  `assert(&self, req: &EffectRequest) -> bool`; no default-allow impl ships.
- `sink` is a caller-owned `EffectSink` (bounded in-memory map:
  `MAX_SINK_ENTRIES: usize = 256`, `MAX_SINK_BYTES: u64 = 65536`); overflow
  => `Err(ExecError::Overflow)` with no partial write.
- Deterministic: same grant/req/broker answers => identical outcome. No
  wall-clock in ordering or verdicts.
- Suggested module boundary: new pure module `crates/ext/src/scoped_exec.rs`
  (crate `opencode-rk-ext`); worker ships additive fragment only, never edits
  shared `lib.rs`, `Cargo.toml`, schemas, migrations. Independent test owner:
  `crates/ext/tests/plugin_scoped_exec.rs`.
- Explicitly excluded: external JS/TS host, dynamic import, executable plugin
  callbacks outside the broker, hook mutation/failure (EXT-008), skill/command
  internals, UI presentation, reload/watch, filesystem, network, subprocess,
  persistence, environment lookup, credentials/secrets, HTTP routes,
  background work, new dependencies.

## Failure states

- Unknown capability (not in grant snapshot): `Err(UnknownCapability)`; broker
  never consulted, sink untouched (assert sink byte-identical).
- Invalid op (empty, too long, bad charset): `Err(InvalidOp)`; sink untouched.
- Oversize args (`args.len() > MAX_ARGS_BYTES`):
  `Err(TooLarge)`; sink untouched.
- Cancel set before broker check: `Err(Cancelled)` promptly; sink untouched.
- Broker deny: `Err(Denied)`; sink provably untouched (deny asserts absence of
  side effects, not merely an error string, per TDD.md/PLAN.md 6).
- Sink overflow (entries or bytes cap): `Err(Overflow)`; no partial write,
  pre-existing entries unchanged.
- Grant binding failure (bad manifest per EXT-005 rules):
  `Err(InvalidGrant)`; no grant issued.
- Stale grant (plugin id removed from EXT-001 registry): caller drops the
  grant; `execute` with a caller-marked-revoked grant => `Err(Revoked)`;
  revocation is caller-driven (no background watcher).
- Secret safety: args/outcome bytes are opaque bounded blobs, never logged;
  no bodies/credentials retained beyond the call. No SQLite/OpenCode DB
  writes. Tests use disposable in-memory broker/sink only.

## Resource bounds

- Byte caps: `MAX_ARGS_BYTES = 4096`, `MAX_RESULT_BYTES = 4096`,
  `MAX_SINK_BYTES = 65536` bound retained/output bytes; args copied at most
  once; no unbounded retained output.
- Count caps: grant capabilities `<= 16` (EXT-005); sink entries `<= 256`;
  cap-checked before insert; no unbounded queue of pending effects.
- Owner/cancel path: caller owns grant, broker, sink, and `AtomicBool`
  cancel; `execute` is synchronous, takes `&` refs, spawns no thread;
  cancel checked before broker call and before sink write; no detached task.
- Zero hidden cost: no registry, no threads, no watchers, no host process;
  idle cost is the caller-owned structs only.

## Test obligations (frozen)

- EXT-006-T01 (happy path): grant with caps `["read","write"]`; allow-all
  broker; `execute` op under `"read"` with 10-byte args => `Ok`, `applied`,
  sink contains exactly one entry with matching bytes; same call twice =>
  identical outcomes.
- EXT-006-T02 (capability gate): request cap `"admin"` not in grant =>
  `assert_eq!(err, UnknownCapability)`; counting broker shows zero broker
  calls; sink byte-identical to before. Empty/bad op => `Err(InvalidOp)`,
  sink unchanged.
- EXT-006-T03 (broker deny, no side effects): grant includes `"write"`;
  deny-all broker; `execute` => `assert_eq!(err, Denied)`; sink empty and
  sink hash identical to pre-call; broker saw exactly one assertion.
- EXT-006-T04 (bounds + cancel + revoke): 4097-byte args => `Err(TooLarge)`;
  fill sink to `MAX_SINK_ENTRIES` then one more => `Err(Overflow)` with prior
  entries unchanged; pre-set cancel => `Err(Cancelled)` with zero broker
  calls; revoked grant => `Err(Revoked)` with sink unchanged.
- EXT-006-T05 (grant binding + safety): bind with bad manifest (dup caps) =>
  `Err(InvalidGrant)`; grant snapshot frozen at bind (mutating source vec
  after bind changes nothing); full matrix runs with no files outside the
  disposable test dir, no DB writes, no child process; captured logs contain
  zero args bytes and zero credential-like bytes.
