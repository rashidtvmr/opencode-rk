# WEB-011 - Attachments, screenshots and local Library

Status: NOT STARTED. Kind: product. Runtime optional: False.
Mandatory for full declared release: yes.
Requirements: REQ-040.
Dependencies: V2 payload/blob/message-parts storage; provider attachment adapter.
Test obligations: WEB-011-T01, WEB-011-T02, WEB-011-T03, WEB-011-T04, WEB-011-T05.

## User-observable outcome

Users can attach real files/images/screenshots by picker, paste, drag/drop or Library
reference, preview them beside the conversation, and send them through a native
provider attachment adapter.

## Observable contract and tests

- **WEB-011-T01 — ingest/send:** an allowed file/image is stored once through the
  bounded blob/multipart path, appears as a composer chip and reaches the provider as
  a real attachment reference.
- **WEB-011-T02 — rejection:** oversize, unsupported, unavailable or unsafe attachment
  inputs fail with actionable errors and never silently degrade to fake text content.
- **WEB-011-T03 — accessible picker/preview:** upload/drop/library controls, attachment
  removal and preview are keyboard/screen-reader operable with text alternatives.
- **WEB-011-T04 — resource lifecycle:** upload size/count, preview memory and retained
  blobs are bounded; abort/removal cleans temporary resources without deleting shared
  referenced content.
- **WEB-011-T05 — Library/reload fidelity:** attach-by-reference and source metadata
  survive reload; deduplicated blobs remain resolvable while referenced.
