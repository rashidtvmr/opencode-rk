## User-observable outcome

A deterministic strict-TDD independent-verification release validator proves
the candidate shipped with frozen RED/GREEN proof and independent rerun before
release assurance may claim the TDD slice. Given a read-only candidate
revision (frozen test manifests, independent verification receipts,
security/resource gate outputs), it emits pass/fail with an attributable
failing fixture on any missing RED/GREEN proof, mutated frozen evidence, or
unverified release state. It duplicates neither AUTO-002/AUTO-005 pipeline
ownership nor the REL-003 safety/resource release guarantee.

## Observable contract

- Proposed validator entrypoint: `python3 tools/check_release_tdd.py --revision <rev> --manifest <frozen.json> --receipts <dir> --gates <dir> --out <report.json>` (new additive file; this card defines the contract, implementer ships the file).
- Inputs (read-only): frozen test manifest (test file hashes + command manifest per TDD.md section 4), independent verifier receipts (exact commands, exit codes, test/log hashes, revision pinned), security/resource gate outputs, candidate revision id.
- Output `report.json`: `{"passed": bool, "checks": {"red_proof": pass|fail, "frozen_intact": pass|fail, "green_on_frozen": pass|fail, "verifier_rerun": pass|fail}, "failing_fixture": "<path or null>", "evidence_rev": "<rev>", "partition": "strict-tdd-independent-verification-validator"}`; stdout mirrors JSON; exit `0` pass, `2` assurance failure, `1` tool error.
- Pass condition (all four): red_proof (RED compiled and failed for missing behavior per manifest), frozen_intact (on-disk test bytes hash-equal frozen), green_on_frozen (GREEN ran unedited frozen suite on exact revision), verifier_rerun (independent rerun on exact revision matched gate pass; worker self-report never counts).
- Deterministic: same inputs => byte-identical report; no network, no wall-clock in verdict.
- Suggested module boundary: `tools/check_release_tdd.py` + fixture dir `fixtures/release-tdd/`; worker ships additive files only, never edits shared `lib.rs`, `Cargo.toml`, schemas, migrations, controller `state/`, verifier config.

## Failure states

- Missing RED proof (no compiling RED failing for missing behavior): exit `2`, `checks.red_proof: fail`, `failing_fixture` points at the empty/missing RED fixture; never pass on import-error-only failure.
- Mutated frozen evidence (on-disk hash != frozen): exit `2`, `checks.frozen_intact: fail`, fixture is the diff receipt (one-byte mutation case included).
- GREEN on edited suite or wrong revision: exit `2`, `checks.green_on_frozen: fail`; verifier revision != integrated revision also fails `verifier_rerun`.
- No independent rerun (only worker self-report / `passes:true`): exit `2`, `checks.verifier_rerun: fail` with reason `self-report-not-evidence`.
- Tool error (unreadable manifest, malformed receipts, unknown flag): exit `1`, no report written; blocked pipeline (missing credentials, isolation failure) records blocker via exit `1` reason `blocked-pending-authority`, never forced pass.

## Resource bounds

- Read-only: opens manifest/receipts/gates read-only; writes only `<out>` report; never mutates the user OpenCode database, never runs host-destructive commands; tests use disposable fixture dirs only.
- Bounded: inputs capped (default 256 files, 8 MiB total); report capped (default 64 KiB); single process, no threads, no network, no retained output beyond the report.
- Owner/cancel path: caller owns process lifetime; `--timeout` (default 60s) aborts with exit `1`; no detached task, no background thread.
