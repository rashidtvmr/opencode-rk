Implementation and acceptance

Outcome and evidence boundary

The strongest recommendation is to treat the upstream component tree, presentation state, and renderer behavior as one contract. Reusing native OpenTUI is a valuable foundation, but it does not automatically port the application-specific layout, Markdown composition, interaction controllers, or session projections.

3. Keep layout ownership explicit

Each component should have a short contract containing: parent-owned outer rectangle, component-owned padding, minimum/preferred/maximum size, shrink/grow behavior, overflow policy, layer/z-order, focus eligibility, and semantic color roles. Copy the upstream numbers and predicates before attempting an abstraction.

For example, session route owns horizontal inset 1 below terminal width 44 and 2 otherwise; Prompt owns its separate inner inset; message cards own their own split border and interior padding. The right sidebar is 42 cells; the left tab rail merely defaults to the same width and is independently resizable. The ordinary prompt's metadata and bottom rail are distinct rows and use different fitting algorithms. A shared padding = 2 at every nested container would multiply spacing and reproduce the user's present placement problem.

Do not replace cell arithmetic with equal percentage columns. Do not normalize the source's different width domains: metadata uses terminal width, inline diff uses content width, and the dedicated diff viewer uses patch-pane width. Port each predicate faithfully and then test its assembled geometry. The user may approve deliberate fixes later; record them as differences instead of silently calling them exact parity. R03, R05

Keep optional space even where source does: the one-row area above the prompt for history/jump-to-latest exists when empty. Preserve the composer's separate half-block bottom lip and status rail. Freeze text and clipping bounds before painting; model/provider labels must not push the context rail into a different row because a generic container was allowed to wrap.

4. State model and event flow

A reusable Rust view model should distinguish durable data from local presentation state. Suggested concepts are SessionView, PromptDraft, TabPresentation, TranscriptProjection, RightPane, BottomSurface, FocusTarget, and AnimationClock. These are illustrative types, not a replacement wire protocol.

Session data should carry real session identity, parent/family links, execution status, unread/viewed timestamps, outcome, latest usable assistant usage, and session cost. Message parts need stable IDs and typed streaming/running/completed/error payloads. Code-mode child calls are metadata entries; subagents are child sessions. Tool completion and child-session completion may occur at different times.

Presentation state owns tab order and history, per-session draft and tracked attachments, selected agent/model/variant, expansion IDs, semantic scroll anchor, active dock, hovered/pressed item, focused pane, interrupt arming deadline, and dialog state. Do not clear all of it when new text arrives. Preserve native node identity for in-place streaming updates; restore saved presentation state when the source intentionally remounts a session frame keyed by session ID. Native object identity need not survive switching between different session frames.

Use a deterministic update path: receive an event or user action, update the appropriate model, derive visible projection, update only affected scene resources, measure, then paint. Side effects should be emitted once by the controller, not from a widget's paint function. This supports a test that sends an Enter action and checks both the resulting frame and exactly one outgoing prompt command. The same separation makes tab changes, queue-to-steer transitions, and asynchronous paste races reproducible. R04, R06

Respect bottom-surface priority from source: auxiliary dock, permission, form, unavailable location, normal prompt. A child session forces the subagent dock except when a form is present. Prompt focus follows those branches; having the correct visible box while keystrokes still go to the hidden textarea is a failed port.

6. A differential parity harness

Run the same semantic fixture through the selected upstream production components and the Rust production components. Use an offline in-process service fixture or replayed typed events. No live model credentials, user sessions, or real tool execution are needed to verify placement and interaction.

fixtures.json specifies inputs, actions, expected rules and checkpoints. It is a test specification, not a set of captured golden frames. Capture the upstream goldens first using the original renderer. A screenshot drawn by an AI, a recreated mock widget, or an expected frame generated by the same Rust code under test is not an independent oracle.

Export a portable frame representation rather than serializing native memory. A proposed record contains dimensions; one record per cell with cluster text, display width/continuation status, foreground/background and terminal-default flags, text attributes and hyperlink identity; cursor cell/shape/blink/visibility; clipping and component bounds; focus target; scroll anchor; and emitted semantic actions. Native handles and pointers must not appear in the portable format. Normalize fixture time/IDs and protocol-internal details only where the contract explicitly allows it.

Comparison layers:

  1. Pure behavior: upstream-derived allocation examples, context arithmetic, grouping and state priorities. These isolate defects but do not alone prove layout.
  2. Production component frames: every glyph, cell coordinate, RGB/alpha/default color, border, attribute, gutter and clipping boundary. Require zero unexplained differences.
  3. Event traces: actual input sequence, focus changes, scroll/selection behavior, one emitted action with the expected semantic arguments. Verify disabled commands stay disabled.
  4. Temporal frames: ManualClock checkpoints for spinner, scanner, pulse, marquee, retry and double-Escape. Test animation-off separately.
  5. Installed-terminal journey: same terminal emulator, font/size, zoom, theme, dimensions and fixtures. Compare captures for half-block seams, cursor placement, image support and real input parsing.

Text-only snapshots cannot detect the wrong sidebar gray or an invisible cursor. Pixel-only snapshots cannot establish command dispatch or unread acknowledgement. Pair them where those aspects matter.

Test robustness rules from upstream

Set width and height explicitly. Enable Kitty keyboard mode in modified-key fixtures. Await the signal that makes content ready; a quiet frame can still be waiting on asynchronous tree-sitter highlighting. Await highlighting completion before capturing Markdown/code. Inject clocks; avoid real five-second waits for interrupt timeout. Destroy timers/renderers before deleting temporary fixtures. Use counts of mounted rows or rendered lines for bounded-work checks rather than noisy wall-clock speed limits. Run package tests from packages/tui, never the repository root. These rules come from the source repository's TUI testing skill. R08

Prove the tests can fail

Run small negative controls in an isolated candidate: shift a parent inset by one cell; change a strict sidebar >120 predicate to >=120; swap sidebar and prompt backgrounds; let Enter reach two handlers; make a stale highlight update a destroyed block. Each should fail its relevant gate. Revert the mutation immediately. This is more useful than hundreds of tests that duplicate implementation formulas and all accept the same mistake.

Authoritative baseline: anomalyco/opencode, project-selected commit 450e7b92412c780a7b5a75226bb8d49aaca24e22 (2026-10-25, package version 2.1.4, OpenTUI 0.6.8). 1. Important version distinction

The project-pinned v2 default right sidebar consists of Context → Limit → MCP → Todo, followed by a pinned footer. These are independent built-in contributions to sidebar.content and sidebar.footer. Each contribution can return no content, so the visible set depends on state. The title above them belongs to the sidebar shell itself. There is no built-in LSP list or changed-file list in this pinned sidebar. Do not copy a v1 screenshot and call it a reproduction of the project-pinned v2 UI. Additional sections can be useful extensions, but keep them out of an exact-baseline fixture unless the target OpenCode installation has an additional plugin. The built-in diff viewer is a separate panel, not an always-present changed-files sidebar. L01, L02

The sidebar is not the left vertical tab rail. They happen to share the default width of 42 columns. The left rail is resizable and can become a compact 5-column rail; the right information sidebar remains 42 columns. L03, L04, L05

2. Whole-screen layout contract

All dimensions here are terminal cells, not browser CSS pixels. Any Rust bridge must make measurement, clipping, foreground/background composition, and pointer coordinates use the same terminal-cell coordinate system.

Root tree

The root is a column exactly the terminal width and height, painted theme.background.base. Its main child is a growing row with minHeight=0, containing an optional vertical tab rail and the remaining route area. That route area is a growing column with minWidth=0. If tabs are horizontal, their one-row strip appears above the route. The route is Home, SessionFrame, or plugin content. App slots and overlays are layered after route content; the optional development bar is outside the main row. Toast/loading/reconnection/migration layers are root children. This hierarchy matters: putting tabs, sidebar, and prompt into one undifferentiated horizontal box produces incorrect shrink behavior. L04

The normal session frame is a row with a growing session pane and at most one right pane. Right-pane selection priority is: active plugin panel; manually opened sidebar; selected terminal; auto-visible sidebar. Opening a plugin panel clears manual sidebar state and the terminal selection. Selecting a terminal closes a plugin panel and manual sidebar state. Switching sessions closes a panel that belongs to another session. L04, L05

Information sidebar when narrow

When manually opened at remaining width ≤120, it is an absolute overlay, covering the frame with a black backdrop of alpha 70/255 and aligning the 42-column sidebar to the right. This overlay does not reserve 42 columns from the conversation. Escape or Ctrl+C closes this narrow sidebar through a higher-priority key layer. Subagent sessions (a session with parentID) never show this information sidebar. The source does not define a custom reduced-width sidebar below 42 columns; capture the baseline renderer at extreme widths instead of inventing one. L05, L06

Plugin panel focus and full screen

Below its 108-column split threshold, a plugin panel becomes full screen; both horizontal and vertical session tabs are hidden. The prospective width calculation still accounts for a configured vertical rail so transitions do not oscillate. The conversation pane remains mounted but is invisible and noninteractive; a full-screen panel uses all currently available frame width. Pane focus is explicit. When the right pane has focus, the session pane gets an absolute click guard; mouse-wheel events inside the transcript viewport are forwarded to the transcript, and a click returns focus without accidentally approving a permission underneath. Default focus bindings are leader+Left and leader+Right. L04, L05, L07

Resize interaction

Resize handles have a 2-column hit target, one visible highlighted column, zIndex=10, and full parent height. The highlight appears on hover or drag using background.raised.high. Left rail sizing uses pointer x+1; right-pane sizing uses terminalWidth-x-1. Drag updates preferred size locally, and persisted size changes once at release. A second boundary click within 300 ms resets to default. Parent-level drag/release handlers keep resizing active outside the handle. Do not persist on every mouse move or change the hit target to a 1-column decorative line. L04, L05, L08

3. Main conversation geometry and scrolling

Inside SessionFrame the session route has a growing transcript area, an always-reserved one-row line below it, then a nonshrinking composer region, then the route's one-row bottom padding. The reserved line displays right-aligned history-loading text or a hoverable “Jump to latest ↓” action; it exists even when empty. Removing that empty row moves the prompt and breaks parity. The jump action has 1 column of left padding and changes its secondary-action text token on hover. L06

The scrollbox is sticky to the bottom except during explicit message navigation/navigation slack. Its viewport adds 1 column right padding when the scrollbar is enabled; the vertical scrollbar also has 1 column left padding. The track background is a decreased raised surface and foreground is border.base. Each session row's outer wrapper has marginTop=1. The sidebar scrolls independently, and the composer never scrolls with messages. Scroll acceleration is either the OpenTUI macOS accelerator when explicitly configured, a configured constant speed, or the default constant speed 3. L06, L09

Scroll restoration is anchored to a message/group target and its screen Y position, not a raw absolute scroll offset. Parent and subagent anchors are separate even though they share a root session tab. Expansion state is per-session and per-group. Closing a root tab clears anchors and expanded groups for its family. These are layout semantics, not cosmetic extras: recreating only text at the bottom will lose the user's reading position after switching tabs or resizing. L10

One source caveat for a faithful port: the render-context content width subtracts 4 from the measured session pane even though terminal widths below 44 use physical padding of 1 on each side. Preserve the upstream behavior in parity fixtures first; any intentional fix is a separately recorded divergence. L06

4. Home screen

Home uses the same horizontal inset rule, centered horizontal alignment, a growing empty spacer, an extra shrinking 3-row spacer, the real Logo component, a fixed 1-row gap, update notification, a prompt wrapper (width=100%, maxWidth=75, top padding 1, zIndex=1000), and a second growing spacer. The footer is a separate full-width, nonshrinking child. The result is a vertically balanced composition, not a prompt pinned at a hard-coded Y coordinate. L11

Global MCP forms can appear while on Home: the prompt is disabled and the form is an absolute overlay with left/right inset 2, bottom offset 1, zIndex=2000. Update notification layout is constrained to the measured logo width, uses hover action coloring, and has behavior for available/installed/remote updates. L11

The default home footer is hidden below height 14 or width 44. It has left/right padding 2, horizontal gap 2, and top/bottom padding 1 except at heights 14–15 where those vertical paddings are zero. MCP status and plugin failure status are left; a growing spacer pushes the version to the right. /mcps and version appear at width ≥64; /plugins appears at width ≥80. MCP failure count wins over connected count. Each status block opens its matching picker. The footer also has the additive home.footer.status extension slot. L12

5. Horizontal session tabs

Width allocation

The strip is exactly one row, nonshrinking, horizontally arranged, zIndex=1. An idle plus affordance reserves 3 columns and renders a plus with one space on either side. When on a new-session page that control promotes into one active “New session” tab; it is not duplicated as a separate plus and draft tab. L13

The layout model uses preferred width 22, max width 32, and minimum inactive width 8. It maintains a sticky window of visible tabs around the active tab. Overflow labels reserve digits(count)+2 cells for an arrow, count, and gap. Roomy layouts split width equally up to max 32, with integer remainder distributed from the first visible tab. Under pressure the active tab receives the remaining width after equally sized inactive tabs. A single tab caps at 32 rather than stretching across the terminal. L14

Label, status, and colors

The indicator region reserves max(2, digits(totalTabs))+1 cells, including its 1-cell right pad, so replacing an ordinal with a spinner does not move titles. Title resting width is max(1,tabWidth-1-numberWidth), shortened by 2 more cells on hover to reveal the close control. Titles are grapheme-aware, use display-cell width, and fade over their final 4 cells when truncated; they do not simply append an ellipsis. Selected/dragged titles are bold. Selected background blends toward a decreased raised surface; hovered inactive tabs use the primary action hovered surface. L13, L16

The status-mode priority is: permission !; question ?; animated busy spinner; plus; unread marker; otherwise an empty indicator. In numbers mode, the ordinal remains visible even when busy or blocked. Busy spinning is suppressed when attention is required. Defaults are the dots spinner at 80 ms and small bullet unread marker; alternate styles exist in the component. Error unread uses the error text token; attention uses the accent hue. A busy child or non-synthetic queued user work can make the root tab busy; a child permission/question can make the root attention indicator appear. L16, L10

Long title hover starts a marquee after 600 ms, advances every 80 ms, runs one cycle, then returns to offset zero. Leaving resets it; moving between descendants has a deferred hover-clear to avoid flicker. Membership changes animate surviving tab widths from current values and grow new tabs from zero with a 0.1s visual-duration spring; terminal resizes normally jump to final widths. L16, L13

Mouse behavior

Left press then release selects; middle-click closes without first selecting; right-click opens a context menu. Hover reveals a close glyph one cell in from the right edge. 7. Navigation state and persistence

Default tabs config is mode=auto, scope=cwd, layout=horizontal, indicators=status; auto is disabled in the HERDR_ENV=1 terminal environment. Tabs render only if enabled, at least one real session is open, and the route is not a plugin route. Thus initial fresh Home does not necessarily display a plus rail despite Home having a draft state. L04, L21

Persisted tabs have global and per-working-directory buckets keyed by session ID. Subagent routes normalize to the root tab, so opening a subagent is not automatically opening a separate tab. Titles prefer live session data, then persisted fallback, then generated title fallback. The provider separately retains session data, per-session scroll anchors, expanded groups, recent closed tabs, selection history, and background prompt pulse counts. Recent-closed and navigation history are in memory; tab order and metadata persist. L10

Unread is derived from server time.idle > time.viewed (or no viewed time), not a local boolean cleared on click. Root outcome failed yields error unread. A selected session is acknowledged viewed only once focus has been confirmed. Failures retry with exponential delay starting 250 ms and capped 5s. Family attention is permission first, then form/question; selecting does not itself clear a pending question or permission. Background subagent completion alone does not mark the root unread. L10

Closing the active tab prefers the previously visited still-open tab from navigation history; absent that, it chooses the right neighbor, then left, then Home. Reopen restores the original index, clamped to current list length. The history limit is 100. Closing a background tab should not steal focus. Deleting a session also removes it from reopen history. Async tab admission is cancellation-aware so a slow persisted write cannot resurrect a just-closed tab. Shared-store updates must not reopen a tab solely because another client still views it. L10, L14

Defaults to reproduce: Ctrl+Tab/Alt+Down next; Ctrl+Shift+Tab/Alt+Up previous; Alt+Shift+Down/Up next/previous unread-or-attention; leader+W close; Ctrl+Shift+T reopen; leader+1…0 and Ctrl+1…0 direct select; leader+B sidebar. 2. Preserve token provenance in Rust

The TypeScript resolver indexes the identity of each RGBA swatch with its hue name and step. References preserve that identity. Hue aliases clone their underlying scale so neutral 600 and gray 600 retain distinct provenance even when their RGB values coincide. increase/decrease truncate finite step counts, clamp within 100…900, and leave untracked literal colors unchanged. A freshly constructed RGBA with the same RGB as a token is deliberately untracked. T03

This is a concrete Rust bridge risk: a flat map of strings to [u8;4] loses the ability to implement the source operation faithfully. Store a resolved color together with optional {hue,step} provenance, or use stable color handles. Do not recover provenance by reverse-searching RGB values: default light neutral 800 and 900 are both white, and tests explicitly cover equal-valued adjacent swatches. The action state precedence is disabled → pressed → focused → selected → hovered → base, using the first true state. Missing states expand to that variant's base. Thus a pressed+hovered action can resolve to transparent if pressed was not given a separate color; inventing a darker pressed shade changes the theme contract. Text feedback roles (error/warning/success/info) are separate from formfield/action roles. T06

Theme documents deep-merge base with the requested mode, expand structural state defaults, then resolve token references. Missing/circular references and incomplete native themes fail validation; they are not silently completed from the default theme. A dialog surface is an absolute view, not a recursive “darken again” operation. Its overridden token references resolve within the dialog context. A dialog action override's base supplies omitted states before the outer action's explicit states, an important precedence rule. Surface wrappers remain reactive and retain stable identity during theme changes. T03, T05, T07

5. Theme loading, switching, and system fallback

Default selection is opencode. Mode comes from explicit dark/light lock, otherwise renderer mode, otherwise startup mode. Theme mode and theme name are distinct settings. One-mode themes render their available mode while preserving the user's requested mode preference; selecting a dual-mode theme later reuses that preference. Unknown names render opencode. An invalid non-default theme emits a theme error, activates opencode, and keeps the application running. T12

Source priority is built-ins < discovered custom files < generated system theme. Custom themes/*.json files are sorted within each directory; later directory discoveries replace same-named themes. V1 objects containing theme are migrated; native documents are parsed and validated. Parse caches key on source-object identity, so a replacement source is revalidated. Theme picker movement previews immediately and calls the same configuration-persisting setter as confirmation. Cancellation restores and persists the initial selection; confirmation keeps the chosen selection. T13

For system theme, first paint uses cached usable terminal colors or fallback opencode. Palette queries begin only after first paint, request 16 colors, and avoid concurrent probes. Default foreground/background are preferred, with slots 7/0 as data fallback. Mode inference uses the actual default background only, weighted luminance 0.299r+0.587g+0.114b >0.5; slot 0 is not used to infer mode. System background retains alpha 0, while derived raised grays and diff tints use palette colors. Refresh reacts to renderer theme events and recognized terminal notifications; mode locks ignore automatic mode changes. SIGUSR2 refresh waits 250 ms / 1000 ms and reloads custom themes on the latter attempt. T12, T14

Theme changes update renderer background and recreate syntax style. Old native syntax resources are retained until the renderer becomes idle before destruction. A Rust bridge must avoid freeing a style still referenced by a queued frame. This is an existing lifecycle requirement, not an optional visual enhancement. T12

1. Transcript projection and grouping

Sources: row projection, grouping rules, group rendering, session defaults.

Observed production rules

  • The default detail level is medium. The session defaults are thinking: hide, Markdown rendered, diff wrapping word, and related-tool grouping enabled unless session.grouping equals none.
  • Transcript rows are not equivalent to chat messages. The row union includes a complete non-assistant message, an assistant part reference, an assistant footer, a queued-compaction divider, a debug turn-usage row, and recursive groups. Assistant text, reasoning, and tools therefore occupy separate stable rows.
  • Group kinds are reasoning, exploration, instructions, and low-verbosity activity.
  • Consecutive reasoning parts group. Exploration includes exactly read, glob, grep, webfetch, and websearch in the grouping classifier. Questions remain standalone. Instruction notices can group by distinct loaded file paths.
  • Low verbosity wraps runs of non-text parts in an activity summary, including nested reasoning/exploration groups. It counts finished work; before anything finishes, it shows a stable status such as “Running command…” or “Preparing code…”. Code-mode execution counts its completed nested calls, with a fallback to counting the execute tool itself when there are none. Permission-blocked parts are excluded from the activity summary and remain visible below the collapsed group.
  • High verbosity opens exploration and instruction groups by default. It does not automatically expand reasoning. An explicitly saved group expansion overrides the default.
  • Group labels change from active to completed: exploration summarizes reads, searches, and fetches; reasoning uses the latest available summary title, completed thought count, and summed duration. Running summaries use spinners. Completed disclosure icons remain clickable even when a tool inside failed.
  • The group disclosure color changes on hover. Text selection takes precedence: a mouse-up with selected text must not expand/collapse a group.
  • Every outer SessionRowView has marginTop=1 and flexShrink=0. This is a row-level rhythm, not a blank row blindly inserted before every nested tool. Expanded low activity uses gap=1, marginTop=1; expanded instruction items remain adjacent to the summary and to each other.
  • Stable row keys, group IDs, and part anchors preserve expansion and scroll position when older history is prepended, streaming updates arrive, or a connection resynchronizes. A page boundary that lands within a group triggers more backfill until the group's beginning is known; otherwise its ID and summary would change after expansion.

Rust port guidance

Use a typed transcript projection layer separate from widgets: MessageStore -> TranscriptReducer -> Vec<TranscriptRow>. Identify a tool/part by (message_id, part_id), not part_id alone. Persist group disclosure in session-local UI state. The renderer needs an anchor map from part/group identity to current geometry, including offscreen/mounted behavior. Preserve the visible anchor offset when expansion, historical backfill, or wrapping changes height.

Do not update all rows by position after inserting history. That loses local hover/expanded state and remounts Markdown. Do not hide a permission-requesting tool inside a collapsed summary.

6. Subagent behavior and code-mode execution

Sources: transcript subagents/execute, execute details, background completion notices.

Subagents

A subagent is active if its tool state is running or its child session is running. Ending the initial tool call therefore does not necessarily end its spinner/status. A new running subagent uses a spinner. Continuation calls use ↳ and a Continue subagent label; they deliberately do not use that new-subagent spinner path. New labels include title-cased agent type and description. A model suffix appears only for an explicit model override, resolves provider/model to a display name, and renders #variant as a parenthetical variant. Unknown models retain the supplied reference.

The Background badge is true only when the tool has completed while metadata status is still running. A foreground running tool must not carry that badge. Clicking navigates to the child session when its ID is available. This is an indeterminate activity indicator; no transcript percentage calculation exists here. Inventing numeric progress would fail exact parity.

Later synthetic completion notices distinguish finished, failed, and cancelled work. Finished uses info color, failed error, cancelled warning; child-session hover uses base text. Descriptions are width-truncated. Shell completion text collapses whitespace. Child-session click remains available and respects text selection.

Execute / custom script

The source explicitly says execute child calls stream through metadata, not a child session. Preserve metadata.toolCalls as an ordered live collection of tool, running/completed/error status, and input. Invalid child entries are filtered at the boundary.

The root execute row always has click and error-click actions opening details. Its spinner covers streaming or running. Runtime failure can be represented by metadata.error === true even when the transport tool completed; use both. The child rows have left padding 3, a fixed 2-cell icon (› or error cross), a one-line truncated compact argument label, hover base text, and independent expansion. Expanded input is under a left border with padding 1. Expanding a child does not open a subagent session.

Inline output preview appears only for runtime errors and is capped at 4 lines / 4 * max(20, content_width - 6) characters. The first line has an arrow; following lines preserve aligned indentation. Successful logs should not flood the main transcript.

The detail dialog is centered and xlarge. Its maximum body height is max(3, floor(terminal_height * 0.7) - 6). It uses one scrollable body for Code and Output, a high raised background, hidden scrollbar, top/bottom padding 1, and a shared gutter width. Code is TypeScript; valid JSON output is highlighted as JSON; trailing Warnings/Logs text is rendered below at the same content column. Source and output line-number gutters align even when they have different line counts, and wrapped continuation rows are unnumbered.

It distinguishes receiving code, running, completed, and failed with duration. Missing code/output and completed no-output have separate placeholders. Arrow/page/home/end navigation works inside the detail view. c copies code and o copies output, replacing that action label with a success-colored copied state. The dialog observes the live tool object while mounted. The entry action captures a stable tool object before a session resync can drop the original row.

7. Diffs, large files, images, and boundaries

Sources: inline diff wiring, PatchDiff, dedicated diff viewer, image previews.

Inline edit/patch view selection respects explicit unified/split. In auto mode it switches only when content width > 120. This is not terminal width, and it is not the same threshold as the dedicated diff viewer. Permission edit preview instead consults terminal width > 120. Test each route separately.

All inline diff colors are semantic: hunk-header text; added/removed/context backgrounds; added/removed sign highlight; line-number text; context/added/removed line-number backgrounds. Preserve syntax highlighting on top of the change backgrounds. Inline diff body has one additional left cell inside its block card.

PatchDiff splits hunks and reserves a shared gutter digit width across them and across split sides. Each subsequent hunk has a one-row colored header. Its gutter has one leading cell plus optional gutter padding. When supplied a scroll container and dealing with an added-file diff larger than 3,000 lines, it can use 128-line chunks, render only the viewport plus one chunk on each side, and leave exact-height placeholders offscreen. It highlights the whole file once and slices ranges into chunks so a fragment is not incorrectly parsed as an independent source file. This optimization is conditional: the inline callers shown do not pass a scroll container, so do not claim all inline patches automatically virtualize.

The dedicated diff viewer uses a different policy: its patch pane must be at least 100 cells for split view; otherwise it forces unified. File-tree width is clamped to 30–40 cells around floor(view_width/4). Full layout uses 2-cell insets; docked or narrow presentation is compact, has no file tree, and uses the raised surface. Fullscreen uses base surface. Preserve this distinction when sharing Rust diff widgets.

Image preview is controlled by session.image_preview. Inline tool previews accept data:image/ file content. User images are deduplicated before display. At most three thumbnails are visible; excess becomes a +N more tile. Thumbnail height is clamp(floor(terminal_height/4), 4, 8) and width/basis twice that height; images use cover fit and automatic protocol. Row gap is 1, padding top/bottom 1, left 3 by default or 2 for user cards, right 2. A failed thumbnail displays No preview. Left-click opens the gallery at that image and stops propagation so the enclosing card does not also activate.

9. Animation, errors, compaction, and runtime notices

Sources: spinner wrapper, spinner renderable, shimmer, compaction/errors/retry.

The standard tool spinner is the ten Braille-frame sequence in spinner-frames.ts, advancing at 80 ms. It occupies one fixed glyph cell; with a label there is one gap cell. A bare spinner cannot shrink, otherwise Yoga can round its fractional width to zero and paint it over the gap. Disabled animations show a static ellipsis glyph and the same label. Some other UI regions use specialized one-cell or subcell animations; do not globally replace them with this spinner.

The custom spinner uses the renderer clock, requests individual frames, and deliberately is not a continuously live renderable. It resets on frame/interval/autoplay changes, respects visibility/culling, and cancels its timer on destroy. A port that starts an endless timer for each historical spinner is both behaviorally and operationally wrong. Shimmer text is separately implemented with a 1,200 ms mask sweep and must preserve actual foreground/background cell composition.

Compaction is a horizontal divider with flexible top borders on either side of a padded title group. Running has an 80 ms spinner (or static fallback); failed non-cancelled has error cross/color; cancelled is muted with cancelled suffix. Completed native compaction can say Provider compaction. Usage here is the compaction request's input/cache and output/reasoning usage, not the resulting context size, which only appears on a later assistant step. Summary below uses the same rendered Markdown rules and left padding 3/top padding 1. A queued compaction is a distinct bordered divider with a diamond and queued label.

Execution errors appear at left padding 3 with error foreground. Interrupted assistant steps suppress the normal error block and append interrupted to the footer. Ordinary retries have a warning line with ceil-rounded seconds until retry time, attempt count, and actual error message; a passed deadline displays a due state. Free-limit error has a specialized reset-time notice and connect/models actions rather than the generic error. Optional debug turn-token rows are collapsed by default and show a per-step table only when enabled, so they must not be added unconditionally to the standard UI.

Long-running shell/subagent work may show a background-action shortcut hint after 3 seconds. Time it from the tool's start identity, retain it while that work remains the same, and remove it with that work; avoid flicker on metadata updates.

Native OpenTUI and Rust boundary

Scope and pins

This is a source audit, not a runtime verification of the user's Rust bridge. It identifies what that bridge must expose or reproduce; it makes no claim that a particular capability is missing from the existing implementation.

The authoritative OpenCode project snapshot is 450e7b92412c780a7b5a75226bb8d49aaca24e22. Its root catalog pins both @opentui/core and @opentui/solid to 0.6.8.P1 The public OpenTUI v0.6.8 tag resolves to commit 8d6065a3e60039d16c6ee697692dcfbc46d3c786, checked out at /tmp/opentui-selected-audit. Every OpenTUI link below uses that immutable commit.

The practical conclusion: a Rust binding to OpenTUI can reuse far more than cell drawing, because this release has a native retained scene, Yoga layout, text/editor resources, terminal rendering, and session/output management. However, binding those primitives does not automatically supply the TypeScript implementations of Markdown composition, asynchronous syntax highlighting, diff construction, scrolling policy, input dispatch, or the application widgets. Those layers need an explicit implementation owner.

2. What is genuinely native

Scene, Yoga and measurement

packages/native/include/opentui.h defines roots, boxes, plain text, sliders, arrows, editors, custom nodes, text views and images. Its style interface uses terminal display cells for numeric dimensions and 0–100 for percentages. The scene surface requires box geometry and explicitly excludes Yoga display:contents. Native scene.zig calls yogaNodeCalculateLayoutChecked; it reads computed geometry, applies translations, propagates opacity, intersects clipping rectangles with border insets, and skips nodes outside configured viewport filters. Native build configuration compiles the bundled Yoga C++ sources and the Zig/C++ bridge.N2, N3, N4, N9

This matters for exact padding and wrapping: replacing this machinery with a different flex implementation is a behavioral change even when both use the word “flex.” A faithful Rust wrapper should retain the native style vocabulary, measurement semantics, terminal-cell rounding, dirty propagation and viewport behavior, then compare geometry with upstream fixtures.

NativeRenderable binds a Yoga node to a native text-buffer view or editor view for measurement. A Rust scene can therefore ask the same native text implementation for wrapped intrinsic dimensions instead of approximating height with string length divided by width.N5

Checked resources and frame/output protocol

The checked C interface is experimental ABI version 1. Upstream explicitly requires matching headers and artifacts from the same revision. Versioned records require exact structure size/version, zero reserved fields and valid flags. Context creation captures the creating OS thread; destruction from another thread fails. Handles contain context ID, slot and generation; copying a handle does not retain it. Context destruction reports busy while required owned state remains.N1, N2, N6

Native frames are a protocol, not a single unqualified paint callback: the header describes request tickets, preparation yields, host hook records, painting and admitted output. The host must acknowledge the exact request and respect phase restrictions. TypeScript's NativeSession separately coordinates writable-stream callbacks, drain/backpressure, output tickets and presentation completion.N7, N8

Rust recommendation: generate or verify ABI layouts against this exact header; wrap handles with explicit ownership and borrowing rules; keep native mutation on its owner thread; translate every status into a meaningful error; prevent unwinding across callbacks; and make frame completion/output acknowledgement first-class. Keep this layer independent of OpenCode widgets so other Rust TUIs can reuse it.

3. What still lives above the native ABI

Markdown is a parser plus a retained composition engine

MarkdownRenderable imports Marked's lexer and creates Code, Box, Text and TextTable renderables. Options include top-level versus coalesced blocks, streaming, concealment, table layout and custom render callbacks. The incremental parser reuses matching token.raw prefixes and, by default, keeps the final two tokens unstable so an unfinished token can change type. It falls back to a complete parse on incremental failure. Matching only final Markdown output misses these transition semantics.M1, M2

OpenCode uses this high-level behavior for streamed responses. The Rust replacement needs stable block identities, incomplete fence/table/list handling, in-place updates when possible, final stream settlement, list-marker alignment, source-versus-rendered text mapping, selectable content and plugin blocks. Upstream tests explicitly assert object reuse while appending list items and preservation of the previous visible text while highlighting is pending.T1

Highlighting spans native storage and a TypeScript worker

CodeRenderable is integrated as a native text_view, but its TypeScript controller owns highlight dirtiness, content snapshot IDs, reruns, pending promises, streaming state, concealment and conversion to styled chunks. For streaming typed content with unstyled drawing disabled, updating content invalidates highlights and requests a frame without first publishing raw unstyled text. This is part of the no-flicker contract.M3

The worker imports Parser, Query, Tree and Language from web-tree-sitter; the client owns worker startup, requests, versions and lifecycle. The native text buffer does not substitute for those grammars, highlight queries, injection handling or asynchronous cancellation rules.M4, M5

Rust recommendation: a Rust Tree-sitter implementation can replace the worker, but parity requires the corresponding grammar/query assets, capture-to-theme mapping, injection behavior, offset conversions and stale-result rejection. Preserve the last valid styled frame until the next valid result is ready. Do not assume any Markdown crate plus a generic code highlighter yields identical wrapping, colors or streaming behavior.

Diffs, scroll controllers and terminal scrollback

DiffRenderable parses patches with the JavaScript diff package and composes Code, LineNumber and Text renderables. It owns logical lines, added/removed/context classification, gutters and unified/split presentation. Native primitives supply the painting substrate; the hunk model and composition are host responsibilities.D1

ScrollBoxRenderable supplies wrapper, viewport, content and scrollbars. Its TypeScript controller maps Shift-wheel to the other axis, applies acceleration, retains fractional deltas until whole cells can be scrolled, maintains sticky/manual-scroll state and performs time-based selection autoscroll. Native viewport clipping/culling complements these behaviors.S1 Separately, native SplitScrollback tracks published terminal rows and tail columns for split output. It is not the conversation list's scroll-position/anchor model.S2

Input and Solid

The stdin parser explicitly owns byte framing and protocol recognition, while KeyHandler and the renderer own dispatch. It produces key, SGR/X10 mouse, paste and terminal-response events. Renderer dispatch distinguishes capability responses from keys and routes paste bytes separately. Reimplementing only printable characters and arrow keys would leave major behavior unmatched.E1, E2

Solid creates core renderable instances, applies reactive properties, maps focus and event handlers, inserts/moves children, and cleans up removed instances. Rust need not reproduce JSX syntax or Solid itself. It must supply equivalent stable identity, update ordering, property removal, event replacement and resource cleanup semantics.F1
