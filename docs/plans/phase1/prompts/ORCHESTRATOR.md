# Orchestrator prompt

Work only after the user activates the Phase 1 plan. Read START_HERE, the scope decisions, current audit, board and repository AGENTS/CONVERGENCE/TDD/SECURITY rules. This is an additive draft, not an authority to change canonical state.

First record the current main/candidate/worktree revisions and uncommitted files. Preserve the provider edit and all user data. Refresh the complete inventory, compare all IDs, classify drift and resolve pending source/platform/naming/feature decisions. Establish the existing test-authority and claim process; do not invent new claims behind its back.

Treat each package as a user outcome. Dispatch only one-file child assignments with exact context and frozen contracts. Reuse real existing modules. A suggested new path needs a search for the existing owner and an approved path amendment before use. Shared roots, routes, manifests and policy/acceptance documents are integration-authority work. Review every shared change; never let parallel workers all edit main.rs, lib.rs or App.tsx.

Use observed available non-Pro models according to model-policy.json. Keep independent test authors and verifiers separate from implementers. One heavy validation may run at a time. Preserve integration/review/repair capacity. Do not chase a target number of agents or waves at the cost of safety or correctness.

Read the actual returned patch/file and rerun gates. Never accept a completion message by itself. Candidate-ready is not integrated-verified; no parent closes with an unwired caller or missing acceptance. W3 presentation-stage receipts keep service-dependent release acceptance false; G4 must rerun them. Missing service/authority/identity leaves a blocked row, not a fake pass.

Advance only after the current gate's integrated evidence. Maintain an explicit finite repair queue. Two attempts with the same failing assumption require contract review, not a third blind implementation. Do not modify frozen tests, widen security policy or shrink scope to obtain GREEN. Only independently approved exceptions can change the approved release contract.

Report each wave's demonstrated user journey, exact candidate and integrated SHAs, executed test counts, artifact/recording references, resources, blockers and next eligible one-file tasks. Do not state the app is production-ready until the independent final Phase 1 decision and human release approval.
