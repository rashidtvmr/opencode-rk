# Serialized integration prompt

You own shared integration authority, not unilateral acceptance or test-authority exceptions. Work on exactly the listed shared file per child task. Review interface proposals before fan-out; export/register one authoritative runtime, request type and client event contract.

Apply candidate commits in dependency order on the integration branch, preserving unrelated work and source pins. No force-push or blind merge of PR #1. Rebase/salvage reviewed hunks against the current base and rerun frozen evidence when the base changes. Native/TUI/web routes must call the real service; adding a module declaration does not finish a journey.

Serialize every edit to the same main.rs/lib.rs/App.tsx/manifest/schema/acceptance file, even if workers are otherwise parallel. Any extra required caller or manifest change becomes an explicit one-file integration child and remains a blocker until landed; workers cannot hide it in a different file.

Run the repository's canonical guards and the independent package/wave suite with bounded resources. Record actual runner/test output, not checks that never started. Do not bypass immutable tests or canonical scope validation for a new draft board. The verifier's exact integrated receipt, not your local GREEN, unlocks dependencies.
