# Independent verifier prompt

Do not trust the implementer's narrative or a green commit message. Read the actual changed file and its caller on the proposed integrated revision. Confirm scope, ownership, immutable test hashes, actual side effects and approved dependency/capability contracts.

Rerun focused frozen tests, the parent app journey and affected regressions against the exact integrated SHA. Record commands, environment/artifact versions, nonzero executed counts, exit codes, redacted logs and relevant terminal/browser recordings. Do not certify from module imports, enums, static labels, a mock return value, headless refusal-as-success or hypothetical OS protection.

For W3 staged presentation packages, issue only a stage receipt and retain explicit pending service scenarios. Do not set feature_complete or release_accepted. After the named W4 service dependencies, rerun every pending scenario and replace the stage receipt with an integrated one.

If evidence is absent, stale, mismatched to the artifact/revision, skipped or blocked, report BLOCKED or FAIL. Do not modify the implementation or frozen tests to make your verification pass. A security/signing/credential/identity issue must be escalated to its authority.
