# EXT-013 worklog

## Claim

Implement bounded safe materialization for bundled skill files: validate a relative path, create a destination once, refuse symlink targets, use exclusive creation with owner-only permissions, and never overwrite an existing artifact.

## Source evidence

- Candidate base revision: `3be4d3c7329da6870fcc979c078de4b780f6c75d`.
- `tasks/EXT-013.md`: REQ-017/REQ-027, five test obligations.
- Task evidence cites Claude Code bundled-skill extraction with one-time materialization, no-follow/exclusive creation, mode 0600, and rejection of parent traversal and absolute paths.
- `crates/tools/src/skill_gate.rs` is an exported stub and is the isolated product boundary for this slice.

## Decisions

- One caller-owned relative file is materialized per call; no queue or retained bundle cache is introduced.
- Reject absolute paths, parent traversal, invalid empty targets, and existing destinations.
- Use `create_new` exclusive creation and owner-only permissions. On supported Unix targets, add `O_NOFOLLOW`; `O_EXCL` also prevents an existing final-component symlink from being followed.
- Reject symlink/non-directory parent components and create new nested directories owner-only. The extraction root is caller-owned/private, matching the pinned upstream nonce-directory assumption for closing parent-component races.
- Remove a newly created output if `write_all` fails, avoiding retention of a partial bundled skill.
