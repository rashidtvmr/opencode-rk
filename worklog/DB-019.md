## v6 narrow repair

The provider contract counts serialized tool name/arguments/output bytes, not
the internal `round_id` identity. The returned `ToolHistoryItem` currently
clones `round_id` into every item, so it remains an allocation concern, but it
must not be charged repeatedly to `max_provider_bytes`. The repair therefore
charges the round identity once per emitted round (after the `HashSet` duplicate
check) and charges each typed row only for `call_id + name + message_id +
payload` lengths. All numeric SQL length gates remain before their corresponding
String extraction. No tests/builds/formatting were run.

## v7 minimal representation repair

`ToolHistoryItem.round_id` is now `Arc<str>` (stdlib only). After numeric SQL
length admission and one-time provider accounting, the fetched round identity
is converted once with `Arc::from(round_id)`; each typed result uses
`Arc::clone(&shared_round_id)`. This preserves the field name and avoids one
full String allocation per typed item.

Provider bytes remain: round identity once, then each typed row's call ID, name,
message ID, and payload. Retained memory is separately bounded as distinct
admitted strings/payloads plus fixed per-item metadata and one Arc handle per
result. A 1 MiB round ID under the default 512 KiB provider budget is rejected;
with a sufficiently large caller budget it is retained once rather than copied
2*expected_pairs times. No tests, builds, or formatting were run.
