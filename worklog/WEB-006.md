# WEB-006 worklog

Status: IMPLEMENTED / NOT ACCEPTED.

## RED

The first process-level test started one `serve` process for a temporary data
directory, created session state through it, then started another `serve` process for
the same data directory on a different loopback port. Before implementation the
second process stayed alive and owned a second backend, violating the singleton
contract.

Frozen test: `crates/cli/tests/web_singleton_runtime.rs`

SHA-256: `5bdadc6831700ada0b8e826593c414c9ab92fc360a88c7f3c28e0cb055239e02`

## GREEN

- singleton ownership uses an advisory OS file lock rather than check-then-write PID
  liveness;
- healthy same-data-directory invocations reuse one published HTTP origin;
- stale descriptor/PID content is recoverable;
- different data directories remain isolated;
- production assets and native APIs share one daemon origin;
- `opencode-rk web --no-open` owns or reuses that daemon without Vite.
