## Observable contract / failure / lifetime / resource bounds

- Same-instance reuse (T01): second serve/web same data-dir must exit 0 printing first origin, bind no second listener, state shared.
- Stale recovery (T02): stale pid/socket/descriptor recovers deterministically; healthy daemon never replaced/shadowed.
- Launch contract (T03): production web discoverable from daemon, no Vite/second manual server; explicit keyboard-independent failure.
- Race/lifecycle (T04): concurrent first starters exactly one owner; readiness bounded; shutdown drops listeners; no detached runtime.
- Isolation/compat (T05): different data-dirs independent; legacy serve cannot create second authority same dir.
- Lifetime: clients detach on exit; only explicit service control terminates daemon.
- Resource: bounded waits only (no unbounded retry); descriptor 8KiB cap; no shell concatenation; loopback only; bearer auth on /api.
