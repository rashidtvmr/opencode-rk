## Follow-up: current-event Location.Ref wire fidelity

After the original GREEN, a pinned-schema review found one concrete over-acceptance in the already-owned INT-008 wire boundary: `OpenCodeEvent<T>::location` was `Option<serde_json::Value>`, so a present null/scalar/array/empty object, a non-string `directory`, or an arbitrary/null `workspaceID` could decode even though the canonical current-event contract requires `Location.Ref`.

Source evidence for the correction:

- `packages/schema/src/event.ts:29-40,54-61`, blob `0d6ec9775aa475a8c491dbdae7a40a41fd43cdf5`, types current-event `location` as optional `Location.Ref`.

## Follow-up: optional metadata/durable null fidelity

A final source-fidelity pass found a second narrow over-acceptance inside the already-owned current-event wire DTO. The pinned Schema makes `metadata` and `durable` optional keys whose present values must satisfy their object schemas; it never unions either field with `null`. Plain Rust `Option<T>` deserialization treated an explicit JSON `null` as `None`, then `skip_serializing_if` silently omitted that key on re-encode.

Source proof:

- `packages/schema/src/event.ts:29-40,54-60`, blob `0d6ec9775aa475a8c491dbdae7a40a41fd43cdf5`, types `metadata?: Record<string, unknown>` and `durable?: { aggregateID, seq, version }` and builds them with the repository `optional(...)` helper; there is no nullable union.
- `packages/schema/src/schema.ts:12-18`, blob `d19a39b9708cfcaeedc1d7c62503afbadfee5dd7`, defines that helper as an optional key/undefined transform and filters only `undefined` during encoding. It does not turn `null` into absence.
- `packages/protocol/src/groups/event.ts:8-13`, blob `a6fc5692eae7cf631678b04eb58b9615bca163c4`, independently defines `metadata` as optional `Record(String, Unknown)` and `durable` as optional structured durable metadata, again without nullable schemas.
- `packages/core/src/event.ts:419-435`, blob `c92ac0ac2ce30d7cdf0f44075e9a82bb2fc0875e`, conditionally omits absent publication metadata rather than publishing null. No stronger metadata-value rule is inferred: values inside the record remain `Unknown` and may themselves be null.
