# OPS-010 worklog

## Claim

Upgrade the existing `opencode-rk doctor` CLI command into a bounded diagnostic surface that reports auth, local connectivity, built-in tool registry, and MCP configuration status in human-readable and JSON forms without exposing credentials.

- `tasks/OPS-010.md`: REQ-037, five test obligations.

- Current `crates/cli/src/main.rs::doctor` only prints static native-core capability metadata and does not inspect these four diagnostic areas.

## Decisions

- Tests invoke the actual compiled CLI binary and use isolated child environments/loopback fixtures; no production credentials or external network are required.
- Diagnostic output reports presence/status only and never prints secret values.
- Connectivity checks are bounded by a caller-configurable/short local timeout; no unbounded retries or background worker is introduced.
- A failed check is reported in the diagnostic result instead of requiring log inspection; catastrophic CLI argument/serialization failures still return an execution error.
- Auth checks only presence of a small known environment-key set and never serializes values.
- Connectivity only probes `OPENCODE_RK_DOCTOR_ENDPOINT`; absence is `unconfigured`, and the HTTP client is bounded to 750 ms.
- Tool diagnostics enumerate the existing `ToolRegistry::new()` built-ins instead of maintaining a second list.
- MCP diagnostics parse explicit `OPENCODE_RK_MCP_CONFIG` JSON and report configured/unconfigured/error without spawning its command.

## Remaining unknowns

- Provider-specific live authentication handshakes and real MCP server connectivity remain separate runtime concerns; this doctor slice deliberately avoids emitting secrets or launching configured MCP servers. Controller/verifier acceptance remains separate.
