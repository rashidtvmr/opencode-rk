## Tests authored (one owned file)

`crates/cli/tests/startup_readiness.rs` adds five minimum named binary-driven tests, plus two explicit negative dimensions:

1. valid matching descriptor + healthy service => actual chat attach and real API request carrying exactly descriptor bearer; token absent from output;
2. healthy foreign listener without descriptor => no attach/API activity, listener remains healthy;
3. table of empty/malformed token, schema mismatch, origin mismatch, symlink descriptors => no lease/API bearer handoff;
4. real `serve` child on an unoccupied loopback address => readiness through descriptor publication, then child service listener disappears after client exits;
5. valid existing service is reused => descriptor bytes are not republished, API is reached, and listener remains healthy.
6. descriptor + HTTP 503 health => no attached lease/API activity, listener remains alive.
7. wrong-owner descriptor: attempt a real owner change only to a generated descriptor using Python's stdlib `os.chown`; where OS privilege denies this (typical unprivileged developer), the case emits an explicit `APP017 WRONG-OWNER UNSUPPORTED` classification tied to the existing UID comparison unit test, rather than claiming a foreign-owner runtime check passed. No host files are targeted.
