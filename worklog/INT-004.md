## Decisions

- Do not extend legacy `providers/auth.rs`: it owns provider auth material and currently stores raw secrets.
- Do not use `security::credentials` or the existing `provider_accounts` SQL schema in this slice; secrets/persistence are separate owners.
- Do not add server AppState/routes or central contracts ids; keep identifiers local and validated in the provider integration module.
- No hidden JS host or external plugin execution in native mode.
- Attempt expiry is caller-driven rather than a background scrubber.
- Public collection bounds are `MAX_INTEGRATION_SCOPES = 8`, `MAX_INTEGRATION_METHODS = 8`, `MAX_INTEGRATIONS_PER_SCOPE = 32`, and `MAX_OAUTH_ATTEMPTS = 8`; exact frozen limits succeed and overflow is typed before unbounded growth.
- Retained caller strings are bounded separately: integration/method/attempt ids at 128 bytes, names/labels at 256 bytes. Authorization codes are accepted only as completion presence and are never copied into retained state or returned metadata.
- Scoped registry layers are ordered by registration time; newest metadata wins and closing that scope reveals the previous layer. Method replacement keeps a single key slot and OAuth slots keyed by method id while preserving deterministic insertion order.
- `OAuthAttempts` uses caller-supplied ids/time, saturating ten-minute expiry arithmetic, typed duplicate/not-found/not-pending/code-required outcomes, explicit expiry and cancel, and no wall clock/background scrubber.
- Completion returns only integration id, method id and optional label; secret material, callbacks and persistence remain outside this module by construction.
