## Contract decisions before RED

- `ReferenceSource` retains only inert local/Git metadata. Git repository/branch strings are not parsed, cloned, fetched, resolved, or cached in this slice.
- Plugin scope lifetime is caller-owned. Newer scopes override the same alias; closing a scope reveals earlier metadata.
- A whole declaration is prevalidated and applied atomically. Invalid alias/duplicates/metadata or capacity failure must leave visible and hidden scoped state unchanged.
- Alias rules follow the pinned config contributor's safe lexical boundary: non-empty and no slash, backslash, whitespace, backtick, or comma.
- Resource categories are bounded: total scopes, references per scope, alias bytes, path/repository/branch/description bytes. Exact numeric caps are frozen by the valid RED suite because upstream has no authoritative values.
- No JS runtime, executable callback, guidance rendering, prompt admission, filesystem/network/storage/env/credential behavior, persistence, background work, or new dependency.

## Implementation

Behavioral implementation began only after the valid RED and frozen hash recorded above. The signature-only scaffold was not treated as product completion.

- Added a pure in-memory `ReferenceRegistry` with bounded scope layers and `BTreeMap`-based deterministic alias ordering.
- `register_plugin_scope` validates the entire declaration before committing it, rejects duplicate aliases, enforces the frozen scope/reference/text caps, and replaces only the named scope after successful validation.
- `add`, `remove`, `list`, and `close_scope` preserve caller-owned scope isolation. Later layers override visible aliases; closing them reveals earlier metadata.
- Local and Git variants retain only caller-provided source metadata. The implementation does not parse or resolve paths/repositories, derive cache paths, clone/fetch Git, read the filesystem, render guidance, touch persistence/env/secrets/network, or launch background/JS work.
- No Cargo dependency changed.
