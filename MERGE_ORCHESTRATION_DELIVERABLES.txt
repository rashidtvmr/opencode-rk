## TECHNICAL SPECIFICATIONS

### Script Language
- Language: Bash (POSIX-compatible where possible)
- Dependencies: jq, git, make
- Shebang: #!/usr/bin/env bash
- Strict mode: set -euo pipefail

### State Machine

Level 1 - Pairs (sequential merging)

- Retention only for quarantined items
- Backup bundle at WORKTREE_BASE
- Configurable WORKTREE_BASE path

## ERROR RECOVERY WORKFLOW

### Scenario 1: Orchestrator crashes mid-run

Step 1: Identify last completed level
```bash
git tag -l "merge-L*-complete" | grep "merge-L"
```

Step 2: Check state directory
```bash
ls -la .merge-state/
cat .merge-state/LN-results.json
```

Step 3: Resume from appropriate level
- L0 complete, L1 crash: Restart L0, load L0 results, resume at L1
- L0 incomplete, all crash: Full restart
- L2 complete, L3 crash: Use L2 results as input for L3

Step 4: Fix any orphaned processes
```bash
pkill -9 -f merge_worker.sh
```

Step 5: Cleanup stale lock files
```bash
rm -rf .merge-state/*.lock && ls -la .merge-state/
```

### Scenario 2: Worker hangs or runs too long

Step 1: Detect slow worker
```bash
ps aux | grep merge_worker | grep -v grep
```

Step 2: Check stale PIDs
```bash
cat .merge-state/bucket-*.pid
```

Step 3: Kill orphaned process manually
```bash
kill <PID>  # or kill -9 if needed
```

Step 4: Cleanup affected worktree
```bash
git worktree remove -f .merge-wtrees/merge-bucket-N
```

### Scenario 3: No disk space

Step 1: Stop orchestrator (Ctrl+C)

Step 2: Clean up worktrees
```bash
git worktree prune
rm -rf .merge-wtrees/merge-bucket-*
```

Step 3: Verify available space
```bash
df -h .
```

Step 4: Restart with fewer workers
```bash
MAX_PARALLELISM=10 ./merge_orchestrator.sh ...
```
